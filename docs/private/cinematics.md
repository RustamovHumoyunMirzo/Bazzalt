# Cinematic sequencing

Timeline.h is the public contract. TimelineAsset.cpp implements versioned, bounded YAML loading. TimelineRuntime.cpp owns per-player restoration snapshots, scene lifetime guards, transform/camera leases and signal dispatch. Scene installs TimelineSystem. It evaluates Directors in the private engine post-script late phase, after animation and all LateUpdate callbacks, before CameraSystem and presentation. Explicit editor evaluation uses a separate TimelinePlayer and silent Seek.

Each player snapshots affected local transforms and camera activation. It creates an output Camera rather than replacing authored Camera components. Stop and destruction restore snapshots. Newly introduced cameras are captured before suppression. Transform conflicts and competing camera players fail explicitly. Physics tracks require nondynamic bodies. Kinematic playback uses MoveKinematic and scrubbing/restoration synchronizes through Teleport. TimelineSystem holds a player reference across callbacks, so event listeners may stop or replace Directors safely.

Component fields reuse the existing serialization/inspection visitor registry. Timeline assets participate in import validation, cooked content, and dependency tracking for event assets. Director Sequence is an asset reference. Track target and shot camera UUIDs are scene bindings and must not be treated as asset dependencies. Rebinding an authored sequence changes its scene bindings. There is no implicit cross-scene name matching.

The Qt Timeline panel uses a native QGraphicsView canvas, shared widgets/theme/locales, bounded document undo, atomic asset writes and transactional native preview. Optional editorId values preserve selection across key ordering and undo. Runtime ignores those authoring IDs. Read-only opening does not rewrite an asset. Project/scene changes, scene saves, Play, panel hiding and editor close release preview. Add the panel to the Git worktree flush/reset boundary whenever changing document ownership.

The initial track arsenal is transform TRS, camera shots and typed signal/marker tracks. Audio and animation choreography can use Global Events and their existing public controls. Add new track variants through validated schema/version handling, C++/Lua bindings, inspector/editor authoring, dependency analysis, cooking and matching runtime tests. Keep preview silent and the engine independent of editor headers.
