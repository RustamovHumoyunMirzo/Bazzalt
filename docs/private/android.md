# Android runtime and packaging

Production builds run in android-runtime.yml for arm64-v8a and x86_64. build_android_dependencies.py refuses local heavy builds. It pins Filament v1.77.0 with RTTI/exceptions and OpenSSL 3.5.4 by commit. NDK 29.0.14206865 supplies the common shared C++ runtime. The host tools export precedes cross-compilation. Keep module builds on the identical NDK revision.

CMake builds libBazzalt.so and the existing GUI, Lua, physics, networking and crypto modules. SDL3 is shared on Android so Java and engine input use one SDL state. libmain.so owns the SDL game entry point. Native gameplay modules use asset-relative paths mapped to deterministic ASCII hash filenames inside APK jniLibs. The signed base-APK inventory carries the mapping. This avoids basename collisions between extension modules and supports Unicode asset filenames. Native dependency libraries keep their SONAME-compatible libNAME.so names. JNI resolves modules against the active extracted asset root and loads them from ApplicationInfo.nativeLibraryDir. android_runtime_abi in runtime.json rejects incompatible launcher/module layouts. Writable content copies remain inventory-checked but are never dlopened. The manifest enables extracted native libraries so the player seal can be verified before scene loading.

Compiler/android_build.py invokes aapt2, javac, D8, zipalign and apksigner directly. It does not invoke CMake or rebuild the engine. APK signatures are verified before publication. Archive output contains the entire install set. Split content is a configuration APK with no Java/native code. OBB and external archives use a signed base-APK inventory. BootstrapActivity bounds extraction, validates paths, lengths and SHA-256, then stages into no-backup app-private storage. The native player verifies ECDSA inventories and package authentication again.

Platform.java owns Keystore and preferences. AndroidPlatform.cpp is the private JNI adapter. Worker threads attach to the VM and release local frames. Keystore AES-GCM keys are non-exportable. A build-specific content seed provisions a wrapping key and private AtomicFile ciphertext. The signed native player still carries offline bootstrap material. This protects stored keys at rest, while authorized server provisioning would be required to remove offline bootstrap extraction risk. Do not describe this as extraction-proof encryption.

SaveGame retains its public API and format. Android commits Base64-encoded save blobs in private SharedPreferences. Temporary files and lock files remain private files, while slot bytes and backups are preferences. Preserve NotFound behavior, synchronous commit errors, backup recovery, bounded sizes and enumeration. Content wrapping keys never enter preferences.

PlayerAndroid.cpp pauses rendering on background and reconstructs its swapchain after surface restoration. Input uses SDL events including primary-touch mouse emulation. Preserve the same physics, scene, scripting and graphics APIs. Device GPU limits continue to apply. Android release validation must include device tests for surface loss, rotation, audio focus, memory pressure, input, Vulkan and GLES presentation. SDK-tool package tests alone do not establish device feature parity.

Icons use ICO for Windows, ICNS for macOS and PNG for Linux/Android. Pillow is compiler-only. The generated BazzaltLauncher.png derives from the shared SVG branding and is included in the compiler package. Neither Python nor Pillow is shipped in Android games.
