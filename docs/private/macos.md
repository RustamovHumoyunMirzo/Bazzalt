# macOS implementation and release checks

Use `.github/workflows/macos-64-bit.yml` (macos-15 arm64, macos-15-intel x64). Never build large dependencies on a Windows development machine. `scripts/build_macos_release.py` consumes an existing build and stages four products. Release tags include both architectures through the release suite.

Cocoa window handles are NSView pointers at the private engine boundary. MacSurface.mm owns a CAMetalLayer, preserves the previous layer, updates drawableSize in physical pixels, and restores the previous layer only after swapchain destruction completes. Keep all Cocoa surface calls on the main thread. SDL's Cocoa NSWindow contentView uses the same adapter as Qt winId(). Public APIs contain no Metal or Cocoa types.

Do not hide QMenuBar on macOS: Qt relocates native menu content outside the client area. Hide only the branding corner widget. PreferencesRole and QuitRole allow native application-menu relocation. Windows caption customization must remain Windows-only.

Game packaging signs cooked native modules before compression and dylibs before hashing the inventory. Sign the bundle once to allocate LC_CODE_SIGNATURE, compute the canonical thin Mach-O bootstrap hash excluding its signature blob and mutable signature sizes, write game.seal inside the signed resources, then sign the final bundle. The native bootstrap first validates the complete bundle through Security.framework, then validates BAZZALT P-256 inventory signatures and content hashes before dlopen. Do not append bytes after signing Mach-O files. Keep Python/native hash normalization identical; tests cover mutation and re-signing invariance. Ad-hoc signatures prove consistency, not publisher identity. Developer ID and notarization require the publisher's credentials.

Keychain mode uses a per-user login generic-password item: service bundleIdentifier + .game, account build UUID, synchronizable false. A configured environment key provisions only a real player launch. Both bootstrap and shared player set KeychainProvisionAllowed=false for --verify-package, so builders never persist the player's key. No editor code calls Security.framework to save game keys. Deleting the build-specific Keychain item requires reprovisioning. Do not promise memory secrecy or automatic secure distribution of the initial key.

Run Python compiler/profile regressions on every host, and Cocoa menu/package verification on each Mac architecture. The workflow runs tests/MacMetalProbe.mm in a separate process and actually creates and populates a Metal argument-buffer encoder, which the pinned renderer requires. A non-null MTLDevice alone is insufficient: the Intel hosted Apple Paravirtual driver aborts inside newIndirectArgumentEncoderWithLayout. Probe failures remain visible in the job warning and capability log; presentation is explicitly unvalidated on those devices. Metal viewport, gameplay and Keychain first-launch tests run when the operation succeeds. Native regressions, Cocoa menus and signed bundle verification run on both architectures regardless. Use BAZZALT_MAC_GPU_TEST=1 on a capable physical Intel Mac to validate Intel presentation; Apple Silicon CI exercises the complete GPU path. Check codesign --verify --deep --strict on final relocated app bundles and confirm otool -L has no source-build or Homebrew runtime dependencies. The app uses @rpath install names and @loader_path search paths. Preserve only bounded in-bundle framework symlinks during Hub archive installation; ordinary archives still reject symlinks.

BuildSettings.json schema 2 preserves platform profiles and migrates schema 1 flat architecture/backend/key delivery into the previously selected platform. The selected profile is authoritative; Effective supplies the legacy flat mirrors used by build tools. Older editors reject schema 2 instead of silently dropping inactive profiles.
