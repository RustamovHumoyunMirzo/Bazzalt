# Physics determinism and replay

Public PhysicsReplay.h contains only engine types and opaque immutable PhysicsState handles. The scene-scoped facade validates lifetime through PhysicsScene. Core delegates via PhysicsModuleApi v4; snapshots and history remain in the sibling physics DLL. The solver module is retained for process lifetime, including snapshot control blocks. No untrusted native-state deserializer or external binary checkpoint input is exposed.

PhysicsReplayWorld.inl captures Jolt StateRecorderImpl plus engine-side pending forces, contact/count/event bookkeeping, driver inputs, joint break flags, soft inverse masses, wheel steering/slip readbacks, previous/current interpolation poses and physics-related entity/ancestor transforms. Jolt does not save all authored configuration or soft inverse masses; our topology/configuration fingerprint rejects mismatches, while pinning is explicitly restored. Other non-physics entities are excluded, so UI/VFX-only changes do not invalidate checkpoints. World session UUIDs prevent stale snapshots being restored into a recreated solver with reused addresses/body IDs. Relevant entity generations also participate.

Restore validates boundary/session/fingerprint/soft counts, prepares allocating bookkeeping copies, saves a solver backup, restores the native recorder and then commits wrapper/pose state. A native restore failure restores the backup. Seek and playback do not dispatch collision/gameplay callbacks. Mutating body/vehicle/soft/joint commands are rejected during playback. AutoSimulation must be false for playback; explicit AdvancePlayback is controlled by the caller. Tick advances only for completed simulation steps and is restored with a frame.

Recording captures the initial state, then appends only after World::Step finishes callbacks and clears its stepping/dispatch guards. Limits stop before appending an over-budget frame. Counters estimate retained frame memory conservatively; externally retained state handles are not part of recorder ownership. State hashes are 16-character hexadecimal FNV-1a diagnostics over solver/config/pose/queue state, not cryptographic authentication and not a portable network checksum.

Deterministic stepping is runtime-only and opt-in, with an exact configured float delta and optional zero-worker policy. Jolt ordering remains deterministic by default. BAZZALT_CROSS_PLATFORM_DETERMINISTIC_PHYSICS defaults ON for source builds; existing imported Jolt packages must declare their matching BAZZALT_JOLT_PREBUILT_CROSS_PLATFORM_DETERMINISTIC flag (legacy default OFF) and are never rebuilt automatically. VerifyJoltVersionID rejects mismatched imported libraries with a C++ exception before Jolt registration can abort. The capability query initializes/verifies the solver before reporting the compiler macro. Keep local testing on supplied prebuilt SDKs. Cross-platform solver arithmetic does not guarantee the entire engine or procedural/vehicle/script math is cross-platform deterministic. See upstream Architecture.md and run shipping-target repeat-input tests.

Coverage: PhysicsReplayTests restores/re-simulates actual rigid/soft bodies and a driven vehicle with forces/impulses, compares velocities/vertices and complete state hashes, tests pinning, histories/limits/loop/seek, unrelated entity changes, invalid states, changed geometry and restarted/wrong worlds. LuaRuntimeTests exercises the real Lua bindings against a world containing vehicles, constraints and cloth. Header/API docs are generated by sync_api_reference.py; guides and What's New explain the boundaries.

Rigid-body synchronization retains its canonical physical scale instead of accumulating decomposition rounding on each solver rotation. Vehicle scale signatures use the same pose quantization as collider signatures, preventing numerical scale noise from recreating vehicle constraints and invalidating otherwise stable checkpoints.
