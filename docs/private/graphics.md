# Graphics rendering boundary

Public contracts live in `include/Bazzalt/Graphics.h`; no Filament object crosses that boundary. `Runtime/GraphicsAccess.h` owns validated immutable CPU geometry snapshots, the transient submission queue and scene-scoped event registry. Native module leases outlive callback destruction. Native script scopes and Lua VM scopes disconnect before code/state teardown. Explicit entity owners expire when the entity disappears.

`Rendering/GraphicsRenderer` caches GPU buffers by mesh ID/revision and reuses renderables/material instances by submission index. Upload buffers have owned completion callbacks. All buffer and sampler preparation happens before `beginFrame`; OnBeforeCamera therefore runs during preparation, not inside an active render pass. OnBeforeDraw is a preparation notification. After events run after the camera's CPU render submission and do not imply GPU completion. A frame scope removes graphics renderables and clears transient commands even on exceptions. Shadow, layer, priority and material state are supplied to the private renderer.

Default geometry uses an embedded unlit vertex-color material owned once by the backend asset cache. Graphics renderers own only its instances; the shared parent outlives all borrowers, including repeated renderer preparation and camera effect teardown. Custom surface materials reuse `RenderAssets` material loading and parameter/sampler binding. Required attributes are checked before binding. World materials using camera textures enter the conservative shared-feed capture SCC so they sample consistent history without reading an attachment being written. Graphics geometry is not an ECS entity or query collider.

Limits: 262144 vertices / 1048576 indices per mesh; 4096 submissions and 128 MiB unique geometry per frame; 4096 subscriptions. Input is validated before publishing a new mesh snapshot. Native and Lua API tests cover bad indices, counts, nonfinite input, revisions, submission lifetime, callback scoping, teardown, and material-list migration. Run BazzaltGraphicsTests normally for NOOP resource tests, and with `--gpu` for a real Vulkan pixel readback.

Camera material lists are schema version 4, with backward reads for versions 1-3. Legacy Post.Material is evaluated first; list setters migrate it into the ordered list. The GUI compositor chains each enabled pass using independent targets before compositing the affected camera region back into the presentation or capture. Editor `CameraMaterialsInput` edits the complete list atomically through the bridge, with project pickers, enable controls and ordering. Shared render-target and effect-memory limits still apply.
