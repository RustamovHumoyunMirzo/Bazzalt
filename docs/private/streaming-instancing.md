# Streaming and GPU instancing

The engine owns StreamingRuntime. Workers capture immutable paths and shared operation state, never Engine/Scene pointers. PreparedScene is a data-only YAML result. Synchronous and async loading share the parser, including UUID, parent, cycle and duplicate-component validation. Component factories always execute on the host thread. Prepared records are topologically ordered so parent transforms exist before child bodies/renderables activate. Scene replacements build detached scenes incrementally; additive cells enter the live registry incrementally and may become visible during Activating. On failure/cancel, only owned entities are removed. Preserve unrelated children during unload. UUIDs are never remapped implicitly.

Pump runs at safe frame boundaries in both editor/game ticks. Limit source jobs and entity work separately; the time limit is soft between records. The resource budget reserves raw buffers/serialized source sizes and is not a claim of total decoded/GPU memory enforcement. Registered cells use position-distance hysteresis and prioritize nearest entries. Runtime registrations reset on scene change. Loaded cells get separate native/Lua behavior runtime instances using the active scene; missing compiled modules fail explicitly. Physics, audio and rendering keep their existing scene ownership. Parent scene environment/gravity wins over cell metadata.

JobAccess::WaitForModule is a private teardown barrier. Native teardown waits its own module's jobs rather than blocking unrelated engine IO. Nested jobs inherit the module lease. Queue bookkeeping and per-module counters use the pool mutex; avoid worker teardown.

Interactive glTF uses jobs for read, URI embedding, external buffers/images and CPU BVH generation. GPU asset creation and ResourceLoader asyncUpdateLoad stay on the render thread. Each async loader owns its decoder provider, avoiding pop-queue conflicts across concurrent loaders. Pending render handles retry without recording permanent failure; failures remain recorded until asset/component invalidation. Weak glTF group owners and pending upload cancellation preserve resource lifetime. PNG/JPEG material loads use AssetManager async bytes and retain input through provider completion. Headless/offline loading is explicitly synchronous by default. HDR/environment and filamesh GPU loaders remain synchronous. GPU publication and custom callbacks can exceed per-frame budgets; no virtual-texture or mip residency system is claimed.

Automatic instancing is enabled on the private Filament engine. Primitive geometry uses canonical parameter keys and reference-counted GPU buffers. Color materials are immutable shared instances: changing one color changes its binding instead of mutating other entities. Asset-backed material instances are shared by asset/shader/render-state identity. Rebinding, debug views, selection masks and destruction must retain old resources until native bindings change. GraphicsMesh submissions share native buffers and compatible materials too. Imported glTF/filamesh resources may still split batches. Device renderer decides eligible batching; diagnostic resource counts are not actual draw-call savings.

Validation uses StreamingTests for async completion/cancel/deferred activation, UUID collisions, transactional rollback, offset hierarchy, distance unload, preservation of unrelated children, main-thread custom deserialization and shared GPU-resource counts. Existing rendering/serialization/material tests remain required. Full real-GPU visual checks remain distinct from NOOP resource-manager tests.
