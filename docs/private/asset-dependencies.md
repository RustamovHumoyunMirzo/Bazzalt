# Asset dependency tracking

AssetDatabase owns cached per-source reports and a reverse UUID adjacency index. AssetManager and Lua forward read-only queries to the active engine. EditorHost serializes reports for the collapsed asset inspector. No file reads occur in query methods. Successful scans are cached by owner path, import generation/cache path, importer name and importer version; unchanged refreshes reuse them. Importers must include external analysis inputs in ComputeSourceHash and bump their version when extractor behavior changes. Replacing an importer invalidates these keys. Analysis and refresh are engine-thread operations; there is no concurrent mutation contract.

Default format extractors live in src/Runtime/AssetDependencies.inl. UUID and path edges retain their serialized field location. UUID edges retain missing targets. Path edges resolve after the full import pass, making discovery order irrelevant; a new target imported with RefreshSource updates old path edges. Traversal is iterative, deduplicated, sorted and excludes the origin. Cycles are valid.

Custom AssetImporter implementations can override CollectDependencies(asset, report) and return true. Set State to Complete only if all references for that format were enumerated. TargetPath is absolute or relative to the owner source directory; UUID-only edges leave it empty. All paths are canonicalized and must remain within Assets, including symlink resolution. Exceptions mark only dependency analysis Failed, without making otherwise usable import products fail. A failed scan discards its unvalidated outgoing references. Never include entity/bus identifiers as asset UUIDs.

Scene/prefab schemas are conservatively Partial. Built-in named asset fields, camera list slots, CSV material lists, script source paths and typed asset property values are recognized. AssetReference.* is an explicit custom serialized UUID convention. Dynamic script lookups, script includes/imports and opaque binary formats are not guessed. Keep coverage prose and tests current when adding components or formats. This is saved-content dependency tracking, not object reachability, automatic reimport or unused-content stripping.

Cooked graph schema v1 stores owner UUID, analysis state/error and direct Target/Path/Field edges; reverse edges and resolution states are rebuilt. Paths are relative to project root; imports never deserialize native code. Reads are bounded to 64 MiB and one million YAML nodes. Missing sidecars are backward compatible. Invalid present sidecars fail cooked database opening. Engine cooking rescans rewritten documents after native script UUID remapping and exports the final graph.

Run BazzaltAssetDependencyTests, Lua runtime tests, editor dependency tests, and documentation checks. Do not build large dependencies locally.
