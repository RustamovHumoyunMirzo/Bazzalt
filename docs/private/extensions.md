# Extension ownership and integration

`bazzalt/extensions.py` is the Qt-free manifest/archive/store boundary. Format 1 packages use explicit payload registration, a normalized JSON descriptor and SHA-256 inventory. Extraction preflights all entries before writing: canonical relative paths, size/count caps, case-insensitive uniqueness, no links or ZIP encryption. Imports stage privately and atomically publish a content-addressed version; imports begin disabled. A cross-process file lock serializes registry mutations. Dependency and public-module/type collision checks occur before committing enablement. Never execute code during import.

`Compiler/extensions.py` compiles Lua using the separately shipped host Lua shared library through ctypes, without executing source. Native compilation consumes the public prebuilt ScriptSDK and existing Clang toolchain. Include validation rejects private/absolute includes. The builder compiles controller/SDK Lua and native modules/behaviors, packages registered resources/headers/source, and atomically replaces the output after cancellation checks. Bytecode is portable between our x86/x64 Lua targets; native dependencies remain architecture-specific. Neither package nor game builds invoke CMake or download dependencies.

`Editor/extensions.py` owns adapters for `.ui` panels, named-widget commands, menus, script hosts, component materialization and scene inspector fields. QtUiTools loading is explicit in release packaging; custom widget plugins, UI resource imports and custom styles are rejected. Panels belong to the shared docking system. Window-menu extension actions are parented to the menu bar and reinserted after its dynamic refresh. No package imports Python or receives raw Qt/editor/renderer objects. Code errors disable the affected controller and log a Console item. Engine code does not import or know the editor.

`ExtensionRegistry` exposes function registration with a bounded value vocabulary. `BAZZALT_EXTENSION` supplies ABI version 1 and its registration entry point. `Runtime/ExtensionAccess` privately loads only declared modules from a bounded runtime index. Native function copies retain a shared library lease; invocation propagates gameplay-module lifetime to callbacks. Clear Lua state before functions/libraries. ExtensionScript VMs disconnect scoped callbacks before lua_close. The runtime index records component ownership for native lifecycle scopes and Lua module environments. Native dependency directories have Runtime/Editor scope; combined packages can register separate editor-only library/bin directories. Public names are globally unique; private names are qualified by extension ID and Lua module environments bind immutable caller ownership for private requires. Public gameplay APIs do not expose sol2 or renderer types.

`Extensions.lock.json` is project dependency state, separate from editor enablement. Pins identify the archive digest plus ID/version. Historical content-addressed installs are retained so a newer enabled package cannot substitute an old project pin. Runtime data/component assets are restored with deterministic UUIDs under Assets/Extensions; modified authored files are never overwritten. Scene extension settings use bounded namespaced strings in `ExtensionProperties`; preserve unknown namespaces while plugins are disabled. Scene serialization/snapshots carry these values through save/load and undo/redo.

Game compilation restores pinned assets, compiles normal component scripts, cooks project data, then stages only Runtime-scope SDK/helpers and target binaries under cooked `ext`. `runtime.json` maps module names and stable runtime asset UUIDs. Editor-scope code/UI never enters staging. The existing package encryption and signed inventory cover ext and extracted native modules. Do not load modules from the editor store in a player. Physical ext files may be inside protected pak content until verified extraction. The OS necessarily receives decoded native libraries at load time.

Tests: `tests/test_extensions.py` covers package validation, dependency/collision state, actual Lua bytecode and runtime filtering. `Editor/tests/test_extensions.py` verifies UI restrictions, menu/dialog integration and real Lua controller/scene settings behavior. `BazzaltExtensionTests` loads a real public native fixture, calls it from C++ and Lua, calls a Lua SDK from C++, and round-trips scene properties. Compiler native-build coverage must execute extension SDK code after cooking/encryption, independently of editor data. Keep these tests and public extension creator/user references current with API changes.

Boundaries: native extensions are trusted process code, not sandboxed; inventory hashes are not publisher signatures. First-version typed exports cover supported scalar/math/UUID values rather than arbitrary C++ object reflection. Editor controllers are Lua adapters; C++ logic is supplied via registered modules. Changes in editor activation apply after restart. Cross-OS native compilation and unsupported platforms remain unsupported. Do not describe these as automatic hot reload or universal binary portability.

The native script service host accepts a service name, declared methods and typed callback; editor command names and their wire adapter live exclusively in EditorBridge/PythonModule.cpp. Qt assignments block signals to prevent recursive controller calls. Editor-owned scene undo groups commit at callback completion and roll back on controller errors. Native dependency libraries are explicitly staged and loaded with directory leases on Windows and dependency-ordered loading on Linux; fixture tests load a companion library outside the executable directory.
