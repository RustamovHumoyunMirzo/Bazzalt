Bshader language reference

Bshader describes a mesh surface and, optionally, changes its vertices. It is not C++, Lua, a compute language, or a fullscreen post-processing language.

File structure

shader Surface {
    options { shading: lit; blending: opaque; doubleSided: false; }
    properties { tint: vec4 = vec4(1.0); }
    vertex { position = position + vec3(0.0, 0.1, 0.0); }
    material { color = tint; roughness = 0.5; }
}

Exactly one named shader declaration is allowed. material is required. properties, vertex, and options are optional; each block may occur once. Names are case-sensitive. Statements and property/option declarations end in semicolons. Use // for line comments or /* ... */ for block comments.

Types and defaults

TypeMeaningDefault example
float32-bit floating-point scalarstrength: float = 0.5;

Properties are read-only inputs. Locals are declared with type name = expression;. A texture is a property, not a local variable. Vector/matrix defaults accept constant constructors, nested constructors, unary minus, and scalar arithmetic. A single scalar splats a vector; a single matrix scalar fills its diagonal and leaves other entries zero. Otherwise provide exactly 2/3/4 or 9/16 components. Matrix component lists are column-major. Defaults cannot sample textures, read properties, call arbitrary functions, or depend on time. Texture defaults are not supported: assign an asset in the material Inspector.

Write float literals as 1.0, .5, or 1e-3, and integer literals as 1. Their types are preserved. Do not rely on implicit integer-to-float conversions. Non-finite numbers and out-of-range defaults are rejected.

Operators, swizzles, and indexing

Precedence, from lowest to highest: ||, &&, == !=, < > <= >=, + -, * /, unary ! -, then calls/member/index access. Parentheses override precedence. Constructors and mathematical function calls use ordinary comma-separated arguments.

vec4 sample = texture(albedo, UV);
vec3 rgb = sample.rgb;
sample[0] = sample[0] * 0.5;
mat3 basis = mat3(1.0);
vec3 direction = basis * rgb;
color = sample;

Members/swizzles and vector/matrix indexing work in expressions and assignments. You may write locals or stage outputs, never properties, including their members or elements. Index and swizzle validity, function signatures, and expression type compatibility are checked by Filament's compiler. There are no array declarations, structs, pointers, user function definitions, preprocessor directives, ternary operator, modulo operator, or compound assignments.

Branches, loops, and scope

float total = 0.0;
for (int i = 0; i < 4; i++) {
    if (i == 2) { continue; }
    total = total + 0.1;
}
int remaining = 3;
while (remaining > 0) {
    remaining--;
    if (remaining == 1) { break; }
}
roughness = total;

if, else if, and else use brace-delimited bodies. Locals belong to their block; inner blocks may shadow outer locals but cannot redeclare a name in the same block. A loop counter belongs to the loop. for requires an initialized int counter, a condition, and an assignment or postfix increment/decrement step. while requires a condition. Loop bodies require braces. break and continue are valid only inside loops.

The compiler inserts a 1,024-iteration guard into each loop. This prevents one accidental infinite loop, but nested loops can still perform many operations. Keep per-pixel iterations small; reaching the guard truncates the loop. Statement-emitting custom transforms are not allowed in loop conditions/steps or assignment indices.

Shading and render options

shading: lit uses lighting and surface parameters; shading: unlit displays base color without surface lighting. blending: opaque ignores opacity for transparency; use blending: transparent when writing alpha should reveal objects behind the surface. doubleSided: true allows both sides of the mesh. Defaults are lit, opaque, and single-sided. Duplicate or unknown options are errors. Unlit materials cannot write roughness, metallic, normal, or ao. Exposure and post-processing can still affect an unlit surface.

Stage outputs

Do not assign a fragment output in the vertex block. Vertex displacement does not update CPU mesh bounds, picking geometry, or physics. Expand authoring bounds or avoid large displacement when those systems matter. No custom varying declarations are exposed.
