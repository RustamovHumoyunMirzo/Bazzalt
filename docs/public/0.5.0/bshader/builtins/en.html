Bshader inputs and functions

Inputs come from the current draw and camera. Properties come from the material instance. Neither is a gameplay component.

Built-in inputs

NameType / stagesMeaning
UVvec2, bothFirst texture-coordinate channel; writable in vertex.
vertexColorvec4, bothMesh vertex color; interpolated in material, writable in vertex.
worldPositionvec3, bothCurrent vertex/fragment world position in Filament's render coordinate system.
worldNormalvec3, lit stagesGeometric world normal, distinct from tangent-space normal output.
timefloat, bothElapsed renderer time in seconds, not a repeating 0-to-1 fraction.
cameraPositionvec3, bothPosition of the camera rendering this view.
viewMatrixmat4, bothWorld-to-view matrix.
projectionMatrixmat4, bothView-to-clip matrix.
modelMatrixmat4, vertex onlyModel-to-world matrix.
positionvec3, vertex onlyRead/write alias for vertex world-position XYZ.

The compiler automatically declares required UV/color mesh attributes. Lit shaders require tangent data. Ensure your mesh provides appropriate data; a declaration cannot manufacture meaningful UVs. Vertex values are processed per vertex; material inputs are interpolated/derived for each fragment. Matrices and camera inputs are supplied for each rendered view, so Scene and Game cameras may produce different results.

Coordinate and time contracts

Filament may use camera-relative world coordinates for precision. Do not compare worldPosition with an absolute C++ entity position without a deliberate coordinate conversion. cameraPosition and shader world-space inputs are intended to be used together. Matrix/vector multiplication uses column vectors: projectionMatrix * viewMatrix * vec4(worldPosition, 1.0).

time lowers to getUserTime().x, supplied by Filament for rendering frames. It is not automatically synchronized with Bazzalt's scaled gameplay clock or paused simulation. For pause-aware animation, declare a float property and set it from C++/Lua using the desired game time. Do not multiply by frame delta inside a shader to produce elapsed time.

Mathematical functions

Ordinary GLSL calls pass through to Filament; they do not need custom transform registration. Common functions include sin, cos, tan, asin, acos, atan, abs, min, max, clamp, mix, step, smoothstep, floor, ceil, fract, sqrt, pow, exp, log, dot, cross, length, distance, normalize, reflect, and refract. Matrix operations include transpose, inverse, and determinant. Use radians for trigonometry. Filament validates supported overloads and stages; an unknown call is not an automatically defined function.

Texture sampling

texture(image, UV) returns a vec4 sample from a texture2d property. UVs are normalized coordinates, not pixel indices. Sampler/filtering behavior belongs to the material's texture binding. Use RGB for color or all four channels for RGBA. A color texture's import/color-space interpretation is distinct from linear numeric data such as normals.

High-level blur

color = blur(albedo, UV * 0.5, radius + 1.0);
// The optional third argument defaults to 1.0:
color = blur(albedo, UV);

blur(texture2d, vec2, float) is fragment-only. Radius is measured in source texture texels. It samples the center with weight two and four diagonal offsets with weight one, divided by six. This is a small weighted blur, not a separable Gaussian, scene-depth blur, or fullscreen effect. Radius zero samples the center. Arbitrary UV/radius expressions are preserved. One helper is injected per stage when needed; invalid arguments fail translation or GPU compilation.

For fullscreen camera effects use the public post-processing API, not a mesh material. Large radii do not add samples and can look like separated taps. For higher-quality filtering, write a small bounded sampling loop or use the appropriate post-processing effect.
