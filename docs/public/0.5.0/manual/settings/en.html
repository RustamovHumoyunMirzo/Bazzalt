Preferences and project settings

Preferences affect your editor installation/user experience. Project Settings describe the game project. Scene environment data belongs to the scene instead.

Open Preferences

Choose Edit → Preferences. The child settings window blocks ordinary editor interaction while open. Sections appear on the left; their fields appear on the right. Select a section before editing its fields.

Preferences include general appearance/behavior, scene navigation and overlays, history limits, build tools, rendering backend selection, and file associations. Settings are stored in the platform's application-data location, not as gameplay components.

Scene tool preferences

Use Scene preferences to adjust navigation speed, grid behavior, orientation visibility, and remembered tool choices. The Scene toolbar also remembers authoring modes such as local/global and pivot/center. A setting affecting the editor camera does not change a game Camera component.

If imported model groups expand too much, change the preference for newly added hierarchy objects. Existing manual expansions are separate choices.

Undo history

History limits bound undo/redo count and memory use. A smaller limit can discard old steps sooner; it is not a substitute for saving scenes. Undo changes authoring state, not your entire source-control history.

Build tools and file associations

C++ behaviors need a compatible native compiler/SDK configuration. Build Tools lets you override supported tool/Script SDK paths. On Windows, Clang alone is not the complete Microsoft SDK/runtime environment. Read Console if compiling Play fails.

File Associations controls the applications remembered for supported source formats. Open uses a saved choice; Open with asks again. Reset an association when the external source editor path is no longer valid.

Project Settings

Choose File → Project Settings for project information. This is not the same as selecting a scene header to change an environment. The Hub still owns creating/choosing projects; Project Settings does not let gameplay scripts take over project management.

Changes requiring restart

Critical changes, such as rendering backend or project name, may prompt a restart. Restart now applies them after reopening; restart later leaves the current session running until you reopen. Save any scene work before restarting. The prompt is about the setting's application, not a promise that every unsaved scene was automatically saved.
