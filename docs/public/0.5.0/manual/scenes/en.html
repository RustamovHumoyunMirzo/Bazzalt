Multiple scenes and saving

The Hierarchy can contain several loaded scenes, but only one is active for Scene view and Game output.

Create and load a scene

Use the Asset Browser's file-creation menu to create a Scene asset. A scene file has the .bscene extension. Double-click it, or use its Load scene context-menu command, to add it to the Hierarchy.

Loading is not the same as activating. Loading another scene keeps the current active scene active. Objects in an inactive scene can still be selected and edited from the Hierarchy, but its contents do not replace the active viewport.

Activate and unload

Right-click an inactive scene header and choose Activate scene. The active header becomes bold. Activation is a single-scene operation, not a way to render every selected scene together.

Unload scene removes an inactive scene from the Hierarchy without deleting its asset. The active scene cannot be unloaded. Activate a different scene first if you need to unload the current one. A scene already loaded is not offered for loading again under a second name.

Scene settings

Select a scene header to inspect scene-level settings, including its environment. A scene is not an entity: it does not have an Add Component button. Environment mode determines whether you assign an environment map or an environment material. Skybox visibility and image-based lighting are separate controls.

Unsaved changes

An asterisk (*) on a scene header means that scene has edits that have not been saved to disk. With several scenes loaded, check the individual headers instead of assuming that one saved scene means all scenes are saved.

Use File → Save or Ctrl S and confirm that the relevant indicators clear. When closing the editor with unsaved changes, choose Save and close, close without saving, or Cancel. Closing without saving discards unsaved authoring changes; Cancel leaves the project open.

Renaming and identity

Use the Asset Browser or the scene header's rename action to rename a scene. The loaded scene tracks its asset identity, not just its path, so it should not become a duplicate when loaded after a rename. Keep matching metadata when moving files outside the editor.

Loading scenes from gameplay

Gameplay can request a scene change through SceneManager.LoadScene in Lua or Bazzalt::SceneManager::LoadScene in C++. The request is deferred to a safe runtime boundary. Loading a scene does not give a behavior ownership of project loading, scene saving, or the application loop.

Check the returned result and GetLastError for a rejected request. Do not assume that a successful request has already switched the active scene in the same callback. See the C++ API overview or Lua conventions.
