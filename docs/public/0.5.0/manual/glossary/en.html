Terms used in these guides

These terms describe different parts of the engine. Keeping them separate helps when editing a scene or reading an API example.

Project and scene

Project: the files and settings that belong to one game. The Hub opens a project in a compatible editor.

Scene: a collection of entities, their components, and scene settings. A project can have many scene assets. The editor can load several scenes, with one active for its viewports.

Runtime: the engine while it is executing a game, including editor Play mode. Runtime-created state may not be part of the saved authoring scene.

Entity, component, and system

Entity: an object with a stable identity in a scene. “Object” in the editor and “entity” in the API refer to the same idea.

Component: data or behavior attached to an entity. A Camera describes a view; a Light describes illumination; a Transform describes position, rotation, and scale.

System: code that processes components. The engine's camera, light, and mesh systems turn component data into rendering state. A custom C++ system can process your own components.

ECS: Entity Component System, the approach of composing objects from components and processing them through systems. You do not need to subclass the engine to create an entity.

Transforms and coordinates

Local transform: an entity's position, rotation, and scale relative to its parent. The C++ Transform component stores local values.

World transform: the result after composing an entity's transform with its ancestors. The editor's transform fields present world values. Use GetWorldTransform and SetWorldTransform in gameplay when you want this meaning explicitly.

Pivot: an object's origin, used for rotation and scaling. Center: a shared point for manipulating a selection together. These are editor tool modes, not different stored positions for the entity.

Asset pipeline

Asset: a project file the engine recognizes. Importer: code that converts source data into runtime data. Cache: generated data from that import, kept to avoid repeating the work unnecessarily.

UUID: a 128-bit identifier. It distinguishes assets and entities even when their names change. A display name is not a reliable identity.

Bytecode: instructions produced for a virtual machine such as Lua. It is not a native C++ binary and is not guaranteed to work with a different Lua version or machine representation.

Rendering

Mesh: geometry made from vertices and triangles. Shader: a program that tells the renderer how a surface behaves. Material: a shader choice together with values such as color and roughness.

Texture: image data sampled by a shader. Skybox: the visible environment background. IBL: image-based lighting, which uses an environment map to illuminate surfaces. The skybox can be hidden while IBL remains enabled.

Gizmo: an editor handle or guide. Viewport: a panel area that renders a view through a camera. Scene view uses an editing camera; Game output uses scene Camera components.
