Assets and project files

An asset is a file used by the project: a model, image, scene, script, shader, or material. The Asset Browser shows the project's asset directory, not every file on your computer.

Which files matter

File or folderMeaning
.bprojectProject descriptor and project metadata.
Assets/The usual source asset directory. A project can configure another asset directory.
.bsceneScene data. The contents use YAML despite the engine-specific extension.
.metaA sidecar beside an asset containing its stable UUID and import metadata.
.bazzalt/Project-local generated/import and script state. It is not a replacement for the original assets.

A UUID is a long identifier used to refer to an asset independently of its filename. Renaming a model should not break a material or scene reference to it. Keep an asset with its matching .meta file when moving project files or using version control. Deleting the metadata can give the asset a new identity on reimport.

Importing and the cache

Add supported source files to the project asset directory. The importer converts them into data the runtime can load and records the result in a cache. For example, Lua source becomes Lua bytecode, and shader source becomes a compiled renderer package. The cache is generated data; keep the source files as the editable originals.

An import error does not mean that the file vanished. Check Console for the asset's path and error. Invalid Lua syntax, an unavailable shader compiler, or a failed environment-map conversion must be fixed before that asset can be used normally.

Assign an asset to a field

Drag an Asset Browser item into an Inspector asset field, or use that field's picker to choose a registered project asset. Pickers filter by the field's expected type. A texture is not a valid model, and a shader is not a material asset.

Fields show asset names rather than raw UUIDs. Clearing a field removes its reference; it does not delete the source file.

Models and their parts

A glTF model is one asset, but placing it in a scene creates a parent object and child objects matching the model's node hierarchy. A node may represent a mesh part or a grouping transform. This is why a model can have many Hierarchy entries even though you imported one file.

Children can have their own components. Adding an ordinary component to a parent does not add it to every child. Transforms compose through the hierarchy, so moving a parent moves its descendants. Use high-level selection in Scene view when you want to manipulate the model as one object.

Open source files

Double-click a scene to load it into the Hierarchy. C++ files support Open and Open with: Open remembers a selected application, while Open with asks again. Configure or reset those choices in Preferences → File Associations.

Asset names normally omit their extensions in the browser. Renaming shows the extension so you can see the full filename. Do not change a file's extension simply to make it appear as another asset type; the contents must match that type.
