Camera textures

A Texture asset is a reusable image resource, not an object in the Hierarchy. A camera can render into it, and unrelated images/materials can display its pixels using the same Texture reference.

Create the asset

In Asset Browser, right-click → Create → Texture. Choose a name and select the file. Properties shows Texture Settings, not entity components or an Add Component button. The .btexture file is readable YAML and has normal UUID/.meta/cache tracking.

Assign a producer

Select a Camera object in Hierarchy. Its Render Target picker accepts writable Texture assets, not PNGs/models/materials. Drag your Texture from Asset Browser or choose it in the project picker. This camera now renders offscreen, so keep another normal camera if you also want direct Game output. Clearing Render Target restores normal presentation.

Display it anywhere

Select a GUI Image and choose the same asset in Texture. It works under Viewport, Camera-Bound and Spatial Frames. The legacy Image Camera field is optional; when nonempty it takes precedence, so clear it if you want the Texture field to supply the source. A material's Texture2D sampler can select the same asset; custom shaders and the built-in Unlit baseColorTexture parameter sample it normally.

Texture settings

Width/Height control pixels; Samples requests MSAA; Mipmaps and Mip Levels control downsampled levels; Color Format chooses RGBA8 or HDR floating point; Depth Format configures depth; Filter and Wrap affect consumers. Clear Color is the initial/idle image. Changes save the asset immediately and safely recreate attachments as needed. GPU allocation is lazy and no CPU readback/upload loop is used for camera frames.

Disabled and conflicting cameras

The camera must be enabled and Active. Disabling/removing it restores the texture's Clear Color rather than leaving stale pixels. A missing/deleted texture cannot redirect its camera into Game output. Only one active camera may write a texture: duplicate writers are suppressed with a diagnostic. Use separate assets or disable one producer. Runtime-created textures are temporary and do not save themselves as project assets.

Old Camera Render Target component

It remains supported for existing camera-owned transient outputs, but new authoring uses the Camera Render Target field and Texture asset. An explicit Texture overrides the old component if both exist. Old scenes are not broken or silently rewritten.

Scripts and advanced controls

C++ and Lua expose Texture and TextureDescriptor, typed Camera/Image/Material setters, runtime resizing and destruction. See C++ Texture or Lua Texture. Changing settings programmatically does not overwrite project files. Recursive feeds use safe double-buffered history; texture-space interaction forwarding is still separate from drawing an image.
