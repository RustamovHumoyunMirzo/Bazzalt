RenderTexture

This is the legacy camera-reference convenience API. New cross-source authoring uses a Texture asset/resource with Camera.RenderTarget and ordinary GuiImage.Texture/material samplers. FromCamera also supports a camera with an assigned writable Texture; GetSize/Resize forward to its resource descriptor.

A render texture is a live image produced by a camera instead of being presented directly in the Game viewport. Use it for monitors, minimaps, character previews, or camera-bound GUI. Include Bazzalt/RenderTexture.h. This handle does not own the camera or expose a native GPU pointer.

Create and display a camera feed

#include <Bazzalt/RenderTexture.h>
#include <Bazzalt/MaterialBuilder.h>
#include <Bazzalt/GUI.h>
auto camera = scene.CreateEntity("Security camera");
camera.AddComponent<Bazzalt::Camera>();
auto& target = camera.AddComponent<Bazzalt::CameraRenderTarget>();
target.Width = 512; target.Height = 256;
auto feed = Bazzalt::RenderTexture::FromCamera(camera);
auto material = Bazzalt::MaterialBuilder(
    Bazzalt::Shader::Builtin(Bazzalt::ShaderPreset::Unlit))
    .SetRenderTexture("baseColorTexture", feed).Build();
material.ApplyTo(monitor); // A primitive or mesh with UV coordinates.
image.GetComponent<Bazzalt::GuiImage>().SetRenderTexture(feed);
// The image must be a descendant of a Frame, not on the Frame itself.

Construction

RenderTexture() creates an empty reference. Copying a handle copies its camera UUID, not an image or GPU allocation.

FromCamera(Entity camera)

Returns a reference to a camera with both Camera and CameraRenderTarget components. Throws invalid_argument for an invalid entity or missing components. It does not add components or activate the camera.

FromCameraUUID(UUID id)

Creates a deferred reference without validation. A zero UUID makes an empty reference. Use IsValid with the intended Scene before relying on it.

GetCameraUUID()

Returns the producer entity UUID. This is an entity reference, not an asset UUID.

Resolve(Scene& scene)

Finds the referenced entity in the supplied scene. Returns an invalid Entity when absent. A handle never retains a Scene pointer; unloading its original scene cannot leave a dangling pointer.

IsValid(Scene& scene)

Returns true only if Camera is enabled and Active, and CameraRenderTarget is present and enabled. This checks logical eligibility, not GPU completion.

GetSize(Scene& scene)

Returns a Vec2 containing the effective requested pixel dimensions, bounded to 1–4096 per axis. Returns zero if the target component is missing. Size may be queried while the camera is disabled.

Resize(Scene& scene, uint32_t width, uint32_t height)

Updates the producer's target dimensions for the next render tick. Returns false when the target is missing. Throws out_of_range for dimensions outside 1–4096. Resize preserves this handle; consumers are rebound before old attachments are destroyed.

Materials and GUI

Material.SetRenderTexture(name, feed) binds a live output to a Texture2D shader parameter. Unlit and UnlitTransparent built-ins expose baseColorTexture; custom shaders can expose their own samplers. Lit built-ins do not expose this parameter. Wrong parameter names/types throw invalid_argument. GetRenderTexture(name) returns an empty handle when the parameter has an asset source. SetTexture, ResetParameter, and ResetProperties clear live bindings; cloning and compatible property copies preserve them. MaterialBuilder.SetRenderTexture follows the same validation at Build.

GuiImage.SetRenderTexture(feed) sets Camera and clears Texture. SetTexture(asset) does the reverse; GetRenderTexture() reads Camera. Existing serialized Camera and Texture fields remain compatible. Missing GUI feeds draw nothing; missing material feeds sample opaque black.

Rendering and lifetime

The engine renders active offscreen cameras once per tick, even with no Game panel open. Camera-Bound Frames are composited into their camera output after the 3D pass. Screen overlays and Spatial Frames may display the feed. Disabling a target restores the camera to normal presentation; disabling the Camera or its Active flag stops its output.

Chained feeds render in producer-first dependency order, not simply by camera Priority. Each producer owns two color attachments. Acyclic consumers see the producer's current completed tick; a strongly connected group (including a camera sampling itself) reads the previous completed tick and publishes its outputs together. This makes recursive monitors/mirrors safe without GPU read/write feedback. The first tick and newly resized history start empty: GUI images draw nothing and materials sample black until an output completes.

Shared world-material or Spatial GUI feeds conservatively freeze all capture cameras into one history group, because shared renderables cannot use different samplers per view and frustum/occlusion can change. This adds one tick of latency but never relies on visibility guesses. Camera-Bound GUI dependencies retain precise producer-first ordering. A capture renders once per tick; recursion is temporal, not an unbounded number of nested renders. Double-buffered color consumes twice the target color memory; depth is shared between sequential writes.

Material bindings are runtime-only overrides; they do not rewrite material assets. Persist GUI camera entity references in scenes, or establish material bindings in gameplay OnCreate. Native rendering ownership, attachment allocation, render order, and presentation remain private. Custom shader samplers and explicit target sizing provide advanced control without granting scripts access to the engine loop.
