C++ API reference

Use this reference to look up an engine type, every public method overload, its fields, defaults, and behavior. Start with the behavior tutorial if you have never written gameplay code.

Before reading a method

A type describes a kind of value: Entity is an object handle, Vec3 holds three numbers, and Material identifies material state. A method is an operation on a value. A static method belongs to the type rather than one instance. An argument is a value you supply; the return value is the result you receive.

For example, entity.GetWorldTransform() asks an existing entity for its world position, rotation, and scale. Bazzalt::Time::GetDeltaTime() calls a static service: you do not construct Time.

Read a C++ declaration

bool SetParent(Entity parent, bool worldPositionStays = true) const;

The bool at the start means the method returns true or false. Entity parent is the first argument. The second argument defaults to true, so you can omit it. The behavior notes explain which false results represent a rejected operation.

void means no returned value. Type& is a reference to existing storage; const Type& is read-only through that reference. Type* is a pointer and may be null where documented. std::optional<Type> means there may be no value. std::vector<Type> is a list. Do not read these forms as interchangeable ownership guarantees.

GetComponent<Light>() uses a template argument: the type Light chooses which component to retrieve. An overload is another declaration with the same method name but different argument types. The reference shows each available overload.

Lifetime and errors

Gameplay snippets run inside a hosted behavior/system. The engine owns the loop and active scene. Handles are not ownership: an entity reference must not outlive the scene storage it refers to. Re-resolve stable UUIDs after scene changes instead of keeping a dangling component pointer.

A documented false/null/empty result represents ordinary failure or absence. Invalid use may instead throw a C++ exception; some template restrictions are compile-time errors. Read the specific method notes, not just its return type.

Browse the reference

Expand C++ API reference in the sidebar, then choose a subject and type. Each type page lists its own public/protected extension methods and data; derived components also inherit the Component API. Private Detail plumbing and third-party EnTT APIs are not advertised as gameplay methods.

  • Entity and Scene: objects, hierarchy, geometry queries, and systems.
  • Input and Time: controls and simulation timing.
  • Camera, Light, and PrimitiveObject: renderable scene data.
  • Material and MaterialBuilder: runtime surfaces.
  • Vec3, Mat4, and Quaternion: math.

Macros, aliases, and module contracts

COMPONENT(Name) declares a final class derived from Behavior. PROPERTY(Type, Name, DefaultValue, ...) declares an authored field discovered by editor tooling. These are declaration macros, not functions to call. Each behavior type/property name must be unique in its scope.

PropertyMap aliases a string-to-string map for component serialization. GetScriptModuleApi is the native entry-point function-pointer type returning a ScriptModuleApi record. ScriptAbiVersion is currently 1. Generated module glue uses those contracts; beginners should use COMPONENT rather than build ABI records manually.

BAZZALT_API in Export.h marks exported/imported symbols when building/linking the library; it is not a gameplay operation. EcsConfig.h provides stable engine component type identity across modules. Its EnTT specialization macros and std::hash<UUID> hashing support are infrastructure, not separate component behaviors. Do not override the engine's built-in identity mappings.
