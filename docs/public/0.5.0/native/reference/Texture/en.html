Texture

A stable handle to a texture asset or runtime texture. A writable texture owns its dimensions and rendering configuration independently of any camera or consumer. Include Bazzalt/Texture.h. Native GPU objects remain private.

Camera output as an ordinary texture

Bazzalt::TextureDescriptor settings;
settings.Width = 1024; settings.Height = 512;
settings.Samples = 4;
settings.Mipmaps = true;
settings.ColorFormat = Bazzalt::TextureColorFormat::RGBA16F;
auto texture = Bazzalt::Texture::Create(settings);
camera.GetComponent<Bazzalt::Camera>().SetRenderTarget(texture);
image.GetComponent<Bazzalt::GuiImage>().SetTexture(texture);
material.SetTexture("baseColorTexture", texture);
// Or use Texture::Load(textureAssetUUID) for a project .btexture file.

Construction and Load

Texture() is an empty handle. Static Load(UUID) creates a non-owning reference; it does not import a file or initialize the engine. GetAssetUUID() returns the stable resource identity. Copying a handle does not copy image data.

Create(descriptor)

Creates a transient writable texture with a generated UUID. Descriptor validation is immediate; GPU allocation is lazy when a camera or consumer uses it. Invalid settings throw invalid_argument. The engine owns allocation, double-buffering, resolve and teardown.

IsValid and IsRenderTarget

IsValid() checks a writable descriptor or a ready imported PNG/JPEG texture asset. IsRenderTarget() checks writable .btexture/transient resources specifically. A camera accepts only writable textures. Logical validity does not promise GPU completion or format support on every device.

IsRuntime()

Reports whether the handle owns a transient runtime descriptor, rather than a project asset. Runtime textures are not persistent project files.

GetDescriptor()

Returns a copy of the current writable descriptor, including runtime overrides. Throws invalid_argument for a missing/deleted resource or an ordinary image asset. Ordinary image import settings are not falsely presented as writable GPU attachments.

SetDescriptor(descriptor)

Validates and applies a runtime override. It does not write asset files. Size, color/depth format, sample count or mip allocation changes recreate attachments safely at the next renderer preparation. Filter/wrap settings update consumers without replacing the texture identity.

ResetDescriptor()

Removes runtime overrides, returning to the imported descriptor or the original Create descriptor. Invalid handles throw invalid_argument. Stop restores asset defaults and discards transient runtime textures.

Resize(width, height)

Updates writable dimensions, validating the 1–4096 pixel range. Explicit mip counts are reduced when the new size has fewer levels. All camera/GUI/material references keep the same UUID. Imported source files are not modified.

Destroy()

Deletes only transient descriptors and returns true once. Imported assets are never removed by gameplay. GPU resources are retired during subsequent preparation after borrowers are detached. Referencing an invalid texture does not silently redirect the camera to Game output.

Producer and consumer rules

Camera.RenderTarget stores the texture UUID; SetRenderTarget(Texture) validates writable type and GetRenderTarget() returns the handle. An empty handle restores normal camera presentation. Camera must be enabled and Active to produce frames. With no producer, a writable texture displays its descriptor ClearColor, not a stale camera frame. Multiple active cameras targeting the same texture are rejected as conflicting captures; neither overwrites the other. Use separate textures or disable one producer.

GuiImage.Texture, Material.SetTexture and MaterialBuilder.SetTexture accept the same UUID or Texture handle. Viewport, Camera-Bound and Spatial GUI all sample the same resource. Dependencies render producers first; recursive groups sample completed history. Camera-Bound controls rendered into textures remain display-only until texture-space input forwarding is added. Existing Texture2D shader samplers share the centralized loader; no source-specific camera ID is required.

Camera Render Target component

CameraRenderTarget is retained for old scenes and code that use camera-owned transient outputs. New authoring uses Texture assets and the Camera Render Target picker, so the legacy component is hidden from Add Component. When both are present, Camera.RenderTarget takes precedence. Existing RenderTexture/GuiImage.Camera APIs remain compatible; they are convenience references, not the new resource identity.
