GUI in C++

Build gameplay interfaces from ordinary scene entities. A Frame owns rendering; child entities supply layout and widgets. The engine updates and draws them automatically.

In the editor, use Hierarchy → Add New → GUI to create Frames, containers, rectangles, text, images, buttons and text inputs. Creating a widget outside an existing Frame automatically creates a Viewport Frame parent. For Camera-Bound Frames, select the destination camera in the properties. Runtime builds ship the separate GUI library beside the core library (bazzalt_gui.dll on Windows); scripts still use the normal core C++ API.

A Frame and its children

Include Bazzalt/GUI.h, or individual headers under Bazzalt/Components/GUI/. Add Frame to an entity, then parent widget entities underneath it. A widget requires RectTransform. Widgets outside a Frame do not render. Other GUI components on the Frame entity itself do not render: create a child for its background. Non-layout intermediate entities pass the parent's rectangle through. A nested Frame is an independent render root, not another widget.

#include <Bazzalt/GUI.h>
#include <Bazzalt/Scene.h>

void CreateHUD(Bazzalt::Scene& scene) {
    auto frame = scene.CreateEntity("HUD");
    frame.AddComponent<Bazzalt::Frame>();
    auto button = scene.CreateEntity("Continue");
    button.SetParent(frame, false);
    auto& layout = button.AddComponent<Bazzalt::RectTransform>();
    layout.Position = {24, 24};
    layout.Size = {180, 40};
    button.AddComponent<Bazzalt::Rectangle>();
    button.AddComponent<Bazzalt::GuiButton>();
    button.AddComponent<Bazzalt::GuiText>().Value = "Continue";
}
// Inside your behavior's OnUpdate:
// if (Bazzalt::GUI::GetInteraction(button).Clicked) { /* continue game */ }

The engine owns initialization, event dispatch, and drawing. No GUI BeginFrame, renderer, GPU object, or engine-loop override is exposed. GUI authoring components serialize with scenes, including enabled flags. Interaction state is transient and never saved. Editor Add Component and Properties support these components.

Frame modes

FrameModeBehavior
ViewportComposited over the entire Game presentation surface, independent of a camera. It remains available with no game camera. Scene-editor overlays are separate from gameplay GUI.
CameraBoundUses the referenced enabled, active Camera's normalized viewport, including its offscreen target if enabled. Useful for split-screen HUDs and GUI in camera feeds. A missing, disabled, or inactive camera suppresses the frame. It is composited GUI, not a depth-tested camera-space plane.
SpatialDraws in the 3D scene. The Frame entity's world Transform positions/orients/scales the whole GUI. PixelsPerUnit converts layout units to world units. Its local XY plane is centered on the Frame's origin; layout Y points downward. Depth-tested against the scene.

Every mode uses the same widget components, styles, layout, clipping, and input state. Changing Frame.Mode does not require replacing the widget hierarchy. Lower Frame.ZIndex draws first; ties use Frame UUID. Within a parent, lower RectTransform.ZIndex draws first; equal values preserve hierarchy order. A parent draws before its descendants.

RectTransform and responsiveness

Coordinates are top-left based. AnchorMin and AnchorMax are fractions of the parent rectangle. Size is an additive pixel size; Position is a pixel offset from AnchorMin. Pivot is a fraction of the resolved size. The exact formula is size = parentSize * (AnchorMax - AnchorMin) + Size * scale, then position = parentPosition + parentSize * AnchorMin + Position * scale - Pivot * size. MinSize/MaxSize clamp the result. Unlike the 3D Transform, this component only controls GUI layout.

FieldDefault
AnchorMin, AnchorMax, Pivot, PositionVec2(0,0).
SizeVec2(160,40).
MinSize / MaxSizeVec2(0,0) / Vec2(100000,100000).
ZIndex0, sibling ordering.
Visibletrue; hidden/disabled layout suppresses descendants.
ClipChildrenfalse; true clips descendants to this rectangle. Every Frame clips at its own boundary.

For a centered fixed-size element, set both anchors and Pivot to (0.5,0.5). For full stretch, use AnchorMin=(0,0), AnchorMax=(1,1), Pivot=(0,0), Size=(0,0). For a right-aligned element, use both anchors=(1,0), Pivot=(1,0). Resizing recalculates bounds automatically. GUI.GetBounds returns the latest resolved rectangle in presentation pixels, or spatial layout units.

Widget components

ComponentFields and behavior
RectangleStyle (GuiStyle); RaycastTarget=true. Draws a filled rectangle with optional border; can block pointer hits without being a button.
GuiImageTexture=zero asset UUID, Camera=zero entity UUID, Color=(1,1,1,1), RaycastTarget=false. Samples an imported PNG/JPEG texture or camera target; nonzero Camera takes precedence. Missing sources draw nothing.
GuiTextValue empty, Color=(1,1,1,1), FontSize=16, Wrap=true. Draws built-in monospace text, clipped to its rectangle. Explicit newlines and optional wrapping are supported.
GuiButtonInteractable=true, TabIndex=0. Supplies click/focus behavior, not its own visuals. Combine with Rectangle, GuiText, or GuiImage.
GuiTextInputValue/Placeholder empty, MaxLength=256 Unicode code points, ReadOnly=false, Password=false, Interactable=true, TabIndex=0. Single-line committed-text input with backspace and Enter submit. Supplies built-in value/placeholder visuals; add Rectangle for a background.

Each component inherits Enabled/IsEnabled/SetEnabled from Component. A disabled widget contributes no draw/behavior of its own; enabled components on the same entity still operate. Disabling its RectTransform or owning Frame suppresses the subtree. Negative TabIndex excludes a control from keyboard traversal. A disabled Button/Input's rectangle can still block underlying hits.

GuiStyle reference

Color defaults to (0.22,0.24,0.28,1), HoverColor to (0.3,0.34,0.4,1), PressedColor to (0.12,0.22,0.36,1), DisabledColor to (0.16,0.17,0.19,0.7), and BorderColor to (0.05,0.06,0.08,1). BorderWidth defaults to zero and is scaled with the frame; Opacity defaults to one and is clamped to [0,1]. Focus uses HoverColor. State colors apply to Rectangle when composed with an interactive control. Images/text have their own tint. There is no CSS parser or cascade yet.

GUI methods and interaction

MethodContract
GetInteraction(Entity)Returns GuiInteraction by value. Missing/unrendered entities return default state.
GetBounds(Entity)Latest GuiBounds; missing layouts return zero bounds.
GetFrame(Entity)Nearest ancestor with Frame, excluding the entity itself; invalid if none.
Focus(Entity)Focus a visible enabled/interactable Button/Input with resolved layout; returns false if unavailable.
ClearFocus(Scene&)Release the scene's GUI keyboard focus.
IsPointerOverUI(Scene&)Whether an eligible GUI hit target currently owns hover.

GuiInteraction.Hovered, Pressed, and Focused describe current state. PointerEntered, PointerExited, Clicked, ValueChanged, and Submitted are one-update pulses. Read them from gameplay OnUpdate; querying does not consume them. Press captures the control; releasing outside it cancels click. Only the frontmost eligible target receives pointer interaction. Tab/Shift+Tab navigate, Escape clears focus, Enter activates/submits, and Space activates buttons. Losing game-window focus clears GUI hover, capture, and keyboard focus. Gameplay input remains readable; use IsPointerOverUI and your focused-control state to gate game actions.

GuiBounds contains Position and Size. Contains(Vec2) uses inclusive left/top and exclusive right/bottom edges; empty bounds never contain a point. Input.GetTextInput returns UTF-8 committed text for the current input frame, not physical key names.

Camera render textures

For new scenes, create/load a Texture, assign it through Camera.SetRenderTarget and GuiImage.SetTexture. The same texture is usable by materials and Spatial GUI. The example below remains supported for legacy transient camera targets.

#include <Bazzalt/Components/CameraRenderTarget.h>
// camera already has a Camera component:
auto& target = camera.AddComponent<Bazzalt::CameraRenderTarget>();
target.Width = 512; target.Height = 512;
auto feed = Bazzalt::RenderTexture::FromCamera(camera);
imageEntity.AddComponent<Bazzalt::GuiImage>().SetRenderTexture(feed);

CameraRenderTarget inherits Component and has Width/Height, both defaulting to 512. Attach it to a Camera, not a GUI Image. The engine owns color/depth buffers, target creation, resizing, and teardown. The valid serialized range is 1–4096 per dimension; runtime writes are clamped to that range. An enabled target sends that camera offscreen rather than directly presenting its view. Removing/disabling it restores ordinary viewport output. GuiImage refers to the camera UUID, never a GPU handle. Camera feeds work in every Frame mode. Offscreen cameras include spatial GUI and use double-buffered history to prevent feedback; targets render before presentation cameras.

Foundation boundaries

RenderTexture reference covers explicit resizing, live material samplers, and GuiImage.SetTexture/SetRenderTexture/GetRenderTexture. Offscreen cameras render once per tick even when the Game panel is closed. A dependency graph orders chained feeds; cycles sample the previous completed tick safely.

This is a retained GUI foundation, not a complete desktop UI toolkit. The built-in font is a small ASCII-oriented bitmap font (lowercase currently shares uppercase glyph shapes); unsupported Unicode glyphs show a box while input values preserve UTF-8. There is no font asset/shaping, IME preedit display, caret/selection editing, clipboard editing, scrolling container, accessibility tree, stylesheet, animation system, or drag/drop widget yet. Spatial input ray-tests the GUI plane, not occluding 3D geometry. Offscreen GUI frames are display-only: interacting through a camera feed requires texture-space input forwarding, not yet implemented. A camera sampling itself uses its previous completed output. One game input surface owns scene GUI focus at a time. Hierarchy/layout traversal is bounded to 128 levels. These boundaries are explicit rather than silently simulated.
