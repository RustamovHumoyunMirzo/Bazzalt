Write a C++ behavior

Attach this behavior to a cube to move it with WASD. The editor supplies the entity and calls the behavior while the game is playing.

Create the file

If headers, namespaces, references, templates, or callbacks are new, read Read your first C++ example before continuing. You still do not need to write an engine loop.

Create a C++ component in the Asset Browser, or add Walk.cpp beneath your project's asset directory, for example Assets/Scripts/Walk.cpp. Replace its contents with this code:

#include <Bazzalt/Script.h>
#include <Bazzalt/Input.h>
#include <Bazzalt/Math.h>

COMPONENT(Walk) {
public:
    PROPERTY(float, Speed, 4.0f)

    void OnUpdate(float deltaTime) override {
        using namespace Bazzalt;
        Vec3 direction{Input::GetAxis(InputAxis::Horizontal), 0.0f,
                       -Input::GetAxis(InputAxis::Vertical)};
        if (direction.LengthSquared() == 0.0f) return;

        auto entity = GetEntity();
        auto transform = entity.GetWorldTransform();
        transform.Position += direction.Normalized() * Speed * deltaTime;
        entity.SetWorldTransform(transform);
    }
};

What the code does

COMPONENT(Walk) declares an attachable behavior named Walk. PROPERTY(float, Speed, 4.0f) exposes a floating-point value in the Properties. The default is 4 world units per second. The Properties can supply another value before OnCreate runs.

OnUpdate receives the frame's scaled time step in seconds. Multiplying movement by deltaTime keeps speed from depending directly on frame rate. Normalizing the direction prevents diagonal movement from being faster. The zero-length test avoids normalizing a vector that has no direction.

GetWorldTransform returns a value, not a live component reference. After changing that value, SetWorldTransform commits it to the entity, accounting for its parent. The negative vertical axis makes W move along world negative Z. This is world-axis movement, not camera-relative movement or a physics controller.

Attach and run

  1. Create a cube and make sure an enabled game camera can see it.
  2. Select the cube and choose Walk under Add Component's script entries, or drag the script onto the entity.
  3. Set Speed in the Properties if needed.
  4. Press Play. If compilation fails, read the Compiler messages in Console.
  5. Click Game output to give gameplay input focus, then press WASD.

Scene view's right-click flying controls move the editor camera, not this cube. Input is inactive when gameplay does not have focus. Typing W into an Properties field should not move the object.

Other lifecycle callbacks

Use OnCreate() to acquire runtime state and OnDestroy() to release resources you own, such as a transient material. OnFixedUpdate(float fixedDeltaTime) is available for fixed-step work. Do not initialize the engine, poll the operating system, or present frames from these methods.

Names and properties

Each source declares one COMPONENT, and its type name must be unique across C++ and Lua behaviors in the project. Two files both declaring COMPONENT(Walk) are a conflict even if their filenames differ. Property names must also be unique within the behavior. Resolve duplicate declarations instead of attaching them and expecting their fields to merge.
