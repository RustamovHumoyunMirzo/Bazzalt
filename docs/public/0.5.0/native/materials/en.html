Runtime materials

Create a material from a precompiled shader, set its values, and apply it to a Mesh or Primitive Object without exposing renderer internals.

Shader and material are different

A shader defines what a surface can do and which parameters it accepts. A material chooses that shader and gives the parameters values. A material cannot invent a new parameter that the shader has not declared. Runtime creation does not run a shader compiler.

Build a material

#include <Bazzalt/MaterialBuilder.h>

auto surface = Bazzalt::MaterialBuilder()
    .SetColor("baseColor", {0.2f, 0.5f, 0.9f, 1.0f})
    .SetFloat("roughness", 0.35f)
    .SetFloat("metallic", 0.1f)
    .Build();
surface.ApplyTo(entity);
surface.SetFloat("roughness", 0.8f); // Applied on a subsequent render update.

The builder defaults to StandardLit. Unknown parameter names, mismatched types, and non-finite numeric values are rejected. Build cleans up its temporary material if validation fails. Keep the resulting handle for later edits and cleanup.

Built-in presets

Shader::Builtin(ShaderPreset) supports StandardLit, Unlit, StandardLitTransparent, and UnlitTransparent. You can pass that shader to MaterialBuilder or use Material::Create(preset).

ParameterType and defaultAvailable on
baseColorVec4, white (1, 1, 1, 1)All presets
emissiveVec3, zeroAll presets

metallicfloat, 0Lit presets
reflectancefloat, 0.5Lit presets

Colors are linear values. Alpha changes require a transparent shader preset to make the surface transparent. Built-in presets support double-sided surfaces; imported shaders need their own appropriate compiled capabilities.

Shared assets and owned runtime instances

Material::Load(uuid) references a shared material asset. Editing it affects other users of that handle, but does not write its asset file. Use Instantiate to make an independent runtime copy. Create and Build also produce transient materials.

Call Destroy on a transient material when you no longer need it. Destroy invalidates all copies of its handle; it does not delete an imported asset. If still assigned, its renderables fall back to their original material on a following update. Stop/runtime reset also discards runtime materials. Saving a scene does not serialize a transient material definition just because its UUID was assigned to a component.

Apply to objects and slots

ApplyTo affects the specified entity only by default. Pass Material::AllSlots, true to include descendants explicitly. It assigns existing Mesh and PrimitiveObject components and returns the number of affected entities; it does not create those components.

A Mesh supports SetMaterial(material) for all slots or SetMaterial(slot, material) for one zero-based slot. ClearMaterial removes overrides. A primitive has only slot zero. Imported glTF's original materials are renderer-owned and are not automatically exposed as separate material asset handles.

Change and reset

Use SetShader to switch shaders; matching names and types can keep their values. CopyPropertiesFrom copies compatible values into another material. ResetParameter and ResetProperties remove overrides, while HasOverride distinguishes an edited value from a default.

MaterialRenderState controls culling, double-sided lighting, depth testing/writing, color writing, and the depth comparison function. SetRenderState enables the override; ResetRenderState restores the compiled defaults. Blending and shader features are compiled settings, so choose another shader instead of expecting depth-write changes to make an opaque material transparent.

Lua equivalent

local B = Bazzalt
local surface = B.MaterialBuilder.new()
    :SetColor("baseColor", B.Vec4.new(0.2, 0.5, 0.9, 1))
    :SetFloat("roughness", 0.35)
    :Build()
surface:ApplyTo(self.Entity)
-- Keep surface as self.Surface; destroy it in OnDestroy when no longer used.

Lua exposes the same typed values, builder, shader presets, and lifecycle. Its AllSlots marker is -1; specific slots still start at zero. See Lua conventions for component snapshot/write-back behavior.
