C++ gameplay API

C++ gameplay code uses the public headers under Bazzalt. The editor and runtime own initialization, input delivery, rendering, and shutdown.

Public headers

Include headers with their exact names and case, such as <Bazzalt/Scene.h> or <Bazzalt/Math.h>. Functions use PascalCase: AddComponent, GetWorldTransform, and SetEnabled. Do not include private Runtime or EditorBridge headers to make a behavior work.

HeaderPurpose
Bazzalt/Script.hBehavior callbacks and COMPONENT/PROPERTY declarations.
Bazzalt/Entity.h, Scene.hObjects, hierarchy, scene queries, and model instantiation.
Bazzalt/Component.h, System.hCustom data components and systems that process them.
Bazzalt/Math.hVec2, Vec3, Vec4, Mat3, Mat4, Quaternion, and related math operations.
Bazzalt/Input.h, Time.hGameplay input and scaled/unscaled time.
Bazzalt/Material.h, MaterialBuilder.h, Shader.hRuntime materials and precompiled shader handles.
Bazzalt/SceneManager.hActive-scene access and deferred scene-loading requests.

How gameplay code runs

A behavior is a script component attached to an entity. The runtime creates its instance, applies Inspector property values, then calls its lifecycle methods. Put initialization in OnCreate, per-frame work in OnUpdate, and cleanup in OnDestroy. You do not write main() or call an engine's update function.

A data component is not necessarily a behavior. A C++ struct derived from Component can hold data for a System to process. Creating such a struct alone does not create automatic Inspector reflection or persistent scene serialization. See Entities and components for this distinction.

Script toolchain

The editor compiles enabled attached C++ behaviors when entering Play. It uses a matching Script SDK and toolchain. On Windows, the production setup uses the Hub's shared LLVM tools plus Microsoft C++ Build Tools and the Windows SDK. Clang by itself is not the complete Windows development environment.

Preferences → Build Tools can point to another supported compiler/SDK setup. Use the SDK for your engine version and architecture. Do not mix a 32-bit module with the 64-bit editor, or assume a module built against an older SDK exports every new API.

Build failures appear in Console and prevent Play from starting. Lua-only projects do not need native script compilation.

Request a scene change

#include <Bazzalt/SceneManager.h>

bool RequestNextScene(Bazzalt::UUID sceneAsset) {
    return Bazzalt::SceneManager::LoadScene(sceneAsset);
}

This requests a load at a safe frame boundary. A true result is not a guarantee that the scene has already changed before the callback returns. Inspect IsLoadPending and GetLastError when needed. Project management and authoring saves stay with the editor and Hub.
