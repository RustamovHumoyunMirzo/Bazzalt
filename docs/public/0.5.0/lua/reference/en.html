Lua API reference

This reference lists the registered Bazzalt Lua types, fields, functions, methods, enums, and lifecycle callbacks. It describes actual bindings rather than assuming every C++ declaration has identical Lua syntax.

Start with a small script

If Lua is new to you, follow Write a Lua behavior first. A script returns a table describing its behavior. The engine supplies self.Entity and calls your optional lifecycle methods while the game is playing.

Read calls and results

local world = self.Entity:GetWorldTransform()
world.Position = world.Position + Bazzalt.Vec3.new(0, 1, 0)
self.Entity:SetWorldTransform(world)

local creates a script-local variable. The first line receives a result from a method. The colon passes the entity to its method. The second line creates a vector and adds it to the copied position. The final line commits the edited world Transform; merely changing a returned value is not always a scene change.

Static functions use a dot, for example Bazzalt.Time.GetDeltaTime(). Constructors use .new(), for example Bazzalt.Vec3.new(1, 2, 3). Object methods use a colon. Reference call signatures use square brackets to mark optional arguments; omit the brackets when writing code.

Copies, lists, and indices

GetComponent returns a copy. Commit it with SetComponent after editing. Returned lists are ordinary one-based Lua tables, while explicit matrix, node, viewport-grid, material-slot, and effect indices follow their documented zero-based engine indexing.

Some methods return several values, such as success and an inverse matrix. Check success before using output values. nil means absence where documented. A non-nil Entity can still be invalid; use entity:IsValid().

Browse the bindings

  • Behavior: callback table and self.Entity.
  • Entity and Scene: component operations, world placement, systems and queries.
  • Input and Time: read game controls and time.
  • Vec3, Mat4, and Quaternion: values and arithmetic.
  • Camera and Material: rendering data and runtime surfaces.

Binding differences matter

Scene is host-owned, not Bazzalt.Scene.new(). C++ templated component operations become string-based Lua operations, such as GetComponent("Light"). Raw matrix pointers, native serializer callbacks, and arbitrary C++ custom structs are not automatically available in Lua.

The underlying C++ declaration is shown for comparison/default values, but use the Lua call displayed above it. Matrix Get/Set, PostProcessingStack.SetEffect, UUID.Parse, and named Lua systems are binding conveniences with their own documented signatures.

Errors and sandbox

Wrong component names/types, invalid argument ranges, and native exceptions are reported as Lua errors by protected callbacks. Read Console. Gameplay Lua does not expose os, io, package, debug, loadfile, or engine-loop initialization. Bytecode is imported asset data and still needs the matching shared Lua VM at runtime.
