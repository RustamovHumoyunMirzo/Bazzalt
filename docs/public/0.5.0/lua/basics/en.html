Lua terms and first calls

This guide explains the notation used in BAZZALT Lua examples. You do not need to memorize the API reference before writing a behavior.

Values and variables

local speed = 4
local label = "Player"
local enabled = true

A value is data: a number, text, or true/false. A variable is a name used to keep a value. local makes that variable local to the surrounding script/function rather than an accidental global. Text in quotes is a string. true and false are booleans; nil means no value.

The equals sign stores a value. The double equals sign compares values. Plus adds numbers or supported vectors; star multiplies them. Case matters: Speed and speed are different names.

Tables and fields

local Walk = { Speed = 4 }
Walk.Speed = 6

A table groups named values. Here Speed is a field on Walk. A dot reads/writes a field. The engine also exposes typed values such as Vec3; they look similar to tables when accessing X/Y/Z, but accept the operations defined by their bindings.

Use Bazzalt.Vec3.new(0, 1, 0) to construct a 3D vector. Zero-argument Vec3.new() creates (0,0,0). It is not a scene object; it is just three numbers used to describe position/direction.

Functions, arguments, and results

local direction = Bazzalt.Vec3.new(1, 0, 1)
local unitDirection = direction:Normalized()

A function performs an operation. Its arguments go inside parentheses. Its result can be stored in a variable. The first call constructs a vector using three numbers. The second returns a unit-length copy; it does not change direction itself.

A static call such as Bazzalt.Time.GetDeltaTime() uses a dot. An object method such as entity:GetWorldTransform() uses a colon to pass that object. Do not replace one syntax with the other arbitrarily.

Callbacks and self

local Walk = { Speed = 4 }
function Walk:OnUpdate(deltaTime)
    local entity = self.Entity
end
return Walk

A callback is a function the engine calls for you. OnUpdate runs during gameplay updates. Its deltaTime argument is the current time step in seconds. With a colon-defined method, self is the table being updated. The runtime supplies self.Entity, the object this behavior was attached to.

The file returns Walk so the runtime can use that table as the behavior. There is no manual engine loop in the script. OnCreate/OnDestroy are optional setup/cleanup callbacks, not commands that launch or close the editor.

Why changing a copy may do nothing

local light = self.Entity:GetComponent("Light")
light.Intensity = 1200
self.Entity:SetComponent("Light", light)

The first line gets a copy of an existing Light component. The second changes that copy. The final line commits it into scene storage. Without the final line, this is not a reliable way to edit the actual component. Add the Light first or test HasComponent before retrieving it.

Movement rates and errors

Moving four units every frame makes speed depend on frame rate. Moving 4 * deltaTime units per update describes four units per second. Input is read from Game output's focus, not from typed letters in Properties.

An unknown method, misspelled component name, nil value, or incompatible argument can raise an error. Read Console and compare the exact names with the Lua reference. Start with the complete Walk example rather than mixing unverified snippets.
