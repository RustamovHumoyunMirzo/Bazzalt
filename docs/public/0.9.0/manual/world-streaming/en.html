World and scene streaming

A world cell is a scene file representing one region of a larger world. Streaming loads nearby regions and removes distant ones while the persistent scene keeps running. A streaming source is usually the player or a camera that tells the engine which regions matter.

Create a streaming world

  1. Create separate scene assets for your regions. Each must have its own entity UUIDs. Use prefabs for repeated scenery inside the regions.
  2. In the persistent scene, create an empty entity for each region and add World Cell.
  3. Choose the region's scene in Scene Asset. Place the definition entity at the region's world offset. The cell's scene-root entities are parented under this offset.
  4. Set Half Extents to half the local region dimensions. For a 256-by-128-by-256 region, use 128, 64, 128.
  5. Choose a Load Distance measured from the region's edge and a larger Unload Distance. For example, 100 and 150 avoid repeatedly loading at a boundary.
  6. Add Streaming Source to the player or camera. Leave Distance Scale at 1 initially. Enter Play and move the source.

How residency works

All enabled sources contribute. One nearby player can keep a region loaded even when another player moves away. Always Loaded keeps essential regions resident without a source. Priority selects which waiting regions enter the queue first; it does not evict existing residents. Disabled sources stop contributing; disabled or removed cell definitions retire their automatically loaded regions.

Authoring components work during Play and standalone gameplay. In edit mode they remain configuration data. The active scene keeps its environment and physics settings. Camera selection and Game output behavior are unchanged: streaming does not create a fallback camera.

Loading and unloading

File IO and scene parsing run on workers. Components, scripts, audio, physics and rendering integrate on engine-owned frame boundaries. A cell is ready for gameplay only after Complete. Unloading stops its scripts and removes entities over several frames within the streaming budget. Objects from outside the cell that were parented under it are detached and preserved.

Do not use one scene asset for several different cells. Conflicting entity UUIDs fail safely, and duplicate authored definitions are rejected. Deleting a region file reports a streaming error rather than silently spawning an empty substitute. Failed automatic loads can retry; inspect them through the C++/Lua streaming API.

Programming and budgets

C++ and Lua can register cells or regular grids, maintain multiple named sources, request manual loads, poll handles, inspect residency and events, and configure budgets. See C++ streaming or Lua streaming. Main-thread time limits are soft around user callbacks. Save-game state is separate from residency: runtime changes inside a cell are not automatically written back to its scene asset.
