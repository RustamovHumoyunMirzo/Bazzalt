Live gameplay script reload

During Play, save an attached C++ or Lua gameplay script in your code editor. Bazzalt debounces the change, compiles native code in the background, imports Lua bytecode and stages replacement script instances. The active scene stays open. Compilation diagnostics appear in Console.

Controls

Edit > Reload Gameplay Scripts, or Ctrl+Alt+R, requests a reload immediately. Preferences > Scripting > Automatically reload gameplay scripts during Play controls file watching. Quoted project headers used by attached C++ sources are watched too. A failed compilation or incompatible state leaves the old instances running. Correct the problem and save again.

What stays active

Entity UUIDs, hierarchy, transforms, components, physics simulation, audio playback and elapsed game time are not reset. Declared C++ properties retain their current gameplay values. Lua data fields retain supported values, including nested tables. Spawned prefab and streamed-cell scripts participate; cell unload still owns their teardown. New properties use new defaults; changing an existing property's type requires stopping Play or an explicit migration.

Reload lifecycle

Replacement instances do not replay OnCreate and old instances do not receive OnDestroy during a successful swap. OnReload runs after replacement behaviors are registered. Scripts should reconnect event handlers and rebuild temporary caches there. New script attachments initialize through OnCreate after commit. Normal Stop still invokes OnDestroy. Stop restores the original authoring scene, as before.

Boundaries

This workflow reloads entity gameplay scripts, not native engine code, global subsystems or extension binaries. Global subsystem changes require restarting Play. Native raw pointers to behaviors become invalid: reacquire them through Scripts.Find/Get. Lua closure upvalues, coroutines, VM globals and unsupported userdata are not copied. Cyclic tables and incompatible state reject reload. Keep C++ constructors and Lua top-level declarations free of scene or external side effects: staging cannot undo arbitrary user code. A failure inside OnReload occurs after commit and is reported rather than rolling back gameplay side effects.

For state hooks and examples, see C++ reload state and Lua reload state.
