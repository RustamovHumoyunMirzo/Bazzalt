Animation

Animation changes a model's bones over time. A skeleton describes the parent-child relationship between bones, a clip contains timed position, rotation and scale keys, and an Animator evaluates clips for one model instance. A controller chooses which motion plays. Copies of a model share imported clip data and keep independent playback state.

Animate an imported model

  1. Import a glTF or GLB containing a skin and animations. Export bone animation from your modelling tool; apply consistent units and a bind/rest pose.
  2. Drag the model into Hierarchy. Its model root owns the imported node hierarchy. Add an Animator to that root. Leave Model empty to use the Model Instance's model, or explicitly pick a glTF/GLB.
  3. Leave Controller empty to play the model's first clip. Default Clip selects another imported clip by name. Speed multiplies playback; Loop and Play On Awake control the automatically generated default states.
  4. Enter Play. Animation updates the node transforms and the renderer's skin palette; mesh instances animate independently. Disabled Animator components stop evaluation.

Animation panel and timeline

Open Window > Animation and select a model root. Clips & Timeline lists the imported clips and skeleton. Each timeline row names a bone and a channel; squares mark keys. Click or drag on the timeline, or edit Time, to sample a pose. Play/Pause, preview speed and timeline zoom help inspect movement. Imported keys remain read-only. Open a controller, switch to Authored Clips, and use Copy Imported Clip to create an editable override, or New Clip for an empty clip. Add tracks, choose a bone index and channel, edit key times/values and cubic tangents, and add named markers. Changes save automatically and support Edit > Undo/Redo. Track times must increase and stay inside Duration; quaternion rotation values cannot be zero. Use the same clip name in a state to play the override. Preview Clip plays it on the selected model without changing the source model.

Preview is an editor transaction. Stopping preview, hiding the panel, changing the selected model, saving, or entering Play restores the original transforms and Animator settings. Preview is unavailable while the game is playing. It does not intentionally change scene authoring data.

Controller graphs and blend trees

Create an Animation asset in Asset Browser. Its .banim controller stores a versioned JSON/YAML-compatible graph. Double-click it to open Controller Graph. Add states, name them, assign imported clip names and mark one as the entry state. Drag state boxes to arrange the graph; changes save automatically and support undo/redo within the panel.

A state uses a single clip, a 1D blend tree, or a 2D freeform blend tree. For 1D, samples have thresholds on X: the two neighbouring samples blend, and values outside the range clamp to the endpoint. For 2D, X/Y positions use normalized inverse-square distance weighting, with exact sample positions selecting that sample. This is freeform weighting rather than triangulated or directional locomotion. Blend trees synchronize sample phase using their weighted duration. Set parameters from gameplay through Animation.SetParameter.

Transitions have source/target states, fade duration, an optional normalized exit time (-1 disables the time condition), and numeric conditions. Every condition must pass; comparisons are >, <, == and !=. Conditions on the current state are tested in asset order, with at most one new transition per evaluation. Source "*" in the API/document matches any state. An active crossfade completes before another automatic transition starts. SetTrigger supplies a value of one, consumed when a matching transition uses it.

Assign the .banim asset in the Animator's Controller field. Imported clip names must exist in the selected model, or the retarget source. Missing clips and invalid graphs produce an Animation console error rather than silently mixing unrelated data.

Layers, IK and forward kinematics

The API supports named override and additive layers. A per-bone mask contains weights from zero to one. Additive motion measures translation, rotation and scale relative to the rig's bind pose. Layer names are evaluated in stable lexical order; choose names such as 00_BaseCorrection and 10_UpperBody when order matters.

Forward kinematics computes model-space matrices from local transforms and the bone hierarchy. Two-Bone IK solves an exact three-joint chain with a pole point that chooses the bend direction. CCD rotates joints iteratively towards the target. FABRIK iterates joint positions while retaining segment lengths, then reconstructs bone rotations. Targets and pole points in IKSettings are in skeleton/model space, not screen space. Unreachable targets produce a best-effort pose and a false result. Zero-length chains and invalid ancestry are errors.

For persistent scene constraints, add an IK Constraint to a helper entity. Pick its Animator Entity and optional Target/Pole Target. With no Target, the helper is the target. Root Bone and Tip Bone are zero-based indices listed by the skeleton/API. Weight blends the result. Ground Raycast projects the target onto the active physics world along scene gravity, using Ray Distance, Ground Offset and Layer Mask. The component's target fields are entity references and participate in scene/prefab remapping.

Root motion and physics

Root Motion Disabled leaves movement in the skeleton. Extract Only removes movement from the selected Root Bone and reports RootDelta/RootRotation without moving the entity. Apply to Transform moves the model root. Kinematic Physics requires Animate Physics, a kinematic Rigidbody on the root and a running physics world; movement is passed through the physics kinematic API before the fixed step. Loop boundaries account for the clip's displacement instead of snapping the root backwards.

Animate Physics evaluates at the fixed step; ordinary animation uses the frame delta (or unscaled time when requested). Animated child bones with kinematic rigidbodies receive kinematic targets. Dynamic rigidbodies retain physics ownership: animation does not teleport them, and their transforms feed back into the final pose. Compose bone rigidbodies, colliders and joints for ragdolls or partial physical animation. Use fixed-step animation for physics-driven characters. Transform root motion deliberately bypasses collision solving; choose kinematic mode when physical motion is required.

Retargeting

A controller can select a Source Model and Translation Scale. Its clips play on the target model's skeleton using bind-pose rotation correction. With no explicit mapping, bone names are matched after removing namespace prefixes and punctuation and ignoring ASCII case. Non-ASCII names retain their UTF-8 spelling. Ambiguous duplicate names are skipped. Use Map Bones by Name in the graph inspector to create editable source/target index mappings and translation-copy choices. Controller preview exposes parameter fields and highlights the active state; clip preview restores its original transforms when stopped. Custom mappings are also available in the controller data and C++/Lua APIs. Target bone lengths remain intact. Map Humanoid Bones uses standard humanoid joint aliases (Mixamo names and common Blender/Unity spellings, including fingers), rejects ambiguous matches and validates ancestry. Review the resulting editable map; arbitrary naming conventions require explicit mappings. C++/Lua also expose editable HumanoidAvatar definitions. Mapping does not automatically solve foot contacts. Add IK constraints where needed.

Formats and limits

The importer supports glTF node translation/rotation/scale tracks with STEP, LINEAR and CUBICSPLINE interpolation. Quaternion linear interpolation uses shortest-path slerp, and cubic rotation results are normalized. Dense and sparse accessors and EXT/KHR meshopt-compressed buffer views are supported. Morph-weight tracks use STEP, LINEAR or CUBICSPLINE interpolation and participate in layers and crossfades. Morph targets map by target name during retargeting, or by index when unnamed compatible counts match. External buffers stay inside the model cache directory.

Limits include 4,096 skeleton nodes, hierarchy depth 256, 1,024 clips, two million imported keys in total, 256 controller states, 1,024 transitions, 64 blend samples per state, 16 runtime layers and 32 scripted IK constraints per Animator. Events retain at most 256 snapshots per evaluation. Editor triangle picking and framing follow the current skin/morph pose, independently for each model instance. Conservative animated bounds keep deformed models visible. Explicit SceneQueryBounds and physics colliders remain separate; use animated bone colliders for gameplay hit detection. These are safety bounds, not performance targets. See the C++ and Lua animation guides for programming contracts.

Markers at time zero fire once when playback enters a state. Blend-tree markers come from the strongest weighted sample, with ties resolved by sample order, so blended footsteps do not duplicate. Times follow normalized blend phase. Non-looping states stop and report Completed, including blend states.
