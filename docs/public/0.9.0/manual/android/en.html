Building Android games

Android output runs the native engine and gameplay libraries. The editor runs on Windows, Linux or macOS. Android requires API 26 or later and an ARM64 or x86_64 device. Choose OpenGL ES 3 for compatible ES devices, Vulkan for Vulkan-capable devices, or Automatic to let the installed renderer SDK choose.

Install the tools

  1. Install a JDK, Android SDK platform 36 and Build Tools 36.0.0. Set JAVA_HOME to the JDK directory.
  2. Install NDK r29, revision 29.0.14206865. The gameplay compiler and prebuilt runtime must use the same NDK revision.
  3. Download the matching Android Core SDK from the release artifacts. Extract it and select its runtime.json directory in Build Settings.
  4. Open Build Settings, select Android, expand its profile, and check SDK directory and NDK directory. Discovery uses environment variables, standard SDK directories and adb. Missing tools leave empty fields. Choose directories manually when needed.
  5. Press Validate Android SDK / NDK. The compiler repeats validation before building.

Minimum SDK controls the oldest supported Android API. Target SDK selects Android compatibility behavior. Compile SDK selects the android.jar used to compile the Java launcher. Minimum must be at least 26 and no greater than Target, and Target must not exceed Compile. The matching platform and Build Tools must be installed.

Identity, signing and icons

Set a unique reverse-domain Application ID, such as com.company.game. Increase Version code for updates. Use a square 512 × 512 PNG application icon. An empty icon field uses the Bazzalt launcher icon.

Build Debug uses an automatically generated local debug keystore and enables Android debugging. Build Release requires your signing keystore and alias. Store and key passwords are read from the named environment variables. Keep the signing keystore backed up securely. Losing it prevents updates signed with that identity. Passwords are never written to BuildSettings.json or passed as literal release passwords on the process command line.

Build and Launch installs on exactly one connected, authorized adb device and deploys companion data. Device storage policies may require the distribution installer to supply companion content. These outputs target direct distribution. Google Play App Bundles and Play Asset Delivery require a separate publishing pipeline.

Content verification and key storage

APK signing protects the launcher, native modules and content inventory. On startup the launcher checks payload lengths and SHA-256 hashes before copying files to app-private no-backup storage. The native player verifies the signed inventory, player seal and encrypted packages before loading scenes.

Android Keystore creates a non-exportable AES-256-GCM wrapping key for the installation. Wrapped content keys live in private no-backup files. Hardware protection depends on the device. Offline distribution includes bootstrap material inside the signed native player, so Keystore does not make offline game content extraction-proof. Server-authorized key provisioning is a separate service.

Save games and lifecycle

The existing C++ and Lua SaveGame APIs keep their slot, backup, encryption and asynchronous behavior. Android stores encoded slots in private SharedPreferences with synchronous commit from the save worker. No content wrapping keys are stored in preferences. Saves are bounded by the existing slot limits. Uninstalling the app removes its preferences and Keystore entries.

SDL supplies keyboard, mouse and primary touch-as-mouse input. Window focus events report app foreground/background changes. Rendering pauses while inactive. Test lifecycle behavior and GPU support on actual target devices.

Output and configuration

Build Release and Build Debug write to bin/Release and bin/Debug. Working caches use .bazzalt/Cache/Build/Release and Debug. Architecture-specific output folders keep Android builds separate from desktop output. Archive output produces a ZIP of the complete APK set and companion data. Native engine libraries are shipped prebuilt. Debug changes gameplay script compilation and Android debuggability.
