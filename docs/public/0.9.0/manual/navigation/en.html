Navigation and pathfinding

Navigation finds routes over surfaces an agent can walk on. Recast turns level geometry into a polygon mesh, called a NavMesh. Detour searches that mesh and steers agents. A baked mesh records the size of the agent used to decide which passages, slopes and steps are traversable.

Build a walkable surface

  1. Create a floor from primitives or imported model entities. Keep moving characters out of the static bake.
  2. Create an entity and add NavMesh Surface. Set Center and Size to enclose the walkable level. Bounds follow that entity at bake time. The bake remains in world coordinates.
  3. Set Agent Radius and Agent Height for the largest agent that will use the surface. Max Slope limits incline. Max Climb limits step height. A smaller Cell Size improves detail and increases bake cost. Cell Height controls vertical detail.
  4. Choose geometry sources. The default uses enabled primitive and mesh geometry, filtered by Layer Mask. Use Physics Geometry bakes actual static Jolt collider triangles, including collider offsets and compound shapes. Trigger and moving bodies are excluded.
  5. Press Bake Navigation below the component fields. The editor blocks input while baking, writes Assets/Navigation/<surface-uuid>.bnavmesh, imports the result and assigns Data. Save the scene.
  6. Select the surface to see the baked polygon edges in the Scene viewport with Gizmos enabled.

Failed replacement bakes preserve the existing mesh. Bake again after changing static geometry, bounds or agent clearance. Auto Bake allows explicit runtime generation for surfaces with no Data asset. A Data asset loads automatically when the game starts updating navigation.

Create an agent

Add Navigation Agent to a character and choose its Surface. An empty Surface selects the first enabled baked surface in UUID order. Specify a Surface when a scene contains multiple surfaces. Radius and Height must fit the baked clearance. Position is at the agent’s feet. Base Offset adjusts the entity origin above or below its navigation position. Speed, Acceleration, Angular Speed and Stopping Distance control locomotion. Set a destination from gameplay code. The agent follows the ground and turns toward its velocity. Stopped pauses locomotion while retaining the destination. ResetPath cancels it. Warp relocates an agent onto the mesh.

Update Position and Update Rotation can be disabled for externally driven characters. Read velocity through GetAgentState to feed an animation controller. Navigation updates before the Jolt step on the fixed simulation clock. It does not move in edit mode or while the simulation clock is paused.

Jolt integration

A physics-driven navigation entity needs a kinematic Rigidbody. Static or dynamic Rigidbody motion conflicts with navigation ownership and produces an error. Kinematic targets use the Jolt movement API, and a capsule sweep prevents the navigation agent from walking through colliders that are absent from the baked mesh. Warp synchronizes the physics body and the navigation state. Place Navigation Obstacle on moving physical objects when routes must plan around them.

Dynamic obstacles and areas

Navigation Obstacle supports a Y-oriented box or upright cylinder. Its Center is local. World position, yaw and scale affect carving. With Carve enabled, TileCache updates affected tiles when an obstacle moves, is disabled, or is removed. Updates are processed incrementally. ObstacleUpdatesPending reports whether tile work remains. A single obstacle can touch at most eight layers. Larger obstacles must be split into smaller entities. Box pitch and roll do not rotate the carving volume. Cylinder radius uses the larger horizontal scale.

NavMesh Modifier applies to render geometry on the same entity. Ignore omits that source. Area 0 marks unwalkable triangles. Areas 1–16 map to bits 0–15 in Area Mask. SetAreaCost changes traversal preferences, with costs of at least 1. Physics geometry bakes currently use area 1. Obstacles are excluded from the static geometry bake.

Queries and results

CalculatePath returns Invalid, Partial or Complete, ordered corners, and route length. A partial route reaches the nearest reachable polygon and must be handled by gameplay code. SamplePosition finds a nearby navigable point inside the supplied search box. Navigation Raycast tests traversal along the NavMesh, using world XZ navigation connectivity. Use Scene Raycast for physical collision queries.

Budgets and authoring constraints

Baking is synchronous and bounded to two million triangles, 1,024 horizontal tiles and 4,096 layers. Voxel layers are limited to 255 cells across, including borders. A surface supports up to 4,096 agents and 4,096 obstacles, with 16 simultaneous area-mask filters. Path queries return at most 2,048 corridor polygons/corners. Crowd corridors use Detour’s local planning limits. Split large worlds into navigation surfaces with explicit handoff. Cross-surface and off-mesh traversal need game-level handling. Baking uses the engine’s Y-up world. Navigation calls and component edits belong on the engine thread. The separate AI library is shipped with game runtimes.
