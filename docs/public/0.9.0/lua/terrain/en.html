Terrain Lua API

Terrain types are available in the global Bazzalt namespace. Methods use colons; stateless TerrainGeometry functions use dots. Entity component operations copy values, so write the changed Terrain back with SetComponent.

Edit a terrain value

local B = Bazzalt
local terrain = entity:GetComponent("Terrain")
local brush = B.TerrainBrush.new()
brush.Radius = 2
brush.Strength = 1
terrain:ApplyBrush(B.TerrainTool.Raise, B.Vec2.new(0, 0), brush, 0.5)
entity:SetComponent("Terrain", terrain)
local hit = B.TerrainGeometry.Raycast(terrain,
    B.Vec3.new(0, 20, 0), B.Vec3.new(0, -1, 0))
if hit then print(hit.Position.Y) end

Surface API

Terrain exposes the same configuration records and methods as C++: IsValid, MarkDirty, Resize, AddLayer, RemoveLayer, GetHeight, GetNormal, GetSlope, IsHole, ApplyBrush, ImportHeightmap, ImportSplatmap, ApplySpline, MatchEdge, ApplyBoolean, GenerateVegetation and PaintVegetation. Layer, chunk, spline and prototype identifiers are zero-based, even though ordinary Lua tables use one-based array positions.

Construct Terrain, TerrainLayer, TerrainBrush, TerrainVegetation, TerrainInstance and TerrainSpline with .new(). GetComponent, AddComponent, SetComponent, RemoveComponent and component enable/disable operations accept Terrain. SetComponent validates the value and advances its revision. Invalid input becomes a Lua script error.

Geometry and imports

TerrainGeometry.BuildChunk returns a TerrainMesh whose Vertices expose Position, Normal, UV and Color, with an Indices collection. TerrainGeometry.Raycast returns a TerrainHit or nil. Imported numeric sample tables are row-major with explicit width and height. Height import optionally multiplies samples by a scale. Image decoding remains an asset/import concern; gameplay can supply its own finite sample values.

Enums

TerrainBlend contains Add, Replace, Maximum and Minimum. TerrainTool contains Raise, Lower, Smooth, Flatten, Paint, ErasePaint, Hole and FillHole. TerrainBoolean contains Union, Intersection and Subtract. The C++ guide and editor manual describe coordinate conventions and budgets; generated Lua reference pages list every exposed binding.

Caves and overhangs

Add a record under Terrain → Caves and overhangs. Carve subtracts an ellipsoid from the ground. Add solid joins an ellipsoid to the ground and can form an overhang. Center and Radius use terrain-local metres. Volume height range must enclose the affected ground and the complete ellipsoid. Vertical samples controls extraction detail. Affected chunks keep full detail. Ray picking and non-convex Mesh Collider use the extracted surface.

Spline surfaces and neighbours

Enable Generate surface on a spline to create a ribbon for a road or water surface. Set Material to a project material instance, Texture scale to metres per UV repeat, and Surface offset to separate the ribbon from the ground. Surface collision controls whether the ribbon joins the terrain collider. The material determines the appearance and animation of water.

In terrain tools, choose a neighbouring terrain as the source, select an edge and use Match edge to neighbour. The operation resamples the source border into the destination and raises destination resolution when necessary. Both terrains must have adjacent upright edges. The selected layer must remain editable through subsequent layer composition. The edit supports undo and scene saving.

Build a cave from Lua

local B = Bazzalt
local terrain = self.Entity:GetComponent('Terrain')
local cave = B.TerrainVolume.new()
cave.Center = B.Vec3.new(0, -1, 0)
cave.Radius = B.Vec3.new(2, 2, 2)
cave.Operation = B.TerrainVolumeOperation.Subtract
terrain.Volumes:add(cave)
terrain:MarkDirty()
self.Entity:SetComponent('Terrain', terrain)

GetHeight samples the underlying heightfield. TerrainGeometry.Raycast returns the extracted surface hit, including cave walls and generated spline surfaces.

Blend custom terrain materials

Assign a material instance to each painted terrain layer. Surface shaders compiled from Bshader, shader graphs or material source receive a terrain variant automatically. The renderer interpolates splat coverage across triangles and blends layers with per-pixel stochastic sampling. Each material retains its parameters, textures, animation and shading model. The Scene viewport enables temporal anti-aliasing while layered materials are visible. Use TAA or TAA + FXAA on game cameras to resolve the sampled transition. Coverage grain is visible with anti-aliasing disabled.

Material edits update shared material instances at runtime. Splat painting updates the layer distribution. The game compiler packages terrain variants alongside ordinary shader packages. Binary-only shader packages require a matching terrain coverage variant.
