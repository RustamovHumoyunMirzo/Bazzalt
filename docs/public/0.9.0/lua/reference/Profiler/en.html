Profiler

Use the global Bazzalt.Profiler table. Captures measure CPU work across the process, including engine scopes and native jobs. They are not GPU timings.

Methods

BeginCapture() starts with 100000 samples; BeginCapture(capacity) accepts 1–10000000. Starting again clears the previous capture. EndCapture() stops recording and retains completed samples. IsCapturing() returns a boolean. GetDroppedSampleCount() returns how many completed scopes exceeded capacity. GetSamples() returns an array of tables containing Name, StartMicroseconds, DurationMicroseconds and Thread (a string preserving identifier precision). It copies data, so do not call it every frame. Active scopes at stop/replacement are discarded. Nested durations overlap.

Example

Bazzalt.Profiler.BeginCapture(20000)
-- Later, after collecting representative frames:
Bazzalt.Profiler.EndCapture()
for _, sample in ipairs(Bazzalt.Profiler.GetSamples()) do
    print(sample.Name, sample.DurationMicroseconds)
end

ExportTrace(path) saves a JSON snapshot to a UTF-8 filesystem path and raises an error on failure; stop capture first. The caller owns the destination path. Native RAII timing scopes are available through C++. Lua callbacks remain on their owning thread; this API does not schedule Lua on workers.

Lua members and signatures

Use Bazzalt.Profiler. Each member below is actually registered in Lua. The adapter declarations are C++ binding notation, not Lua example code. sol::property exposes a field, sol::overload lists alternatives, sol::optional accepts an omitted/nil argument, and std::make_tuple returns multiple Lua values. sol::as_table returns a Lua table. Instance methods use value:Method(...); service/static calls use Bazzalt.Profiler.Method(...) unless a colon overload is explicitly registered. An engine exception becomes a Lua script error. See the examples and behavior notes above for usage.
