Lua hot reload state

Save a gameplay .lua asset during editor Play. The editor imports bytecode and constructs a fresh sandboxed VM. Candidate declaration errors or incompatible state leave the old VM active.

Store state on self

local Walker = COMPONENT("Walker")
Walker.Speed = PROPERTY("float", 2.0)
Walker.Progress = { distance = 0 }
function Walker:OnUpdate(dt)
    self.Progress.distance = self.Progress.distance + self.Speed * dt
end
function Walker:OnReload()
    -- self.Progress.distance and self.Speed retain current values.
    -- Reconnect event handlers here; OnCreate is not replayed.
end
return Walker

Reload copies booleans, numbers, strings, vectors, quaternions, UUIDs, entity/entity-reference handles and supported asset handles. Nested tables use string or number keys. New defaults and new functions come from the new source. The Entity field is rebound by the runtime. Existing data must keep its type. Tables are bounded to 16 levels and 16,384 visited fields per instance; strings to 1 MiB. Cycles reject the candidate. Shared table identity is not retained.

Custom state and migration

function Walker:OnSaveReloadState()
    return { version = 1, distance = self.Progress.distance }
end
function Walker:OnRestoreReloadState(state)
    assert(state.version == 1)
    self.Progress.distance = state.distance
end

These optional callbacks select data to transfer and migrate it onto a candidate. OnSaveReloadState must return a supported data table. With no restore hook, its fields merge into the new instance. With OnRestoreReloadState, the transferred table is passed to that method instead of automatic merging, so your method owns validation and migration. Throwing rejects the candidate. Use this to omit transient handles and recreate them in OnReload. Both callbacks must avoid external side effects and have the standard Lua instruction budget.

Functions and resources

Functions come from the new source, never the old VM. Keep changing gameplay state on self rather than in local closure variables or VM globals. Closures, coroutines, custom userdata and registered systems are not migrated. Recreate subscriptions, systems and derived caches in OnReload. OnReload errors are reported and disable that Lua behavior. Top-level code should only declare data and methods; scene changes there run during staging and cannot be rolled back.
