Baked lighting in Lua

Saved probe lighting is available in Lua through Bazzalt.Lighting and the LightProbe component. Gameplay uses the baked scene directly. Baking is normally an editor authoring operation.

Read scene lighting

local scene = Bazzalt.SceneManager.GetActiveScene()
local irradiance = Bazzalt.Lighting.Sample(scene,
    Bazzalt.Vec3.new(0, 1, 0), Bazzalt.Vec3.new(0, 1, 0))

Values are linear diffuse irradiance. No influence returns a zero vector. Pass world-space position and a nonzero normal. The same four-probe interpolation is used by lit materials.

Create and bake

local probes = Bazzalt.Lighting.CreateProbeGrid(scene,
    Bazzalt.Vec3.new(-5, 1, -5), Bazzalt.Vec3.new(5, 5, 5), 2, 2, 2, 15)
local settings = Bazzalt.LightBakeSettings.new()
settings.Samples = 512
settings.Bounces = 2
request = Bazzalt.Lighting.BeginBake(scene, settings)
-- Poll in a later tool update; do not block the engine thread.
if request:GetStatus() == Bazzalt.LightBakeStatus.Complete then
    if not request:Apply(scene) then
        local reason = request:GetError()
    end
end

Keep the request until it finishes and call request:Cancel() when abandoning work. Instance methods use a colon; Lighting service calls use a dot. Apply must run on the thread that started the request, validates the unchanged scene, and does not save files. Lighting.Clear(scene) removes coefficients without removing probe entities. Light.Mode accepts Bazzalt.LightMode.Realtime, Baked or Mixed. Mesh.ContributeGI and PrimitiveObject.ContributeGI opt static geometry into the snapshot. Invalid settings and scene geometry raise a script error; asynchronous failure is available through GetStatus and GetError. See the editor lighting guide for quality settings and material limitations.

UV lightmaps

Add a Lightmap component to static Primitive Object or Mesh entities, or select them and choose Add lightmaps to selection in Window > Lighting. Resolution is a power of two from 16 to 4096. Padding is the gutter around each triangle chart. Increase resolution if the charts do not fit. Bake lighting writes a non-overlapping triangle-chart irradiance atlas. Runtime reconstructs chart coordinates from the baked world triangles, preserving the model’s original texture UV sets and material textures. This is non-directional diffuse lighting. A matching lightmap replaces probe diffuse at that surface; it is not added twice.

Moving a lightmapped entity invalidates its atlas until it returns to its baked transform or is rebaked. Animated/deformed geometry is unsuitable. Meshes need not have a pre-authored UV2 channel. Each triangle receives an equal-sized chart, so dense models need higher resolution or separate receivers. Disable the component to fall back to probes.

Reflection captures

Create a Reflection Probe in Window > Lighting, or add the component to an entity. Position it in empty space. Resolution (4–256) controls each cubemap face. Radius limits influence; Intensity scales HDR radiance; Blend Distance feathers the edge into the scene environment. Box Projection uses Box Size as world-space half extents for local parallax correction. Bake lighting captures contributing static triangles, analytic lights and the cached HDR environment, then generates GGX-filtered roughness mip levels. Realtime lights appear in the capture as a frozen snapshot; rebake if they change.

The four strongest overlapping captures blend per fragment. Moving a capture disables its stale result until rebaked or restored. Disabling it removes its contribution. Native material BRDF, roughness, AO, clearcoat and environment fallback remain in use. A scene without an environment uses a black fallback, not an extra light.

Material support

Built-in lit materials, original imported glTF PBR materials and cooked source surface shaders receive baked lighting. Imported textures and UV mappings are retained. Unlit materials and GUI overlays remain unlit. Source material compilation adds private engine parameters without adding them to the public material inspector. Existing precompiled opaque material packages must be rebuilt from source to participate; their bytecode cannot be safely rewritten.

Budgets and data lifetime

There is no 64-probe rendering cap. Up to 65,536 diffuse probes are supported as an explicit resource budget. A spatial lookup stores all overlapping influences; excessive overlap uses exact global lookup rather than silently dropping probes. The GPU atlas is bounded by hardware support and 4096×4096 RGBA32F texels. An oversized atlas reports an error and disables baked sampling. Split very large worlds into streamed cells.

MaxBakeTexels limits lightmap and reflection storage together (default 1,048,576, maximum 8,388,608). Lightmap Samples and Reflection Samples control integration quality independently of diffuse-probe samples. Baked vectors are stored losslessly as little-endian float32 data in YAML scene fields. Scene size is limited to 256 MiB; saves publish atomically, retaining the previous file on failure. Settings and results travel with scenes through cooking and streaming.

Lua controls

entity:AddComponent("Lightmap")
local map = entity:GetComponent("Lightmap")
map.Resolution = 128
entity:SetComponent("Lightmap", map)
probeEntity:AddComponent("ReflectionProbe")
local probe = probeEntity:GetComponent("ReflectionProbe")
probe.Resolution = 32
probeEntity:SetComponent("ReflectionProbe", probe)
settings.LightmapSamples = 16
settings.ReflectionSamples = 64
local reflection = Bazzalt.Lighting.SampleReflection(scene, position, direction, 0.5)

Component Get returns a copy; Set validates and commits it. Enabled uses the same Entity component methods as other components. The public reference lists every field, including the low-level baked payload. Editing payloads directly requires Bazzalt.Lighting.Invalidate(scene). Prefer the bake API for normal authoring.
