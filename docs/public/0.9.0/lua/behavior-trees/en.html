AI behavior trees in Lua

Lua uses the same behavior runtime, .bbtree assets, Jolt actions and per-agent blackboards as C++. Service functions use dots; instance methods use colons. Read the authoring guide and complete XML/block catalog for node attributes and execution semantics.

Agent components and shared memory

local B = Bazzalt
local Guard = COMPONENT("Guard")
Guard.Tree = PROPERTY("UUID", B.UUID.new())
function Guard:OnCreate()
  if not self.Entity:HasComponent("BehaviorTreeAgent") then
    self.Entity:AddComponent("BehaviorTreeAgent")
  end
  local agent = self.Entity:GetComponent("BehaviorTreeAgent")
  agent.Tree = self.Tree
  agent.Loop = true
  self.Entity:SetComponent("BehaviorTreeAgent", agent)
  local memory = B.AI.GetBlackboard(self.Entity)
  memory:Set("target", B.Vec3.new(10, 1, 0))
  memory:Set("alert", 0.8)
  B.AI.SetHandlers(self.Entity,
    function(name, entity, board, dt, cancelled)
      if cancelled then return end -- release resources here
      if name == "Watch" then
        board:Set("watching", true)
        return B.BehaviorStatus.Running
      end
      return B.BehaviorStatus.Failure
    end,
    function(name, entity, board, dt)
      return name == "Alert" and board:Number("alert") > 0.5
    end)
end
return Guard

GetComponent returns a copy: commit Tree/Loop changes with SetComponent. Enabled is inherited from Component and can also be changed with SetComponentEnabled. HasComponent, AddComponent, RemoveComponent, IsComponentEnabled and GetInheritedComponent use the same component operations as other engine components. The system ticks the agent automatically; do not also manually tick its tree.

AI service signatures

  • B.AI.GetBlackboard(entity) → Blackboard: a checked live view of agent memory. Retaining the view does not keep a removed entity/scene alive; later access raises an error.
  • B.AI.SetHandlers(entity, actionOrNil, conditionOrNil): cancel old work and install per-agent dispatch. Action receives (name, entity, memory, dt, cancelled); condition receives (name, entity, memory, dt).
  • B.AI.ClearHandlers(entity): cancel and disconnect the agent's per-agent dispatch.
  • B.AI.Reset(entity): cancel running work and restart traversal, preserving memory.

Actions must return BehaviorStatus.Success, Failure or Running when ticked; cancellation may return nil. Conditions must return a boolean. Missing handlers fail. Handlers run on the engine thread with a Lua instruction budget; errors are reported through the AI console and stop that agent until Reset, handler replacement or an asset reload. Do not destroy entities or alter scene structure inside dispatch. Scripts that stop, fail initialization or hot-reload have their handlers disconnected before their Lua VM closes. Registering new handlers from a VM-closing cancellation callback is rejected. Scene/entity cleanup can pass an invalid entity during cancellation; check validity before component access.

Typed blackboards

local memory = Bazzalt.Blackboard.new()
memory:Set("ready", true)
memory:Set("score", 2.5)
memory:Set("label", "Guard")
memory:Set("target", Bazzalt.Vec3.new(1, 2, 3))
assert(memory:Contains("score"))
assert(memory:Get("ready") == true)
assert(memory:Number("score", 0) == 2.5)
memory:Erase("label")
assert(memory:Get("label") == nil)

Set accepts only boolean, finite number, string or finite Vec3. Tables, functions and nil are rejected; use Erase to remove a key. Get returns the stored type or nil. Number reads only numeric values and otherwise returns fallback (default zero). A constructed blackboard owns its data; an agent view resolves the live agent on each access. Initialize applies defaults only to missing keys.

Standalone execution and reset

local B = Bazzalt
local tree = B.BehaviorTree.FromSource([[
<BehaviorTree version="1"><Tree>
  <Sequence><Wait seconds="0.5"/><Succeed/></Sequence>
</Tree></BehaviorTree>]])
local memory = B.Blackboard.new()
tree:Initialize(memory)
local status = tree:Tick(self.Entity, memory, 0.25, nil, nil)
assert(status == B.BehaviorStatus.Running)
tree:Reset(self.Entity, memory, nil)

B.BehaviorTree.Load(assetUUID) loads a ready imported/cooked asset. FromSource(xml) validates source without filesystem access. Tick(self, memory, dt, actionOrNil, conditionOrNil) returns BehaviorStatus; provide callbacks on every tick. Reset(self, memory, actionOrNil) cancels running custom actions using the supplied callback. A tree owns its execution state; create separate trees for independent NPCs. Keep the same memory/handlers for an active execution. Call Reset before dropping a tree whose actions own resources. Negative/non-finite dt, malformed XML and unavailable assets raise Lua errors and can be handled with pcall.

Behavior parsing, tree execution, utility selection and per-agent runtime state live in the same bazzalt_ai.dll module as navigation (libbazzalt_ai.so on Linux/Android, libbazzalt_ai.dylib on macOS). The core engine keeps the public API and Lua bindings and forwards through a versioned private module table. Ship the matching AI module beside the core runtime; existing runtime staging includes it.
