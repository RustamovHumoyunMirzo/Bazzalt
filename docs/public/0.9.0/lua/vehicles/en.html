Vehicles in Lua

Lua uses the same vehicle components and physics simulation as C++. Entity component getters return copies; commit edits with SetComponent. UUID fields refer to wheel entities, not asset files.

Create and control a car

local B = Bazzalt
local scene = self.Entity:GetScene() -- Inside an entity script lifecycle callback.
local car = scene:CreateEntity("Car")
local pose = car:GetWorldTransform()
pose.Position = B.Vec3.new(0, 1.2, 0)
car:SetWorldTransform(pose)
local collider = car:AddComponent("ShapeCollider")
collider.Size = B.Vec3.new(1.6, .4, 3)
car:SetComponent("ShapeCollider", collider)
local body = car:AddComponent("Rigidbody")
body.Mass = 1200
car:SetComponent("Rigidbody", body)
car:AddComponent("Vehicle")
car:AddComponent("VehicleEngine")
car:AddComponent("VehicleTransmission")
local wheels = {}
for i = 1, 4 do
    local wheel = scene:CreateEntity("Wheel " .. i)
    wheel:SetParent(car)
    local settings = wheel:AddComponent("VehicleWheel")
    settings.Position = B.Vec3.new(i % 2 == 0 and .9 or -.9, 0, i <= 2 and 1.2 or -1.2)
    wheel:SetComponent("VehicleWheel", settings)
    wheel:AddComponent("WheelSuspension")
    wheel:AddComponent("WheelTire")
    wheel:AddComponent("WheelBrake")
    if i <= 2 then wheel:AddComponent("WheelSteering") end
    wheels[i] = wheel
end
local axle = car:AddComponent("VehicleDifferential")
axle.LeftWheel = wheels[3]:GetUUID()
axle.RightWheel = wheels[4]:GetUUID()
car:SetComponent("VehicleDifferential", axle)
-- Once running, send input before physics and read telemetry afterwards:
local physics = scene:GetPhysics()
physics:Synchronize()
physics:SetVehicleInput(car, 1, 0, 0, 0)
local state = physics:GetVehicleState(car)
if state then print(state.Speed, state.EngineRPM, state.Gear) end
local wheel = physics:GetVehicleWheelState(wheels[1])
if wheel and wheel.Grounded then print(wheel.SuspensionForce) end

Input ranges and manual gearbox rules match C++: normalized throttle/steering [−1, 1], brake/handbrake/clutch [0, 1]; manual throttle is nonnegative. SetVehicleGear returns false in automatic mode or for an invalid gear. GetVehicleState and GetVehicleWheelState return nil outside active simulation. Invalid numeric inputs raise a Lua error through the script error reporting system.

Components and ownership

ComponentAttach toPurpose
VehicleChassisLocal up/forward axes, wheel contact test, collision layer and optional pitch/roll limit. Requires a dynamic Rigidbody and chassis collider.
VehicleWheelOne child per wheelSuspension attachment Position in chassis-local metres, radius, width, inertia, damping, camber/toe axes, and visual animation.
WheelSuspensionWheelRequired for an active wheel. Direction, minimum/maximum travel, preload, spring frequency in Hz, damping ratio and optional chassis force point.
WheelTireWheelLongitudinal slip-ratio and lateral slip-angle grip curves. Peak and tail values distinguish adhesion from sliding. Omit for Jolt's default tire curve.
WheelSteeringSteered wheelSteering axis and maximum angle in degrees. Omit for a non-steering wheel.
WheelBrakeBraked wheelService-brake and handbrake torque in Nm. Omit for a freely rolling wheel.
VehicleEngineChassisEngine torque, operating RPM, inertia, damping and a normalized three-point torque curve. Omit for an unpowered trailer.
VehicleTransmissionChassisAutomatic/manual shifting, one to ten forward ratios, reverse, clutch strength/timing and shift thresholds.
VehicleDifferentialChassis or axle childLeft/right wheel entity references, final-drive ratio, torque split, limited-slip ratio and drivetrain torque share. Add one per driven axle; shares are normalized.
VehicleAntiRollBarChassis or axle childConnect two wheels and resist differential suspension travel, with stiffness in N/m.
VehicleAerodynamicsChassisAir density, frontal area, drag, downforce and a chassis-local center of pressure. Forces depend on speed squared.

Coordinates and visual wheels

The default vehicle uses +Y up, +Z forward and +X along the wheel axle. Distances are metres, mass is kilograms, torque is Nm, and authored angles are degrees. Rigidbody supplies mass, center of mass, collision detection and body interpolation; chassis collision geometry is built from its ordinary colliders.

Wheel entities must be descendants of their chassis and have no separate Rigidbody or collider. Put a wheel mesh on the wheel entity or under it. Colliders in that visual subtree are excluded from the chassis compound; a nested independent Rigidbody remains a separate body. Rotate a mesh child to match its imported model axis. VehicleWheel.Position is an explicit chassis-local suspension attachment; it is independent of the wheel entity's animated Transform. The simulation positions, steers and spins the wheel entity without changing that attachment. Disable Animate to drive visuals yourself from wheel telemetry. Stop in the editor restores the authored scene.

Positive uniform chassis world scale is supported. Nonuniform or mirrored chassis scale is rejected. A vehicle has 2–32 active wheels. A wheel needs both enabled VehicleWheel and WheelSuspension components. Disabling Vehicle stops its wheel solver; the Rigidbody remains an ordinary body. Disabling an optional component removes its contribution. Without both an enabled engine and transmission the powertrain stays disconnected in neutral, while steering, brakes and suspension continue working. An absent/disabled engine reports zero RPM. Invalid or cross-vehicle wheel references are reported instead of silently connecting another car. Drive torque reaches wheels only through an enabled differential; without one the vehicle rolls passively. Disabled wheels disconnect from the differential, and anti-roll bars suspend their action until both linked wheels are active. Each wheel can belong to only one differential.

Arcade and physical tuning

For an arcade car, start with ray contacts, a lower Rigidbody center of mass, a limited Max Pitch Roll Angle, short suspension travel, strong grip and fast automatic shifts. For a more physical car, allow the full 180-degree pitch/roll range, use sphere or cylinder contacts, realistic chassis mass and center of mass, measured wheel inertia, suspension travel, damping, torque/RPM and gearbox ratios. Use different steering/brake components on front and rear wheels; split torque across two axle differentials for all-wheel drive.

WheelTire uses piecewise-linear grip curves, not a thermodynamic tire model. Tire temperature, tire wear, fluid brakes, body damage and engine combustion are not simulated. Contact forces do affect dynamic ground objects. Use normal joints and rigidbodies to compose articulated trailers. Core simulation is independent of visual polygon count.

Editing and runtime state

Select a chassis or wheel with Scene Gizmos enabled to see wheel circles and suspension travel. Component fields are saved in scene YAML and are available in C++ and Lua. Structural/configuration edits rebuild the vehicle constraint safely while retaining the chassis body's motion and current driver input; engine/wheel rotational state is reinitialized. Use SetVehicleInput and SetVehicleGear for driving, rather than rebuilding component settings every frame.

GetVehicleState returns signed forward speed in m/s, RPM, gear, clutch friction and grounded wheel count. GetVehicleWheelState returns current wheel position, ground contact, suspension length/force, angular velocity in rad/s, steering angle in degrees and tire slip. ContactPoint and ContactNormal are meaningful only when Grounded is true. Telemetry is absent outside a running simulation or for disabled/unregistered components. Read it after a physics step. Wheel contacts are reported through telemetry, rather than ordinary chassis collision callbacks; scene OnBeforePhysicsStep/OnAfterPhysicsStep events remain available for control and telemetry.
