GUI stylesheets

Import a .css asset and assign it to GuiElement.Stylesheet in the inspector or through C++/Lua. Add GuiElement to author an ID, whitespace-separated Classes and Tags, or Attributes such as [state="active"]. Rules apply to that Frame hierarchy; a nested Frame starts its own scope. GuiElement.Stylesheet scopes additional rules to its subtree. Computed styles never replace your authored component values.

Engine terms, familiar syntax

A stylesheet describes GUI entities, not web pages. A type selector names a widget such as Button, an ID identifies one widget, a class identifies a reusable group and an attribute describes explicit widget metadata. Hierarchy relations mean GUI parent/child or sibling relations within a Frame. States such as hover and focus come from engine input. There is no DOM, JavaScript, browser history or network loading.

/* Assign this asset to the Frame entity’s GuiElement Stylesheet field. */

@layer defaults, theme;

@layer defaults {

    Button { color: white; gap: 8px; }

}

:root { --accent: #4a90e2; --spacing: 12px; }

.toolbar > Button.primary:hover {

    color: var(--accent, rgb(74 144 226));

    margin: calc(var(--spacing) * 2);

}

@viewport (min-width: 900px) and (orientation: landscape) {

    .toolbar { gap: clamp(8px, 2vw, 24px); }

}

Supported properties are color, background-color, background-image, border-color, border-width, opacity, font-family, font-size, font-kerning, letter-spacing, line-height, white-space, display, visibility, pointer-events, flex-direction, align-items, justify-content, overflow, z-index, width/height and their min/max variants, left/top, gap, flex-grow/shrink, padding and margin (including sides). Unknown properties produce diagnostics. Percent lengths use parent content bounds; em uses font size and rem uses the Frame root size. See layout and inheritance.

Widget types are Frame, Button, TextInput, Image, Text, Rectangle and Container. Set GuiElement.ID explicitly, or use the entity name as its default ID. Tags are available through the tags attribute. Attributes use presence or exact-value syntax, for example [disabled] [state="active"]. Hover, active and focus update from engine input. Disabled Frames and controls expose :disabled.

Comma-separated selectors share a declaration block. Widget type and pseudo names are ASCII-insensitive; IDs, classes, attributes and custom-property names are case-sensitive by default. Unsupported/malformed selectors produce diagnostics rather than silently becoming a broader match. Pseudo-elements, namespaces, :has and nested style-rule syntax are not implemented.

Cascading and variables

The winning declaration is chosen by !important, layer precedence, specificity, then declaration order. ID specificity outranks classes/attributes/pseudo-classes, which outrank widget types. Unlayered normal rules beat layered normal rules; important rules reverse layer order. Duplicate declarations preserve their order. Layer names may have dotted paths; full browser nested-layer/revert-layer behavior is not claimed.

:root { --accent: #acf; --padding: 12px; }

Button { color: var(--accent); padding: var(--missing, var(--padding)); }

#play { color: rgb(255 255 255 / 80%) !important; }

Custom properties inherit through the GUI snapshot hierarchy. Parent variables are computed before child redefinitions. Variables are substituted as tokens, not executable text. Nested fallbacks work. Missing variables without a usable fallback, cycles (including fallback dependencies), excessive depth or expansion size invalidate the declaration and produce a diagnostic. A losing lower-priority declaration is not substituted as a fallback for an invalid winning value.

Ordinary inherit, initial and unset are resolved into per-frame computed component copies. Local authored values remain intact. Explicit component Inherit flags still work; a CSS declaration overriding that property takes precedence in the computed copy.

Values and conversion

Strings and booleansEscaped UTF-8 strings/identifiers; true/false literals. Strings never execute commands.

Balanced unknown functions and units remain available in parsed data, but typed conversion can reject them. This is not full browser CSS: every named color, CSS Color 4/5 color space and web-only unit is not implemented. Parsed colors are encoded sRGB values; renderer conversion is a separate responsibility.

At-rules

@viewport and @media conditionally contain rules. Supported features are min/max/exact width, height and aspect ratio, orientation, prefers-color-scheme and prefers-reduced-motion. Width/height also accept range syntax: (width >= 600px) and (400px < width <= 1200px). Conditions use the current Frame destination size in logical GUI pixels and are reevaluated after resizing. Queries support screen/all, and/or/not, comma alternatives and parentheses. @viewport is an engine conditional, not a way to create or resize the native game window.

@layer statements and blocks define cascade order. Other at-rules, including @import, @font-face and @supports, are retained with warnings and not executed. Their bodies do not leak into the normal cascade. In particular, @import never downloads or reads another file, fonts are assigned directly with font-family: asset("UUID") or the Font picker instead of @font-face.

Rounded borders

border-width accepts one, two, three or four lengths in CSS order: top, right, bottom, left. Use border-top-width, border-right-width, border-bottom-width and border-left-width for individual sides. border-color uses the same shorthand order and has corresponding side fields. border: 2px solid #aaccee is supported; border-style accepts solid or none. Shorthands and longhands participate in specificity, !important and source order, including values supplied through variables.

.card {

    border-width: 1px 2px 3px 4px;

    border-color: #555 #777 #999 #bbb;

    border-radius: 12px 18px 24px 30px / 8px 12px 16px 20px;

    border-top-left-radius: 20px 10px;

}

Corner shorthand order is top-left, top-right, bottom-right, bottom-left. A slash separates horizontal and vertical ellipse radii. Percentages use the corresponding box dimension; overlapping corners are reduced together to fit. The other longhands are border-top-right-radius, border-bottom-right-radius and border-bottom-left-radius. Borders overlay the box rather than adding to its measured size. overflow:hidden/clip creates a rounded clipping group for descendants.

Gradient backgrounds

.banner { background-image: linear-gradient(to right, #173453, #6d91bf 70%, white); }

.radial { background-image: radial-gradient(circle at 30% 40%, white, transparent); }

.wheel { background-image: conic-gradient(from 45deg at center, red 0deg, lime 120deg, blue 240deg, red 360deg); }

.stripes { background-image: repeating-linear-gradient(45deg, #333 0px 8px, #555 8px 16px); }

linear-gradient, radial-gradient and conic-gradient have repeating- equivalents. Linear directions accept angles or to left/right/top/bottom combinations. Radial backgrounds support circle/ellipse with side/corner extents, explicit radii and an at position. Conic backgrounds accept from angle and at position. Stops accept supported CSS colors and one or two positions; omitted positions are distributed between their neighbors. There are at most eight stops per gradient and four gradient layers. The first listed gradient is painted on top. background is a single color, asset reference or gradient shorthand; background-image is preferred for layered gradients. Arbitrary web image-loading URLs and interpolation-color-space syntax are not supported.

Element and backdrop filters

.soft { filter: blur(15px) contrast(110%); }

.glass {

    background-color: rgb(255 255 255 / 15%);

    border-radius: 16px;

    backdrop-filter: blur(10px) saturate(140%);

}

.shadow { filter: drop-shadow(3px 5px 8px rgb(0 0 0 / 50%)); }

Both properties support the same ordered operations: blur, brightness, contrast, grayscale, invert, opacity, saturate, sepia, hue-rotate and drop-shadow. blur accepts a nonnegative logical-pixel radius through 128px. Color filters accept nonnegative numbers or percentages through 16 (1600%); grayscale/invert/opacity/sepia clamp to 1 (100%); hue-rotate accepts an angle. drop-shadow accepts horizontal offset, vertical offset, optional blur radius and a color. Each chain is limited to eight operations. none removes the chain. Unsupported functions or invalid arguments produce diagnostics.

filter renders an element and its descendants as a group before applying the chain. backdrop-filter samples already painted content behind the element, excludes its foreground and clips the filtered result to its rounded box. Viewport and CameraBound destinations include the current camera/background image. Spatial Frames sample earlier GUI content on their own plane; they do not sample arbitrary world geometry behind that plane. A filter establishes a grouping boundary, so descendant z-index stays within that group. New paint properties accept inherit, initial and unset; explicit inheritance copies computed values while local component data remains intact. A plain opacity declaration still affects the entity's own layers; filter:opacity(...) applies to the composited group.

Effects use private GPU render targets and separable Gaussian passes, with no gameplay renderer handles or CPU framebuffer readbacks. Targets are allocated before rendering and do not sample themselves. The main accumulation and camera input stay at full destination resolution. Per destination, effect scratch resolution is reduced when needed to stay within a 16-million-pixel allocation budget and a 4096-pixel maximum dimension. Full-size effect destinations are limited to 16384 pixels per edge and 32 million pixels. Other limits are 128 scratch targets, 256 passes and 16 nested groups; exceeding them reports a diagnostic and falls back to unfiltered drawing.

Additional placement controls

position:absolute opts a child out of row/column flow; position:relative keeps it in flow. right and bottom place the box relative to the parent content area when left/top are absent. aspect-ratio:16/9 derives the missing dimension when exactly one of width or height is specified. Existing min/max constraints still apply. These values are computed without modifying authored transforms.

Errors and safety

Diagnostics carry severity, UTF-8 byte offset and one-based line/byte column. The parser recovers enough to report later errors, but a syntax-invalid sheet is not authoritative for cascading. UTF-8 and NUL validation, finite-number checks and byte/token/rule/declaration/recursion/expansion/work limits prevent unbounded input processing. Unknown conditions fail closed. All functions operate on owned data and caller-provided hierarchy snapshots; no editor loop, renderer or OS access is exposed.

Assets, fonts and live editing

Create a stylesheet with Asset Browser > Create > Stylesheet. Edit it with Open or Open With. Assign it using a Stylesheet picker, then give GUI entities reusable Classes. Font and image references use asset("UUID") or url("asset://UUID"). Obtain the UUID from the asset metadata or AssetManager; it is a stable project identity, not a filesystem path.

.title { font-family: asset("FONT-UUID"); font-size: 24px; }

.card { background-image: url("asset://IMAGE-UUID"); padding: 12px; }

Button:hover { background-color: #467cb8; }

.hidden { display: none; }

Used stylesheet/font files are watched in the editor. Saving them triggers targeted import and updates computed values and font atlases. Imported stylesheet dependency manifests retain referenced fonts/images in cooked games. Query GUI::GetStyleDiagnostics(entity) for application diagnostics; changed diagnostics also appear in the editor Console. Syntax-invalid assets are marked failed in the Asset Browser.

Fonts use the same rendering path for Viewport, CameraBound and Spatial Frames. See font assets and measurement. CSS opacity currently affects each entity's own layers, not an offscreen composited group. This dialect does not implement CSS Grid, flex wrapping, auto content sizing, browser DOM or arbitrary web stylesheets. Resource and traversal limits may use the built-in fallback glyph instead of allocating without bounds.

Typed stylesheet inputs

A stylesheet can declare editable inputs. Select the stylesheet in a GuiElement component: its declarations appear underneath as inspector fields. Values belong to that GuiElement, are saved with its scene and support editor undo/redo. Sharing the stylesheet does not share instance overrides.

@require(accent, #4da3ff, color, label("Accent color"));
@require(spacing, 12px, length, min(0), max(64));
@require(icon, none, texture);
@require(face, none, font);
@require(caption, "Continue", string);
@require(enabled, true, bool);
@require(alignment, center, enum, options(start, center, end));
@require(insets, 8px 12px 8px 12px, vec4);
Button {
    background-color: require(accent);
    background-image: require(icon);
    font-family: require(face);
    padding: require(insets);
    gap: require(spacing);
    content: require(caption);
    interactable: require(enabled);
    text-align: require(alignment);
}

The spelling require(-> accent <-) also works. Declarations must be at the stylesheet root. Supported types are float (number), int (integer), bool (boolean), string, color, length, vec2, vec3, vec4, texture (image), font and enum. Vectors are whitespace-separated CSS numeric/length values. String defaults require quotes. Asset defaults use none or asset("asset-uuid"). Texture and font fields use filtered project asset pickers with drag/drop validation.

Optional metadata is min(value), max(value), label("Caption"), tooltip("Description") and options(first, second). Bounds apply to numeric values (or each vector element) in their declared units; enum defaults must be one of their options. The length field retains its declared unit. Right-click a generated field to reset it to the stylesheet default.

Duplicate names, invalid defaults, unsupported types, invalid options and unknown require references fail import with a diagnostic. Invalid overrides loaded from data fall back to the current default. Requirements are scoped to the stylesheet-owning GuiElement; parent and child sheets may declare the same name independently. A nested Frame still starts a new GUI scope. Declaration changes refresh the inspector; removed/stale overrides are retained as dormant scene data but do not create fields or affect rendering.

Programmatic values

auto fields = Bazzalt::GUI::GetStylesheetProperties(stylesheetUUID);
bool accepted = Bazzalt::GUI::SetStyleProperty(button, "accent", "#ff8844");
Bazzalt::GUI::SetStyleProperty(button, "caption", "\"Start\"");
auto value = Bazzalt::GUI::GetStyleProperty(button, "caption");
Bazzalt::GUI::ResetStyleProperty(button, "accent");

SetStyleProperty validates the selected stylesheet declaration, range and asset type, returning false without modifying data if invalid. Its value is one CSS literal, never a declaration or a file path. GetStyleProperty returns an effective CSS literal or an empty string for an unknown name. GuiStyleProperty describes the name, type, default, label, tooltip, optional bounds and enum choices. GuiElement.StyleProperties is the persisted map; prefer the validated GUI setter when changing values at runtime.

Editing CSS during play

Each GuiElement can have a private runtime stylesheet and inline declarations. These are instance data: editing one entity does not modify the shared .css asset or another entity. Runtime edits are temporary and are not written to scene files. They affect the next GUI layout/render in the same ordinary frame pipeline, including Spatial and Camera-Bound Frames.

GetStylesheetCSS (or GuiCSS.GetBaseText) reads the directly assigned asset source. GetCSS returns the additional runtime stylesheet text; SetCSS replaces that layer and AppendCSS adds rules after it. The assigned asset remains the base layer. An empty replacement removes the additional layer. Inline values override normal stylesheet rules; author !important rules still win over normal inline values. GetCSSProperty reads an inline declaration, not a computed pixel value. Use GetBounds and ResolveStyle for effective layout and appearance.

OperationPurpose
GetCSSStyle(entity)Returns a lightweight GuiCSS handle for object-style editing.
GetCSS / SetCSS / AppendCSSRead, replace or append the private runtime stylesheet.
GetCSSProperty / SetCSSProperty / RemoveCSSPropertyRead, set or remove one inline declaration. Removing it restores the cascade.
SetCSSRule / RemoveCSSRuleReplace or remove matching top-level selector rules. Pass declarations without outer braces. Replace the enclosing stylesheet to edit rules inside a media/viewport block.
SetCSSKeyframes / RemoveCSSKeyframesReplace or remove a named top-level keyframe definition. Pass the frame blocks as text.

GuiCSS exposes Get, Set, Remove, GetText, GetBaseText, Replace, Append, SetRule, RemoveRule, SetKeyframes and RemoveKeyframes. Its owner must have an enabled GuiElement to render the styles. It does not own the entity. Invalid/stale owners and malformed edits return false; rejected edits leave the previous valid source intact. Set and rule-edit operations cannot inject additional rules through a property value.

Transitions and keyframes

Button {
  opacity: 1;
  width: 120px;
  transition: width 250ms ease-out, opacity 150ms linear;
}
Button:hover { width: 170px; }
@keyframes pulse {
  from { opacity: 0.4; }
  50% { opacity: 1; }
  to { opacity: 0.4; }
}
.busy { animation: pulse 1.2s ease-in-out infinite alternate; }

Transitions respond to changed cascade values, including inline runtime edits, hover and requirement overrides. A replacement transition starts at the last displayed value rather than snapping back. No entrance transition runs on the initial layout. Define the base value explicitly so removal has a target to transition back to.

Supported transition longhands are transition-property, transition-duration, transition-delay and transition-timing-function. Comma lists repeat when shorter than the property list; all selects interpolable changed properties and none disables transitions. Timings include s/ms, negative delay, linear, ease, ease-in, ease-out, ease-in-out, cubic-bezier(x1,y1,x2,y2), steps(count,start/end), step-start and step-end. Colors and matching numeric value structures interpolate; incompatible units, textures and discrete keywords change directly.

Animation supports animation-name, animation-duration, animation-delay, animation-timing-function, animation-iteration-count (fractional or infinite), animation-direction (normal, reverse, alternate, alternate-reverse), animation-fill-mode (none, forwards, backwards, both) and animation-play-state (running, paused), plus the shorthand above and comma-separated animations. Declare keyframes outside conditional viewport/media blocks. Keyframes accept from, to, percentages and grouped offsets. Missing endpoints use the authored base value when available. Later animations override earlier animations on the same property, !important values override animations, and active transitions override both. Changing the definition restarts its timeline; pause/resume retains elapsed time. Time follows the engine game clock, including time scale and pause.

The GUI implements its own CSS dialect, not a browser DOM. Animate supported GUI layout/paint properties; parsing a web-only property does not add renderer support. Interpolation requires compatible units/structure, so use consistent units across endpoints. CSS transforms, additive animation composition and per-keyframe timing overrides are not provided. Motion shorthands and longhands follow normal declaration order and cascade priority. Motion remains bounded: 64 simultaneous animations per element, 1024 keyframe offsets per definition, 256 KiB runtime stylesheet text, 128 inline properties and 64 KiB total inline data. Existing parser, hierarchy, filter and renderer limits continue to apply.

auto css = Bazzalt::GUI::GetCSSStyle(button);
css.Set("width", "170px");
css.SetKeyframes("pulse", "from{opacity:0.4}to{opacity:1}");
css.Set("animation", "pulse 1s linear infinite alternate");
css.Set("animation-play-state", "paused");
