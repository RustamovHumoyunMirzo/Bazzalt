C++ hot reload state

Include Bazzalt/Script.h and declare gameplay with COMPONENT and PROPERTY normally. The editor-generated module exposes typed property readers. Reload matches instances by entity UUID and component type, copies matching properties and keeps defaults for added properties. Removed properties are ignored; a changed property type rejects reload.

Custom state and callbacks

COMPONENT(Counter) {
public:
    PROPERTY(float, Speed, 2.0f)
    int Hits = 0;
    std::string OnSaveReloadState() const override {
        return std::to_string(Hits);
    }
    void OnRestoreReloadState(const std::string& state) override {
        Hits = state.empty() ? 0 : std::stoi(state);
    }
    void OnReload() override {
        // Reconnect subscriptions and rebuild derived caches here.
    }
};

OnSaveReloadState returns a versionable, NUL-free string for fields that are not PROPERTY declarations. OnRestoreReloadState receives it on the candidate before commit. Both may reject a reload by throwing. Keep save const and restore limited to the candidate's own data; external mutations cannot be rolled back. The custom payload and each reflected value are limited to 1 MiB. No process addresses, object bytes or vtables are copied.

Lifetime

OnCreate/OnDestroy are skipped for the swap, while C++ constructors/destructors still execute. Use OnReload to restore scoped subscriptions and avoid persistent scene edits in constructors. Engine-owned module jobs complete before capture and unload. Old module leases remain alive while engine-managed work needs them. Reacquire Behavior pointers after reload. Globals, statics, arbitrary external threads, global subsystems and extension DLLs do not migrate.

See the Behavior reference and editor controls.
