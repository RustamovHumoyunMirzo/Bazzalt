Native SDK authoring

Register ordinary C++ functions through Bazzalt/Extension.h. The engine supplies Lua conversion; extension authors do not include sol2 or Lua headers and do not receive renderer or editor internals. A native extension is trusted native code and runs with the process's privileges.

Export a module

#include <Bazzalt/Extension.h>
namespace {
double Double(double value) { return value * 2; }
void Register(Bazzalt::ExtensionRegistry& registry) {
    registry.Bind("StudioMath", "Double", Double);
}
}
BAZZALT_EXTENSION(Register)

Register this source in Scripts with Public: true and ModuleName: StudioMath. Build Package compiles it against the selected prebuilt ScriptSDK. BAZZALT_EXTENSION declares the versioned module entry point. Registration must export only the module name declared by the manifest. Duplicate names reject loading.

Registry API

ExtensionRegistry.Bind(module, name, functionPointer) wraps a free function. It validates argument counts and converts arguments. ExtensionRegistry.Export(module, name, callback) accepts an ExtensionFunction for dynamic dispatch. The callback receives ExtensionArguments and returns ExtensionValue. No Lua binding internals are exposed.

ExtensionValue supports nil/monostate, bool, signed 64-bit integer, double, string, Vec2, Vec3, Vec4 and UUID. Bind converts supported C++ numeric argument types and can return void. References to custom C++ objects, raw pointers, containers and arbitrary user classes are not marshalled through this boundary. Expose operations using supported values or supply public C++ headers for richer native-only interfaces.

Consume from Lua and C++

local Math = Bazzalt.require("StudioMath")
local result = Math.Double(4)

auto result = Bazzalt::Extensions::Call("StudioMath", "Double", {4.0});
auto doubled = std::get<double>(result);

Call native module functions with dot syntax in Lua. Bazzalt.require itself accepts dot or colon syntax. Public SDK functions are available to gameplay scripts; private helpers are scoped to their owning extension. Native function callbacks retain their library lease through invocation.

Binary compatibility and dependencies

Supply libraries matching the target OS, architecture and engine SDK version. C++ ABI compatibility is not inferred from a manifest's version range. Package artifacts record their engine version. A game build can compile a missing target artifact from the packaged native source using its matching prebuilt runtime SDK; it never builds Filament, Qt or the engine. Supplied third-party link/runtime libraries must support that target too. Restrict Compatibility when they do not.

Put public headers in IncludeDirs and link/runtime dependencies in the appropriate platform directories. Do not include private Runtime, Rendering or EditorBridge headers. Native code cannot be sandboxed by manifest validation; package hashes detect corruption, not a malicious author or administrator.
