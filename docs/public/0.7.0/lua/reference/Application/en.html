Application

Global application controls: frame limits, background behavior, session state, window dimensions, metadata and deferred quit. This service is not owned by an entity.

Methods, results and limits

MethodResult or action
SetTargetFrameRate(int), GetTargetFrameRate()Set/read the foreground software frame cap. Default 60.
SetBackgroundFrameRate(int), GetBackgroundFrameRate()Set/read the unfocused cap. Default 30; the tighter positive cap wins.
SetRunInBackground(bool), GetRunInBackground()Set/read whether unfocused gameplay continues. Default true.
GetFrameRate()Smoothed measured gameplay updates per unscaled second; zero before a measured frame.
GetFrameCount()Number of measured gameplay updates in this application session.
IsFocused(), IsPlaying(), IsEditor(), IsQuitting()Read current global session flags.
Quit(int exitCode = 0), GetExitCode()Request clean shutdown/read its code (0..255). In the editor, stops Play rather than closing the editor.
GetWindowWidth(), GetWindowHeight()Last reported Game viewport drawable dimensions in pixels; zero before a size notification.
GetName(), GetCompanyName(), GetVersion()Project name and project.company/project.version metadata; unset strings are empty.
GetPlatform()Windows, macOS, Linux, or Unknown for the compiled host. This does not promise player support for every platform.

Application settings reset when a new game/Play session starts; save project-specific preferences yourself when persistence is needed. Controls do not expose initialization, rendering backend ownership, or the engine loop.

Availability and errors

Rates accept 0 (uncapped) or 1–1000; other values throw. Quit accepts codes 0–255. Controls reset each session. Measured FPS is not a promised target. All operations run on the main gameplay thread.

Application controls accept dot and colon syntax. Global event listeners are C++ subsystem-only: Lua OnBoot/OnUpdate-style application subscriptions throw a diagnostic rather than registering listeners. Entity behavior callbacks remain supported.

Bazzalt.Application:SetTargetFrameRate(120)\nlocal fps = Bazzalt.Application:GetFrameRate()\nBazzalt.Application:Quit(0)

Lua members and signatures

Use Bazzalt.Application. Each member below is actually registered in Lua. The adapter declarations are C++ binding notation, not Lua example code. sol::property exposes a field, sol::overload lists alternatives, sol::optional accepts an omitted/nil argument, and std::make_tuple returns multiple Lua values. sol::as_table returns a Lua table. Instance methods use value:Method(...); service/static calls use Bazzalt.Application.Method(...) unless a colon overload is explicitly registered. An engine exception becomes a Lua script error. See the examples and behavior notes above for usage.
