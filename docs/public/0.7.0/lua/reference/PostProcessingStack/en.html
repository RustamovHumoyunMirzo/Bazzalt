PostProcessingStack

Ordered custom camera effects. C++ references into its vector can be invalidated by additions/removals; Lua getters return copied effect values.

Underlying public header: Bazzalt/PostProcessing.h.

Read signatures together with the behavior notes below. The reference introduction explains arguments, return values, value copies, and errors.

In call notation, argument = default describes an optional argument and its default; Lua does not use named arguments here. Supply the value positionally or omit it. The C++ declaration below is comparison data, not Lua syntax.

Construction

Bazzalt.PostProcessingStack.new()

Each line is an accepted construction form. The argument names stand for values you supply; an empty call uses default values. Plain data types construct with their declared default fields.

Example

Gameplay snippets run inside a behavior callback or helper. Variables such as scene, camera, savedText and assetUUID are existing values, not automatically declared global variables.

local stack = camera.PostProcessing.CustomEffects
local effect = stack:AddEffect(shaderAssetUUID, "Custom")
effect.Parameters = { Bazzalt.PostProcessParameter.Float("strength", 0.5) }
stack:SetEffect(0, effect)
self.Entity:SetComponent("Camera", camera)

AddEffect

stack:AddEffect(shaderAsset [, name])

Appends an effect with nonzero shader UUID and optional name. C++ returns a reference; Lua returns a copy. Empty/zero shader UUID throws.

Returns: effect copy; use SetEffect to commit edits.

ArgumentMeaning
UUID shaderAssetPrecompiled custom-effect shader UUID, nonzero.
std::string name ={}Display label or declared parameter/type name as specified by this method; names are not UUID identity.

Invalid arguments and C++ exceptions are reported as Lua errors at the protected script boundary. Check the specific absence/false result rules above; not every missing value is an error.

GetEffects

stack:GetEffects()

Returns the effects vector in C++; Lua returns a one-based list of copied effect values. Add/remove operations can invalidate C++ references.

Returns: one-based table of effect copies.

SetEffect

stack:SetEffect(index, effect)

Lua writes an effect copy back at a zero-based stack index. Invalid index raises an error; commit the containing camera afterward.

Returns: no value.

Lua members and signatures

Use Bazzalt.PostProcessingStack. Each member below is actually registered in Lua. The adapter declarations are C++ binding notation, not Lua example code. sol::property exposes a field, sol::overload lists alternatives, sol::optional accepts an omitted/nil argument, and std::make_tuple returns multiple Lua values. sol::as_table returns a Lua table. Instance methods use value:Method(...); service/static calls use Bazzalt.PostProcessingStack.Method(...) unless a colon overload is explicitly registered. An engine exception becomes a Lua script error. See the examples and behavior notes above for usage.
