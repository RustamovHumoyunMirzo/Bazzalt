AssetManager

Read-only access to the active project asset database. Call static methods from hosted gameplay; there is no public project-open/import loop.

Underlying public header: Bazzalt/AssetManager.h.

Read signatures together with the behavior notes below. The reference introduction explains arguments, return values, value copies, and errors.

In call notation, argument = default describes an optional argument and its default; Lua does not use named arguments here. Supply the value positionally or omit it. The C++ declaration below is comparison data, not Lua syntax.

This is an enum/static service, host-owned scene, or returned behavior table, not a constructible Lua value. Use the static service or the host-provided value.

Example

Gameplay snippets run inside a behavior callback or helper. Variables such as scene, camera, savedText and assetUUID are existing values, not automatically declared global variables.

local asset = Bazzalt.AssetManager.GetAsset(assetUUID)
if asset and asset.State == Bazzalt.AssetState.Ready then
    -- Runtime cache is ready.
end

GetAsset

Returns optional AssetInfo for UUID or source path; absence becomes nil in Lua. It does not import files or open another project.

Lua members and signatures

Use Bazzalt.AssetManager. Each member below is actually registered in Lua. The adapter declarations are C++ binding notation, not Lua example code. sol::property exposes a field, sol::overload lists alternatives, sol::optional accepts an omitted/nil argument, and std::make_tuple returns multiple Lua values. sol::as_table returns a Lua table. Instance methods use value:Method(...); service/static calls use Bazzalt.AssetManager.Method(...) unless a colon overload is explicitly registered. An engine exception becomes a Lua script error. See the examples and behavior notes above for usage.
