Global subsystems

Subsystems are project-wide C++ services. Unlike entity scripts, they are registered for the project rather than added to an object in the Hierarchy.

Create and register

In Asset Browser choose Create > Subsystem Script. Open Window > Global Subsystems. Pick the C++ asset, choose its startup level and select Add. The modal child window groups entries by startup level. Apply saves registrations; changes take effect on the next Play or build. Remove Selected unregisters the service for the next session.

Choose a startup level

Boot runs earliest, followed by Window, Initialization, Content and Ready. Choose Ready for a service that needs the loaded scene. Earlier levels are for startup work; choosing an earlier level does not make unavailable services ready. Order within a level follows the dialog’s registration order.

Conflicting scripts and errors

A registered source cannot also be attached to an entity, even as a disabled component. Resolve conflicting attachments before applying or playing. The editor reports invalid registrations and lifecycle access in Console and stops the failed Play session. Game builds report fatal subsystem errors in a native error dialog.

Shared headers

Create > C++ Header creates a project header. Header files are edited with the configured external application. Only trust native code from known sources; project C++ is not sandboxed.

Programming reference

For implementing services, startup readiness, listener restrictions and shared interfaces, read the C++ subsystem programming guide and the Subsystem, Subsystems, Scripts and Application references. Lua supports application controls, not subsystem registration.
