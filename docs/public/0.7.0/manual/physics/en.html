Physics in the editor

Physics simulates movement and contact between objects. A Rigidbody supplies motion and mass. A collider describes the invisible volume that touches other colliders. A rendered mesh alone does not collide. BAZZALT runs Jolt inside its separate bazzalt_physics runtime library; you edit engine components without managing that library.

Make a falling cube

  1. Create a Cube from Hierarchy > Add New > Primitives. Name it Floor, give it a wide X/Z scale and move it below the origin.
  2. Select Floor. In Inspector > Add Component add Shape Collider. Its default Box shape follows the object's scale. With no Rigidbody it is static.
  3. Create another Cube above Floor. Add both Shape Collider and Rigidbody. Keep Motion Type set to Dynamic.
  4. Press Play. The upper cube falls onto Floor. Stop restores the authored scene; ordinary editing does not simulate.

Pause stops fixed simulation, and the editor's single-step control advances the existing game loop. To drive simulation manually from code, turn off scene Auto Simulation and call scene:GetPhysics():Simulate(deltaTime) during Play. Do not write an engine loop or initialize Jolt yourself.

Rigidbody

Static bodies do not move in simulation. Kinematic bodies follow explicit movement targets and can push dynamic bodies. Dynamic bodies respond to gravity, forces, impulses and contact. A Rigidbody without a collider still moves, but touches nothing. Disabled rigidbodies stop participating; this does not disable independent child rigidbodies.

Shape Collider and Mesh Collider

Shape Collider supports Box, Sphere, Capsule, Cylinder and an infinite Plane. Size is the full box size. Height is the full capsule/cylinder height; their long axis is local Y. Infinite planes require a static body. A sphere uses the largest scale axis; capsules and cylinders use the larger X/Z radial scale. Use positive, non-singular world scale.

Offset, Rotation and Scale are relative to the collider entity, in addition to its ordinary Transform. Inspector rotations are degrees; the C++/Lua component stores a Quaternion. Green selected guides show the cooked collision surface. Trigger guides are blue. The Scene Gizmos visibility control hides these guides; they are never game geometry.

A child collider attaches to the nearest Rigidbody above it, forming a compound body. Adding a separate Rigidbody to that child makes an independent body. Parent components are not copied to children. Mixed trigger and solid child colliders retain their individual contact behavior.

Mesh Asset is an optional override. Leave it empty for attached geometry: a Primitive Object, the selected model child mesh, or the mesh descendants of a grouping object. A child collider does not pull in the complete model or unrelated branches. Descendants with their own Rigidbody form independent physics bodies and are excluded from a parent's automatic geometry. Pick a glTF/GLB asset only when you want an explicit geometry override. Picking the same model asset on a model node retains that node or subtree scope rather than pulling in the whole model. Convex constructs a solid hull suitable for dynamic bodies. Turn Convex off for static/kinematic triangle surfaces. Concave dynamic bodies and moving infinite planes are rejected. Double Sided enables both triangle directions; Sanitize cleans the triangle input. Cooked geometry is cached and reused for repeated instances and property edits. Exact duplicate hull points are removed; collision triangles are not reduced. Selected green/cyan guides remain visible over mesh surfaces. Dense diagnostic wireframes have a drawing budget; that budget never changes collision geometry.

Friction controls sliding resistance; Restitution controls bounce from zero to one. Convex Radius rounds convex edges. Layer selects one of 32 collision layers. Equal nonzero Collision Group values suppress contacts within that group. Is Trigger produces enter/stay/exit notifications without a contact response.

Scene settings and layers

Select the scene row in Hierarchy and expand Physics. Gravity defaults to (0, -9.81, 0). Settings also include automatic simulation, sleeping, solver iterations, collision substeps, worker count, speculative distance, allowed penetration and sleeping thresholds. Max Bodies, Max Body Pairs and Max Contact Constraints bound solver capacity; stop Play before changing those capacities.

Edit Collision Layers opens a symmetric 32-by-32 matrix. A checked pair can collide. Query layer masks are separate: disabling a layer pair does not hide either object from raycasts.

Physics components/settings save with each scene and participate in editor undo/redo and game cooking. Inactive loaded scenes do not start running simulations just because they appear in Hierarchy. Only the active scene is stepped by the runtime.

Control and callbacks

Use scene.GetPhysics() in C++ or scene:GetPhysics() in Lua to apply forces/impulses, set velocity, move kinematic bodies, teleport, wake/sleep, query contacts and subscribe to physics events. Rigidbody components are data; they do not own the engine loop.

Entity scripts can implement OnCollisionEnter/Stay/Exit and OnTriggerEnter/Stay/Exit. Events contain both body and collider entities, durable UUIDs, a normal, relative velocity and world-space contact points. Callbacks run on the main thread after the solver, with duplicate mesh manifolds combined by collider pair. See the C++ guide and Lua guide.
