Application controls

Bazzalt.Application is a global service, not a component or an entity-owned object. Ordinary C++ and Lua scripts can control frame pacing, inspect application state, and request a clean exit. Only registered C++ Subsystem Scripts can listen to application lifecycle events.

Control the running game

-- Inside an ordinary Lua behavior:
Bazzalt.Application:SetTargetFrameRate(120)
Bazzalt.Application:SetBackgroundFrameRate(30)
Bazzalt.Application:SetRunInBackground(true)
local fps = Bazzalt.Application:GetFrameRate()
-- Stops Play in the editor; exits the standalone game:
Bazzalt.Application:Quit(0)
#include <Bazzalt/Application.h>
Bazzalt::Application::SetTargetFrameRate(120);
Bazzalt::Application::SetRunInBackground(true);
Bazzalt::Application::Quit(0);

Lua accepts both colon and dot calls. Target/background frame rates accept 0 for uncapped or an integer from 1 to 1000. They are maximum rates, not performance guarantees. GPU synchronization, rendering cost, and the host timer may produce a lower actual rate. BackgroundFrameRate is an additional cap while unfocused. Disabling RunInBackground suspends gameplay updates without blocking OS/editor event handling. Minimized standalone games can continue simulation without presenting frames when background running is enabled.

Control API reference

MethodResult or action
SetTargetFrameRate(int), GetTargetFrameRate()Set/read the foreground software frame cap. Default 60.
SetBackgroundFrameRate(int), GetBackgroundFrameRate()Set/read the unfocused cap. Default 30; the tighter positive cap wins.
SetRunInBackground(bool), GetRunInBackground()Set/read whether unfocused gameplay continues. Default true.
GetFrameRate()Smoothed measured gameplay updates per unscaled second; zero before a measured frame.
GetFrameCount()Number of measured gameplay updates in this application session.
IsFocused(), IsPlaying(), IsEditor(), IsQuitting()Read current global session flags.
Quit(int exitCode = 0), GetExitCode()Request clean shutdown/read its code (0..255). In the editor, stops Play rather than closing the editor.
GetWindowWidth(), GetWindowHeight()Last reported Game viewport drawable dimensions in pixels; zero before a size notification.
GetName(), GetCompanyName(), GetVersion()Project name and project.company/project.version metadata; unset strings are empty.
GetPlatform()Windows, macOS, Linux, or Unknown for the compiled host. This does not promise player support for every platform.

Application settings reset when a new game/Play session starts; save project-specific preferences yourself when persistence is needed. Controls do not expose initialization, rendering backend ownership, or the engine loop.

Lifecycle listeners belong to subsystems

An entity behavior or Lua script attempting to register an application listener receives an error. Create a C++ Subsystem Script in the Asset Browser and register it through Window > Global Subsystems. It can use simple named functions such as Application::OnLateUpdate(callback), without an Application-derived class or an owning entity.

#include <Bazzalt/Subsystem.h>
SUBSYSTEM(GameServices) {
public:
    void OnRegister() override {
        Bazzalt::Application::OnLateUpdate([this](float dt) {
            auto player = GetScene().FindEntityByName("Player");
            (void)player; (void)dt;
        });
    }
};

See the subsystem guide for event arguments, startup levels, failure handling, and service readiness. Existing Application Script project entries must be replaced with C++ subsystem registrations; Lua bootstrap scripts are no longer supported.
