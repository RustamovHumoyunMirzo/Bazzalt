Global subsystems

A Subsystem Script is a project-wide C++ service. Unlike an entity behavior, it has no owning entity, Transform, or component lifecycle. It remains loaded across scene replacements and is removed at the end of the game/Play session. Lua is for entity gameplay and application controls, not global lifecycle registration.

Create and register

In the Asset Browser, choose Create > Subsystem Script. Open Window > Global Subsystems, select the C++ asset, choose a load level, and Add it. The dialog groups registrations by startup level. Apply saves project metadata; changes take effect on the next Play or build. Remove Selected unregisters a service for the next session. This is a modal child window, not a docked panel.

A registered source cannot also be an entity script. Registration checks saved scenes and the attachment manifest; Play validates active scene attachments again. Even disabled attachments conflict. A manually edited scene cannot silently run the same source as both a component and a subsystem. A C++ source must implement the subsystem contract: SUBSYSTEM(Name) with OnRegister(). Existing unattached COMPONENT sources may be compiled in subsystem mode, but entity-only methods and GetEntity() will fail compilation rather than be emulated.

Startup levels

LevelLoad boundary
0 — BootBefore OnBoot. Packages are authenticated and project metadata is available; no scene or drivers are ready.
1 — WindowBefore OnBeforeWindowCreate.
2 — InitializationBefore OnInit. This begins driver initialization, not its completion.
3 — ContentBefore OnLoad. Core rendering/input drivers are initialized; initial scene content is not ready yet.
4 — ReadyBefore OnPostWindowCreate. The startup scene and rendering surface are available.

A subsystem may subscribe to its own level or higher levels. A Ready subsystem subscribing to OnBoot or OnInit is an error. A Boot subsystem may subscribe to OnLateUpdate and access the scene inside that later callback. Loading early does not give permission to use uninitialized services early. Registration order within a level follows the dialog order; shutdown unregisters in reverse loading order.

Editor Play simulates these application startup phases against the existing editor host; it does not create a second editor window. Boot still follows package/project and native module setup. OnBoot is not literally the first CPU instruction or a bypass of package verification.

Subsystem API

Include Bazzalt/Subsystem.h. SUBSYSTEM(Name) derives from Bazzalt::Subsystem, not Component or Behavior. Override OnRegister() to connect listeners, and optionally OnUnregister() to release owned transient state. GetScene() returns the active scene only when it is ready. Use normal scene APIs such as GetScene().FindEntityByName("Player"). Avoid keeping entity references across scene unloads.

Application::OnX(callback) returns a subscription token. Application::Unsubscribe(token) disconnects it early. Listeners registered in subsystem callbacks are disconnected automatically before its object/module is destroyed. Generic Application::Subscribe(type, callback) receives an ApplicationEvent; named listeners receive the arguments listed below. Ordinary entity behaviors cannot acquire registration authority.

Events and arguments

Boot: OnBoot(). Window: OnBeforeWindowCreate(). Initialization: OnInit(). Content: OnLoad() and OnSceneLoad(path).

Ready: OnPostWindowCreate(), OnPlay(), OnStop(), OnPreRender(), OnRender(), OnPostRender(), OnPreShutdown(), OnShutdown(), and OnWindowCloseRequested(). Window changes use OnWindowResize(width, height) and OnWindowFocusChanged(bool). Scene notifications use OnSceneLoaded(sceneUUID), OnSceneUnload(sceneUUID), and OnSceneUnloaded(sceneUUID).

Also at Ready: OnPreUpdate(deltaTime), OnUpdate(deltaTime), OnFixedUpdate(fixedDeltaTime), and OnLateUpdate(deltaTime). Entity behaviors still have their own update and late-update callbacks; those do not become global listeners. OnPostRender reports return from the backend call, not GPU completion. A close request is a notification, not a cancellable operation.

Input is prepared before OnPreUpdate; fixed updates precede normal gameplay, then late updates and rendering follow. Scene-load requests are deferred to a safe frame boundary. OnSceneUnload runs before teardown, OnSceneUnloaded afterward. Audio playback services start with gameplay: use OnPlay or later for playback operations. Shutdown hooks cannot be guaranteed after an OS kill or fatal driver/native-code fault.

Sharing code and headers

Native entity scripts also expose Scripts::Find(entity, typeName) and Scripts::Get<Interface>(entity, typeName), declared in Bazzalt/Script.h. They return an optional Behavior pointer or a checked shared-interface reference. This lets C++ entity scripts and subsystems call one another through project headers. Resolve instances after initialization; a script may be constructed before its OnCreate has run. References expire on scene/script teardown. Lua does not gain arbitrary native-interface invocation through this API.

Create > C++ Header creates a header asset using the header.svg icon. Include project headers normally and expose interfaces or inline helpers there. Subsystems::Find(name) returns a loaded Subsystem pointer or null; Subsystems::Get<Interface>(name) returns a checked interface reference and throws if unavailable/incompatible. This supports calling a service through an interface shared in a project header without exposing runtime internals. Do not retain the pointer after the session ends.

Errors and security

Invalid level subscriptions and guarded early scene/asset/input/audio access throw descriptive errors. The editor reports subsystem failures in Console and stops the failed Play session. A standalone game stops and presents a native OS error dialog. This is controlled failure, not continued execution with invalid service state.

Only public SDK headers are staged. Compilation rejects absolute, escaping, and recognizable private-header includes, and fingerprints included project headers so changes rebuild modules. These checks prevent accidental internal API dependencies; native C++ is trusted code, not a security sandbox. Arbitrary machine code, forged declarations, static initializers, invalid pointers, filesystem access, and third-party code cannot be isolated by an include validator. Run only trusted project C++ code. Put service use and listener registration in OnRegister/callbacks, not static constructors.
