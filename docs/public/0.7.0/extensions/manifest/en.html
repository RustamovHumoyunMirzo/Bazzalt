Extension manifest reference

The authoring file is YAML. The package contains a normalized, versioned JSON manifest and a SHA-256 inventory. The .bpack container is a bounded ZIP archive; it is not a project asset archive and cannot be installed by simply renaming an arbitrary ZIP.

FormatVersion and General

FieldMeaning
FormatVersionInteger 1. Omission means version 1.
General.IdRequired stable lowercase ID. Segments start with letters; lowercase letters, digits and underscores are allowed within segments. Dots or hyphens can separate segments.
Name, ShortDescription, VersionRequired nonempty display strings and semantic version, such as 1.0.0 or v1.0.0-beta.
LongDescriptionOptional relative path to a packaged text file.
HomePageUrl, RepoUrl, DocsUrlOptional HTTPS URLs. Installation does not fetch them.
AuthorsOptional author information retained in the manifest.

Compatibility and Dependencies

MinEngineVersion is required. MaxEngineVersion is an optional inclusive maximum. Prereleases compare before the corresponding stable release. Optional Platforms contains Windows and/or Linux. Optional Architecture contains x86_64 and/or x86. Omit these lists to express portability; doing so does not manufacture native libraries for another target.

Dependencies.Requires is a list of extension IDs. Dependencies must already be installed and enabled. Missing dependencies, cycles and public module collisions reject activation without changing the enabled state. Project locks pin exact package digests and versions, including dependencies. There is no automatic network dependency installer.

AssetRegistry

Each entry has a unique identifier Id and a relative file Path. Register scripts, UI files, icons and other files needed by your tool. A script or panel references this ID, not an absolute filename. Asset IDs are local to an extension; public module names are global. Optional asset Scope is Runtime or Editor. Panel UI and panel icons default to Editor; other data defaults to Runtime. Explicitly mark other editor-only data as Editor. Runtime data assets receive stable project UUIDs and can be resolved with Extensions.GetAsset. Package inventory hashes cover the normalized manifest and every packaged file. Editing installed files causes integrity validation to fail.

Scripts

Scripts is a mapping from local script keys to registrations. Each registration requires an asset Id referring to a .lua or .cpp file. ModuleName defaults to its key. Public defaults to false. Public scripts are gameplay SDK modules and must have Runtime scope. SelfContained defaults to true: the module is addressed by ModuleName alone. When false, its name is ExtensionId.ModuleName. Private modules always use ExtensionId.ModuleName and can be required by SDK modules from that same extension.

Scope is Runtime or Editor. Entry scripts and scripts referenced by editor panels or menus default to Editor; other scripts default to Runtime. Mark editor-only helper scripts explicitly with Scope: Editor so they never enter a game build. Entry defaults to false. At most one editor entry script is allowed. An entry script cannot be Public. The builder adds a Compiled map for portable Lua bytecode or target-specific native binaries; do not edit generated artifact paths by hand.

Native

Enabled controls deployment of supplied dependent native binaries. IncludeDirs lists packaged public header directories. LibDirsWin and LibDirsLinux provide link libraries for native scripts. BinDirsWin and BinDirsLinux provide runtime libraries, copied next to native extension modules. Native.Scope is Runtime or Editor; an editor-only plugin defaults to Editor so its native libraries are not copied into games. EditorLibDirsWin/EditorLibDirsLinux and EditorBinDirsWin/EditorBinDirsLinux supply additional editor-only dependencies in a combined package. All directories are relative to the manifest. Provide libraries matching the selected target architecture. Duplicate output library names are rejected.

EditorRegistry and Extends.Menubar

EditorRegistry keys refer to .ui asset IDs. Each panel requires Title and optionally Icon (another registered asset ID) and Script (a script key). Panels are registered in the shared docking system and can be opened from Window or an Editor.OpenPanel command.

Extends.Menubar is a list of mappings with Menu, Title, Script and Function. Menu can be File, Edit, Object, Build, View, Window or Help, or a new top-level menu title. Triggering an action calls the named function on the controller table returned by its script. Editor scripts and their UI assets are excluded from game output.

Extends.Component

Each mapping entry has Script and optionally Icon. Script must refer to a private, non-entry COMPONENT behavior, not a subsystem. The actual COMPONENT declaration names its type and PROPERTY declarations define its inspector fields. Use a type name unique across all project and extension scripts, for example StudioTerrainBrush. A component can use SDK modules, private helpers from its own extension and normal gameplay APIs. Its source and SDK headers are materialized under Assets/Extensions/ExtensionId, becoming normal project script assets. Removing or disabling the tool does not delete those authored project assets.

Extends.SceneSettings

Each setting is keyed by a unique field name and contains Type (bool, int, float or string), Default, optional Label and optional numeric Min/Max. Defaults must match the type and range. Fields appear when a scene is selected in the hierarchy. Values are saved in that scene under ExtensionProperties using ExtensionId:FieldName keys. Values remain serialized if the extension is disabled and are available through the public Scene extension-property methods.

Extends:
  SceneSettings:
    GravityScale:
      Type: float
      Default: 1.0
      Min: 0.0
      Max: 10.0
      Label: Gravity scale
