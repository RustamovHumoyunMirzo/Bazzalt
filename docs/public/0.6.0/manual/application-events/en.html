Application events

An application event is a notification from the running game, such as a window resize or the start of shutdown. These notifications do not give scripts ownership of the engine loop. Use a project-level application script for startup events; use a scene behavior for the lifetime of one entity.

Choose an application script

Open File > Project Settings and choose Application Script. This stores the script asset UUID under application.script. Do not attach this script to an entity. It has no owning entity, survives scene changes, and is loaded once per game session. Native application scripts use the existing C++ compiler; Lua application scripts are imported to bytecode like other Lua assets.

#include <Bazzalt/Application.h>
APPLICATION(Game) {
public:
    void OnBoot() override { /* No scene or initialized drivers yet. */ }
    void OnWindowResize(std::uint32_t width, std::uint32_t height) override {}
    void OnWindowFocusChanged(bool focused) override {}
    void OnLateUpdate(float deltaTime) override {}
    void OnPreShutdown() override { /* Save gameplay state here. */ }
};

Lua application scripts return an ordinary table. Named methods receive the same arguments as the C++ hooks, with the table passed as self by Lua's colon syntax.

local Game = {}
function Game:OnBoot() end
function Game:OnWindowResize(width, height) end
function Game:OnWindowFocusChanged(isFocused) end
function Game:OnLateUpdate(deltaTime) end
function Game:OnPreShutdown() end
return Game

Startup and shutdown

HookMeaning
OnBoot()First trusted gameplay lifecycle notification, before the native window and game subsystems.
OnBeforeWindowCreate()Immediately before native window creation.
OnInit()Beginning of subsystem initialization. Drivers are not necessarily ready inside this callback.
OnLoad()Beginning of scene loading, including later scene loads.
OnPostWindowCreate()Window and rendering surface/context are available.
OnPlay() / OnStop()Scene scripts have started / are about to stop.
OnPreShutdown()Before scene/services are destroyed; save persistent gameplay data here.
OnShutdown()Final notification after normal player window and context teardown.

Package authentication, project metadata, the Lua interpreter or native module loader, and entry declarations must exist before any game callback can run. OnBoot does not bypass these security requirements. Editor Play creates a game session inside an already-running editor: completed editor initialization/window events are not replayed. Stop ends that application session. A force-killed process cannot deliver shutdown notifications.

Frame callbacks

OnPreUpdate(float deltaTime) runs after input preparation. OnFixedUpdate(float fixedDeltaTime) runs in each fixed simulation step. OnUpdate(float deltaTime) follows normal scene logic; OnLateUpdate(float deltaTime) follows normal updates and is suitable for camera tracking. Scene behaviors and custom systems also support OnLateUpdate. C++ systems receive Scene& before the delta; Lua system methods receive scene, deltaTime.

OnPreRender() and OnRender() run immediately before backend rendering. OnPostRender() runs after the backend call returns, not after GPU completion. These are notifications for preparing data, not access to Filament or permission to submit rendering yourself. Paused editor redraws do not run gameplay callbacks.

Window and scene callbacks

OnWindowResize(width, height) reports drawable pixel dimensions after the resize is applied. OnWindowFocusChanged(isFocused) reports focus gain/loss. Focus notifications do not automatically pause gameplay or mute audio. OnWindowCloseRequested() reports a close request; it is not cancellable.

OnSceneLoad(path) runs before deserialization. OnSceneLoaded(sceneUUID) runs after successful scene replacement. OnSceneUnload(sceneUUID) runs before old scene teardown, and OnSceneUnloaded(sceneUUID) follows replacement. Failed deserialization leaves the current scene alive and does not send OnSceneLoaded.

Subscribe from ordinary scripts

Any running script can subscribe to future notifications. Events are not replayed: a scene script subscribing in OnCreate has already missed OnBoot. Generic subscribers receive one ApplicationEvent value, rather than the named method arguments.

local B = Bazzalt
local token = B.ApplicationEvents.Subscribe(
    B.ApplicationEventType.OnWindowResize,
    function(event) print(event.Width, event.Height) end)
B.ApplicationEvents.Unsubscribe(token)
#include <Bazzalt/ApplicationEvents.h>
auto token = Bazzalt::ApplicationEvents::Subscribe(
    Bazzalt::ApplicationEventType::OnWindowResize,
    [](const Bazzalt::ApplicationEvent& event) { /* event.Width, event.Height */ });
Bazzalt::ApplicationEvents::Unsubscribe(token);

ApplicationEvent contains Type, DeltaTime, Width, Height, IsFocused, SceneUUID, and ScenePath. Only fields relevant to the event are populated. GetName(type) returns the callback name. Unsubscribe(token) returns whether a registration existed. Use subscriptions only on the game thread. Subscriptions created inside native behavior lifecycle callbacks are cleaned up when that instance stops; Lua VM subscriptions are cleaned up before the VM closes. Explicitly unsubscribe earlier when a listener is no longer needed. Exceptions are logged without stopping other listeners.
