AntiAliasing

Camera anti-aliasing mode. Anti-aliasing reduces stair-stepped edges; temporal modes also use previous frames.

C++ header: Bazzalt/Components/Camera.h.

Read signatures together with the behavior notes below. The reference introduction explains arguments, return values, value copies, and errors.

#include <Bazzalt/Components/Camera.h>
enum class AntiAliasing

None

None

No camera anti-aliasing.

FXAA

FXAA

Fast approximate spatial anti-aliasing.

TAA

TAA

Temporal anti-aliasing using frame history. Reduces temporal shimmer but can soften detail or leave ghosting on motion.

MSAA2x

MSAA2x = 3

Two-sample geometry coverage anti-aliasing, without temporal history.

MSAA4x

MSAA4x = 4

Four-sample geometry coverage anti-aliasing. Higher bandwidth and memory cost than 2×; a useful starting point when temporal filtering is unwanted.

TAAFXAA

TAAFXAA = 5

Temporal anti-aliasing followed by FXAA. Can smooth remaining spatial edges at the cost of another pass and additional softness.

MSAA2xFXAA

MSAA2xFXAA = 6

Two-sample MSAA followed by FXAA.

MSAA4xFXAA

MSAA4xFXAA = 7

Four-sample MSAA followed by FXAA.

Applying a mode

auto& camera = entity.GetComponent<Bazzalt::Camera>();
camera.PostProcessing.Enabled = true;
camera.PostProcessing.AntiAliasingMode = Bazzalt::AntiAliasing::MSAA4xFXAA;

Settings apply live to each enabled camera, including split-screen views and camera-to-Texture captures. CameraPostProcessing.Enabled=false disables the camera AA stages; re-enabling restores the chosen mode. Switching modes resets unused stages instead of leaving old MSAA/TAA enabled. Invalid C++ enum casts fall back to no camera AA; serialized and editor values outside 0–7 are rejected.

MSAA treats geometry coverage, not every shader/texture shimmer. FXAA is inexpensive but can blur detail. TAA uses previous frames. Combined modes trade more work and softness for coverage of different artifacts. There is no SMAA, SSAA, DLSS or FSR anti-aliasing mode behind these names.

Sample counts are requests; Filament adapts to backend/device capabilities. TextureDescriptor.Samples is a separate destination attachment setting, not another name for CameraPostProcessing.AntiAliasingMode. For ordinary camera captures, a single-sample destination may be used with camera MSAA. Explicitly multisampled destination assets remain independent. The editor Scene navigation camera is separate from game Camera components.

When both a camera MSAA mode and a multisampled Texture asset are used, the internal render stage requests the larger sample count up to the supported view limit of 4×, then resolves into a single-sample output texture. Counts are not multiplied. Prefer TextureDescriptor.Samples=1 when the camera alone should choose the MSAA level.

Camera MSAA presets currently stop at 4×. An 8× preset is not exposed: the integrated Vulkan view path failed real-GPU tests despite the device advertising 8× support. Low-level Texture sample requests do not raise the camera's internal MSAA stage beyond 4×.

Existing scene values remain stable: None=0, FXAA=1 and TAA=2. The default remains TAA.
