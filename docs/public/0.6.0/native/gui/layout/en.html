GUI layout and style inheritance

A GUI container can position its children automatically in a row or column. Layout and style inheritance use the same entity hierarchy in viewport, camera-bound and spatial Frames. The engine owns layout and rendering; gameplay only edits components.

Absolute layout remains the default

Include Bazzalt/GUI.h. RectTransform defaults to Layout = Absolute. Anchors, Position, Size and Pivot retain their existing behavior. MinSize and MaxSize constrain the final dimensions. All pixel-like values are logical GUI units multiplied by the Frame scale. A spatial Frame uses its reference surface and PixelsPerUnit for world placement.

Rows and columns

Set Layout on the parent's RectTransform to GuiLayoutMode::Row or Column. Only direct children with an enabled, visible RectTransform participate. Children with IgnoreLayout use ordinary anchored placement instead. A nested Frame is an independent render root and never a layout item. An entity without RectTransform still passes its inherited parent rectangle to its descendants, but is not a flow item.

#include <Bazzalt/GUI.h>

// scene is an existing Scene reference supplied by your behavior/service.
auto hud = scene.CreateEntity("HUD");
hud.AddComponent<Bazzalt::Frame>();
auto& row = hud.AddComponent<Bazzalt::RectTransform>();
row.Layout = Bazzalt::GuiLayoutMode::Row;
row.Padding = {16, 12, 16, 12};
row.Gap = 8;
row.Align = Bazzalt::GuiAlignment::Stretch;

auto panel = scene.CreateEntity("Panel");
panel.SetParent(hud, false);
auto& item = panel.AddComponent<Bazzalt::RectTransform>();
item.Size = {240, 80};
item.MinSize = {120, 40};
item.FlexGrow = 1;
panel.AddComponent<Bazzalt::Rectangle>();

A RectTransform on the Frame entity configures its children's layout and padding; it does not change the Frame surface or make widgets on that root render. On an ordinary container, its own box is determined by its parent and its Layout controls the next level down.

Layout field contracts

FieldMeaning
LayoutAbsolute (0), Row (1), Column (2). Row's main axis is X, Column's is Y.
PaddingVec4 left, top, right, bottom. Nonnegative; defaults to zero. Insets the content box for both anchored and flow children.
MarginVec4 left, top, right, bottom on the child. Nonnegative; defaults to zero. Reserves space in flow layout only.
GapNonnegative spacing between participating children, not before the first or after the last; default zero.
FlexGrowChild's nonnegative share of spare main-axis space, default zero. Two unconstrained children with weights 1 and 2 receive one-third and two-thirds of the spare space.
FlexShrinkNonnegative shrink weight, default 1. Shortage is distributed by weight times the child's original constrained preferred size. Zero prevents shrinking.
AlignCross-axis Start, Center, End or Stretch. Stretch fills the available cross-axis area after margins, subject to the child's min/max. Default Start.
JustifyMain-axis Start, Center, End or SpaceBetween. Applied to positive space remaining after flex sizing. Default Start. SpaceBetween adds spacing between two or more items.
IgnoreLayoutFalse by default. True opts this child out of its parent's row/column while retaining its own child layout.

In flow, Size is the preferred size and min/max still apply. The parent owns final child positions, so the participating child's anchors, Position and Pivot do not affect placement. Flow order follows hierarchy sibling order; ZIndex affects drawing and hit testing only. Disabled or hidden RectTransform children reserve no space. Flex constraints are redistributed after a child reaches min/max. If minimum sizes, margins or gaps exceed the available box, children overflow from Start rather than acquiring negative sizes. ClipChildren controls clipping; layout never silently changes it.

Explicit style inheritance

Inheritance is opt-in per property. The renderer resolves effective values each frame; the child retains its authored local value so disabling inheritance restores it immediately. Use the inspector checkboxes or the same C++ fields. Stylesheets use the same inheritance contract through computed copies; authored local values remain unchanged.

Component/valueFlags and sources
Rectangle.Style (GuiStyle)InheritColor, InheritHoverColor, InheritPressedColor, InheritDisabledColor, InheritBorderColor, InheritBorderWidth, InheritOpacity. Each searches ancestor Rectangle components.
GuiTextInheritColor, InheritFontSize, InheritWrap. Each searches ancestor GuiText components. Value remains the child's own text.
GuiImageInheritColor searches ancestor GuiImage components. Texture and Camera are never implicitly inherited.

Traversal skips ancestors without the matching component and disabled matching components. It stops at and includes the nearest Frame entity, never crossing into an outer Frame. If an ancestor also requests inheritance, resolution continues for that property. If no further source exists, the last matching source's local value is the fallback; with no matching source at all, the child's local value is the fallback. Colors are assigned, not multiplied; opacity inheritance is not group compositing. Text color does not accidentally inherit a Rectangle's background color. A Frame root can provide styles even though widgets on the root itself are not drawn.

auto& parentStyle = hud.AddComponent<Bazzalt::Rectangle>().Style;
parentStyle.Opacity = 0.8f;
auto& localStyle = panel.GetComponent<Bazzalt::Rectangle>().Style;
localStyle.InheritOpacity = true;

// Read an effective snapshot without modifying authored component data.
auto effective = Bazzalt::GUI::ResolveStyle(panel);

GUI::ResolveStyle, ResolveText and ResolveImage return effective copies. A missing/invalid entity returns the corresponding default value. ResolveText preserves the child's Value and ResolveImage its source. These operations do not require a rendered frame and reflect live parent edits/reparenting. Do not commit an effective snapshot back when you want to preserve local authored values.

Persistence and boundaries

RectTransform, Rectangle, GuiText and GuiImage now serialize as component version 2. Version-1 scenes load with absolute layout, zero insets/gap and inheritance disabled. Invalid enum values, negative insets/flex weights and nonfinite numbers are rejected by editor/scene deserialization without replacing the old component. Programmatic invalid layout data is excluded from layout. Layout and inheritance traversal are bounded to 128 hierarchy levels. Invalid or zero presentation sizes clear stale bounds and interaction state.

This step provides a single-line row/column flex foundation, not full CSS Flexbox or Grid. Wrapping, content measurement/auto sizing, baseline alignment and scrolling are not implemented. CSS assets and cascade and FreeType font assets are available; complex-script shaping is not. See the editor authoring instructions or Lua examples.
