GUI stylesheets

Import a .css asset and assign it to Frame.Stylesheet in the inspector or through C++/Lua. Add GuiElement to author an ID, whitespace-separated Classes and Tags, or Attributes such as [state="active"]. Rules apply to that Frame hierarchy; a nested Frame starts its own scope. GuiElement.Stylesheet scopes additional rules to its subtree. Computed styles never replace your authored component values.

Engine terms, familiar syntax

A stylesheet describes GUI entities, not web pages. A type selector names a widget such as Button, an ID identifies one widget, a class identifies a reusable group and an attribute describes explicit widget metadata. Hierarchy relations mean GUI parent/child or sibling relations within a Frame. States such as hover and focus come from engine input. There is no DOM, JavaScript, browser history or network loading.

/* Assign this asset to a Frame's Stylesheet field. */
@layer defaults, theme;
@layer defaults {
    Button { color: white; gap: 8px; }
}
:root { --accent: #4a90e2; --spacing: 12px; }
.toolbar > Button.primary:hover {
    color: var(--accent, rgb(74 144 226));
    margin: calc(var(--spacing) * 2);
}
@viewport (min-width: 900px) and (orientation: landscape) {
    .toolbar { gap: clamp(8px, 2vw, 24px); }
}

Supported properties are color, background-color, background-image, border-color, border-width, opacity, font-family, font-size, font-kerning, letter-spacing, line-height, white-space, display, visibility, pointer-events, flex-direction, align-items, justify-content, overflow, z-index, width/height and their min/max variants, left/top, gap, flex-grow/shrink, padding and margin (including sides). Unknown properties produce diagnostics. Percent lengths use parent content bounds; em uses font size and rem uses the Frame root size. See layout and inheritance.

Widget types are Frame, Button, TextInput, Image, Text, Rectangle and Container. Set GuiElement.ID explicitly, or use the entity name as its default ID. Tags are available through the tags attribute. Attributes use presence or exact-value syntax, for example [disabled] [state="active"]. Hover, active and focus update from engine input. Disabled Frames and controls expose :disabled.

* / Button / #play / .primaryEvery GUI entity / widget type / exact ID / class.

:root, :emptyFrame-root and explicit empty-state queries supplied by the GUI adapter.

Comma-separated selectors share a declaration block. Widget type and pseudo names are ASCII-insensitive; IDs, classes, attributes and custom-property names are case-sensitive by default. Unsupported/malformed selectors produce diagnostics rather than silently becoming a broader match. Pseudo-elements, namespaces, :has and nested style-rule syntax are not implemented.

Cascading and variables

The winning declaration is chosen by !important, layer precedence, specificity, then declaration order. ID specificity outranks classes/attributes/pseudo-classes, which outrank widget types. Unlayered normal rules beat layered normal rules; important rules reverse layer order. Duplicate declarations preserve their order. Layer names may have dotted paths; full browser nested-layer/revert-layer behavior is not claimed.

:root { --accent: #acf; --padding: 12px; }
Button { color: var(--accent); padding: var(--missing, var(--padding)); }
#play { color: rgb(255 255 255 / 80%) !important; }

Custom properties inherit through the GUI snapshot hierarchy. Parent variables are computed before child redefinitions. Variables are substituted as tokens, not executable text. Nested fallbacks work. Missing variables without a usable fallback, cycles (including fallback dependencies), excessive depth or expansion size invalidate the declaration and produce a diagnostic. A losing lower-priority declaration is not substituted as a fallback for an invalid winning value.

Ordinary inherit, initial and unset are resolved into per-frame computed component copies. Local authored values remain intact. Explicit component Inherit flags still work; a CSS declaration overriding that property takes precedence in the computed copy.

Values and conversion

Value familySupported conversion
Numbers and lengthsSigned/exponent numbers; px/dp, %, em/rem, vw/vh/vmin/vmax. The layout context supplies percentage and font-size bases. Unitless values are retained for scalar properties.
Mathcalc with +, −, *, /; min, max and clamp. Invalid dimensional arithmetic, division by zero and nonfinite results are rejected.
Colors#RGB, #RGBA, #RRGGBB, #RRGGBBAA; rgb/rgba comma or space/slash forms; hsl/hsla with angle hues; hwb; color(srgb ...); transparent/currentColor. Basic CSS 16-color names plus grey, orange, rebeccapurple, cyan and magenta are recognized.
Strings and booleansEscaped UTF-8 strings/identifiers; true/false literals. Strings never execute commands.
Referencesurl("asset://...") and asset(...) are parsed references. The parser never fetches, opens or imports them; the asset adapter accepts project UUIDs and validates font/image types. External URLs are not loaded.

Balanced unknown functions and units remain available in parsed data, but typed conversion can reject them. This is not full browser CSS: every named color, CSS Color 4/5 color space, gradient, animation and web-only unit is not implemented. Parsed colors are encoded sRGB values; renderer conversion is a separate responsibility.

At-rules

@viewport and @media conditionally contain rules. Supported features are min/max/exact width and height, orientation, prefers-color-scheme and prefers-reduced-motion. Queries support screen/all, and/or/not, comma alternatives and parentheses. @viewport is an engine conditional, not a way to create or resize the native game window.

@layer statements and blocks define cascade order. Other at-rules, including @import, @font-face, @keyframes and @supports, are retained with warnings and not executed. Their bodies do not leak into the normal cascade. In particular, @import never downloads or reads another file, fonts are assigned directly with font-family: asset("UUID") or the Font picker instead of @font-face.

Errors and safety

Diagnostics carry severity, UTF-8 byte offset and one-based line/byte column. The parser recovers enough to report later errors, but a syntax-invalid sheet is not authoritative for cascading. UTF-8 and NUL validation, finite-number checks and byte/token/rule/declaration/recursion/expansion/work limits prevent unbounded input processing. Unknown conditions fail closed. All functions operate on owned data and caller-provided hierarchy snapshots; no editor loop, renderer or OS access is exposed.

Assets, fonts and live editing

Create a stylesheet with Asset Browser > Create > Stylesheet. Edit it with Open or Open With. Assign it using a Stylesheet picker, then give GUI entities reusable Classes. Font and image references use asset("UUID") or url("asset://UUID"). Obtain the UUID from the asset metadata or AssetManager; it is a stable project identity, not a filesystem path.

.title { font-family: asset("FONT-UUID"); font-size: 24px; }
.card { background-image: url("asset://IMAGE-UUID"); padding: 12px; }
Button:hover { background-color: #467cb8; }
.hidden { display: none; }

Used stylesheet/font files are watched in the editor. Saving them triggers targeted import and updates computed values and font atlases. Imported stylesheet dependency manifests retain referenced fonts/images in cooked games. Query GUI::GetStyleDiagnostics(entity) for application diagnostics; changed diagnostics also appear in the editor Console. Syntax-invalid assets are marked failed in the Asset Browser.

Fonts use the same rendering path for Viewport, CameraBound and Spatial Frames. See font assets and measurement. CSS opacity currently affects each entity's own layers, not an offscreen composited group. This dialect does not implement CSS Grid, flex wrapping, auto content sizing, gradients, animation, browser DOM or arbitrary web stylesheets. Resource and traversal limits may use the built-in fallback glyph instead of allocating without bounds.
