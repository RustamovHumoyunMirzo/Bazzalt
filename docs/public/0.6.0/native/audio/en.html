C++ audio

Include Bazzalt/Audio.h for the service, voice handle and source/listener components. Individual headers are available at Bazzalt/AudioClip.h, Bazzalt/AudioMixer.h, Bazzalt/Components/AudioSource.h and Bazzalt/Components/AudioListener.h. No third-party audio headers are required.

Play an entity's source

#include <Bazzalt/Audio.h>
#include <Bazzalt/Script.h>
COMPONENT(Footsteps) {
public:
    PROPERTY(Bazzalt::AudioClip, Step, {})
    void OnCreate() override {
        auto& source = GetEntity().AddComponent<Bazzalt::AudioSource>();
        source.Clip = Step;
        source.PlayOnAwake = false;
        source.SpatialBlend = 1;
        source.MinDistance = 1;
        source.MaxDistance = 20;
    }
    void OnUpdate(float) override {
        // Call when your movement logic produces a footstep:
        // Bazzalt::Audio::Play(GetEntity());
    }
};

Assign Step in the behavior's inspector. Clip fields use asset UUIDs, not owning pointers or paths; moving or renaming a source file does not break the reference when its .meta file is preserved. Do not add another source if the entity already has one: use HasComponent/GetComponent instead.

Keep a voice handle

auto voice = Bazzalt::Audio::Play(entity);
if (voice.IsValid()) {
    voice.SetPitch(1.1f);
    voice.Pause();
    voice.Seek(0.25);
    voice.Resume();
    voice.FadeTo(0.0f, 0.5);
}
auto shot = Bazzalt::Audio::PlayOneShot(clip, position, 0.8f,
    Bazzalt::AudioMixer::GetSFXBus(), 1.0f);

Play restarts an entity source, replacing its previous voice. PlayOneShot creates an independent voice at a fixed world position. A voice is a non-owning numeric handle; it becomes invalid when playback finishes, the source is disabled/destroyed, another Play replaces it, it is stolen by the voice limit, or the scene stops. Destroying the C++ handle does not stop the sound.

Entity-owned voice settings are synchronized from AudioSource each tick. Set the component's Volume/Pitch for lasting source changes; voice SetVolume/SetPitch are useful for independent one-shots and may be overwritten for entity-owned voices. FadeTo is a separate multiplier and remains in effect until the voice ends or is restarted. Seconds and pitch do not implicitly follow Time scale.

Route and control buses

auto music = Bazzalt::AudioMixer::GetMusicBus();
music.SetVolumeDecibels(-12.0f);
music.SetPaused(true);
auto dialogue = Bazzalt::AudioMixer::CreateBus("Dialogue");
source.OutputBus = dialogue;
// Persist a specific bus identity in your mixer asset if scenes reference it.
auto settings = dialogue.GetSettings();
settings.Parent = Bazzalt::AudioMixer::GetSFXBus().GetUUID();
dialogue.SetSettings(settings);

Bus configuration is runtime state. Source UUIDs are persisted, but dynamically creating a new random bus each launch will not restore an old bus UUID. For authored routing, assign a .bmixer asset to AudioListener.MixerAsset, or call AudioMixer::Load(assetId). Load validates the complete graph before replacing routing and keeps existing voice playback cursors.

Lifecycle and failures

The engine starts/stops the audio system with gameplay. Authoring never plays PlayOnAwake sounds. Device initialization is lazy and failure does not crash the editor or invent a listener. Test IsValid on returned voices and use Audio::GetLastError for details. Calls that manipulate voices, buses or ECS belong on the gameplay/main thread, not an audio callback or arbitrary worker thread. Never initialize miniaudio yourself through the public API.

See the complete audio API reference and the editor audio guide.
