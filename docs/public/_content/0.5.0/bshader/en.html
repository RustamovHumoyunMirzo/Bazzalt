Shaders and material assets

A shader declares surface behavior and parameters. A material asset chooses a shader and stores values for those parameters.

The asset types

The engine imports shader sources with .shad or Filament's .mat extension. A .matinst file is a material instance asset, not shader source. A compiled .filamat package is renderer data generated for loading, not a file to edit as shader code.

Assign a shader to a material's Shader field, then edit its declared parameters. Assign the material to a Mesh or Primitive Object's Material Asset field. A shader is not interchangeable with a material in that picker.

Bshader source

Bshader provides a higher-level language that translates surface declarations into Filament material source. For example:

shader SimpleSurface {
    properties {
        roughnessFactor: float = 0.5;
    }
    material {
        roughness = roughnessFactor;
    }
}

Properties become parameters the material can supply. The material block assigns surface properties supported by the language and rendering pipeline. Translation is not the same as GPU compilation: the engine's import/build pipeline compiles the resulting material through Filament's material compiler before runtime loading.

Editor workflow

  1. Add a supported shader source to the project's asset directory.
  2. Create a Material asset and select it in the Asset Browser.
  3. Assign the shader in its Inspector. The parameter fields come from that shader's declarations.
  4. Set its values and assign the material to a renderable entity.
  5. If it fails, inspect Console for source/translation/compiler errors instead of assuming a material has been generated.

Textures assigned to texture fields are asset references. The shader must declare and sample a texture parameter for it to affect the surface. Adding a texture file beside a material does not assign it automatically.

Runtime boundary

Gameplay can choose a precompiled shader, create material instances, and change compatible parameter values. It cannot add a new uniform or compile arbitrary shader text through MaterialBuilder. Use runtime material presets if you only need a standard lit or unlit surface without writing a shader.

Using the translator library

Engine/tool developers can use Bshader's separate C API in shader_translator.h: create a ShaderContext, call ShaderTranslatorCompileString, inspect success and diagnostics, then free the result and context. The current translator returns generated material source text; the runtime package compilation step remains separate.

That compiler/tooling interface is not the gameplay material API. Most game scripts should use Material, Shader, and MaterialBuilder rather than manage compiler contexts.
