Read your first C++ example

This guide explains the engine examples' notation. It is not a complete C++ course, but it identifies the pieces you need before using the API reference.

Headers and names

#include <Bazzalt/Math.h>
Bazzalt::Vec3 position{0.0f, 1.0f, 0.0f};

The include line makes declarations from a header available to the compiler. Bazzalt is a namespace, and :: selects a name inside it. Vec3 is a type containing X/Y/Z floating-point numbers. position is your variable. The three values in braces initialize it.

float represents a fractional number; the f suffix marks a floating-point literal such as 1.0f. bool represents true/false. std::string represents text. A semicolon ends a declaration/statement. The filenames and API spelling are case-sensitive for portable code.

Fields and methods

position.Y += 1.0f;
auto direction = position.Normalized();

A field is stored data; .Y selects the second coordinate. += adds into the existing value. A method is an operation: Normalized() returns a normalized copy. auto asks the compiler to infer the result's type; it does not mean an untyped Lua value.

Static methods belong to a type/service. Bazzalt::Time::GetDeltaTime() does not require you to create a Time object.

Copies, references, and pointers

auto entity = GetEntity();
auto world = entity.GetWorldTransform();
world.Position.Y += 1.0f;
entity.SetWorldTransform(world);

world is a value copy. SetWorldTransform commits it. In contrast, GetComponent<Light> returns a reference to stored component data; declaring auto& preserves that reference. A pointer uses *, can be nullptr, and accesses members with ->. A reference is not an ownership promise: never keep component storage after removing its component or destroying the scene.

Component templates

The type between angle brackets chooses the component: entity.HasComponent<Bazzalt::Light>() tests Light, not a string called “Light”. Lua uses type-name strings because its bindings do not expose C++ template syntax.

AddComponent fails if the same type is already attached. Required default components cannot be removed. TryGetComponent gives a pointer when present or nullptr when absent; check it before dereferencing.

Behaviors, properties, and callbacks

#include <Bazzalt/Script.h>
COMPONENT(Example) {
public:
    PROPERTY(float, Speed, 4.0f)
    void OnUpdate(float deltaTime) override {
        (void)deltaTime;
    }
};

COMPONENT declares an attachable behavior class. public makes its declared members accessible. PROPERTY declares an Inspector-editable value with a default. void means OnUpdate returns no value; its float argument is seconds. override says this implements a lifecycle method from Behavior.

The engine calls this callback while playing. You do not write main(), create the private Engine, or call its frame loop. The empty example deliberately does nothing; continue with Walk movement for a visible result.

Build and runtime failures

A compile error means the compiler could not build the source: check includes, spelling, types, and Console's source location. A runtime error occurs after code is built, for example using an absent component. A false/null/optional-empty result can instead represent normal absence. Read the operation-specific contract in the reference.
