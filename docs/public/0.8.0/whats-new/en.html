What's new in 0.8.0

0.8.0 focuses on engine and editor performance and adds composable level-of-detail groups. Existing scene and project data remains readable. Most changes remove duplicate CPU work or GPU state uploads without lowering visual quality, changing fixed-step timing or slowing property refresh.

Shared runtime optimizations

Transforms use direct affine composition, physics reuses body poses within each synchronization, and stable render/light state avoids repeated uploads. Primitive shapes share CPU geometry and BVHs for accurate picking; ray traversal avoids temporary heap allocations. These paths serve editor previews and standalone game players.

Editor fixes and interaction

The Play inspector avoids rewriting unchanged values, while moving objects and edited properties continue updating. Rejected field edits restore valid values. Vehicle, wheel and anti-roll guides are included in editor selection. Corrupt cyclic transform ancestry reports an error instead of hanging a world-transform query.

Entity LOD groups

Add LOD to a parent and assign detailed/simplified child subtrees. Screen-height thresholds, bias, hysteresis, culling, forced levels, orthographic views and independent per-camera selection are supported. Geometry and shadows switch without toggling scripts or physics. Viewport picking and outlines respect the selected representation. Copy/paste and serialization preserve group settings and reconnect copied child references.

Read the editor guide, C++ guide, Lua guide and performance guide. API reference pages document LOD and LODLevel for both languages. LOD uses authored meshes and hard switching; automatic mesh simplification and cross-fading are not included.

Typed global events

Create YAML .event assets in the Asset Browser, edit named typed arguments in the inspector, and assign them to C++/Lua behavior properties. GlobalEvent supports validated firing, ordered subscriptions, unsubscription, scoped cleanup and bounded FIFO delivery for nested same-frame messages. Global Subsystems can opt into direct UUID asset access, including packaged games. Read the editor guide and the C++/Lua API references.

Native macOS targets and platform profiles

Editor, Hub, Core, Compiler and game-player targets now include Intel x64 and Apple silicon arm64 on macOS 12+. The editor uses the native system menu bar and Metal viewports. Build Settings retains independent collapsible profiles for each platform; production, windowing and packaging stay shared. Native game bundles support signing, optional notarization and player-side login Keychain provisioning. Read the macOS guide for requirements and deployment details.
