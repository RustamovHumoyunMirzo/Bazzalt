Docs / What's new in 0.8.0

Particle and VFX graphs

Create .vfx assets with reusable UUID-based graph imports, spawn and initialization settings, forces, lifetime color/size, flipbooks and material output. Particle Emitter components and matching C++/Lua controls use the native fixed-step CPU simulation and camera-facing renderer. The Visual Effects panel includes graph history, autosave, typed asset pickers and simulation snapshots. Shader Graph palettes now start collapsed. Read the VFX guide.

Hierarchical LOD, impostors and transitions

Authored HLOD clusters can replace whole nested groups with proxy geometry or camera-facing, directional atlas impostors. LOD Transition adds reversible dither coverage with independent camera histories and a whole-group hard-switch fallback for incompatible materials. Components are editable in the inspector, serialized, duplicated with remapped child references, and available in C++ and Lua. See the LOD guide for authoring steps, shader compatibility and proxy/atlas limitations.

Asset dependency tracking

Assets now expose saved-reference reports with resolution and analysis states, direct/transitive dependencies and reverse references in C++ and Lua. The inspector has a read-only Asset References section. The graph handles cycles and missing UUID targets and is exported with cooked games. See the asset reference guide for coverage and dynamic-reference boundaries.

Multiplayer transport and player saves

C++ and Lua gain authenticated encrypted UDP client/server sessions, reliable/unreliable messages, binary codecs, connection events and statistics. SaveGame adds cross-platform progress slots, atomic commits, backup recovery, schema migration, asynchronous saves and optional authenticated encryption. Networking and crypto ship as sibling runtime modules. See the framework guide.

What's new in 0.8.0

Deterministic physics and replay

PhysicsReplay adds fixed-step policies, immutable solver checkpoints, branch restoration and bounded recording with seek, loop and playback controls in C++ and Lua. State includes rigid/soft bodies, constraints, vehicle inputs, pending forces, contacts and relevant hierarchy poses. Source builds enable Jolt cross-platform deterministic arithmetic; runtime capability reporting distinguishes imported solvers. Solver pose synchronization also retains canonical scale and ignores numerical scale noise in vehicle signatures, avoiding unnecessary constraint recreation. This is same-session physics replay with compatible topology, not a whole-game input replay. Read the workflow and limits.

Live gameplay script reload

During Play, editing C++ or Lua gameplay scripts now reloads code while retaining active entities, physics, audio and elapsed time. Native properties and custom state hooks, Lua instance data, spawned prefabs and streamed cells participate. Compilation runs in the background; incompatible candidates keep the prior scripts active. Edit provides an explicit reload command and Preferences controls automatic reload. Read the workflow and boundaries.

Prefab assets and linked instances

Create reusable .bprefab hierarchy assets by dragging objects into Asset Browser. Instantiate them from C++/Lua, double-click or hierarchy drag/drop. Linked instances support property and hierarchy overrides, apply/revert/update/unpack, typed entity-reference remapping, custom and unknown component preservation, multi-scene undo and standalone script cooking. See the prefab workflow.

Asynchronous streaming and GPU instancing

C++ and Lua can asynchronously read assets, replace scenes with deferred activation, and stream world cells manually or by distance. Loading supports cancellation, bounded queues, incremental main-thread activation and failure rollback. Empty scenes remain compatible with the legacy bare Entities YAML field; newly saved empty scenes use an explicit empty list. Interactive glTF and material-image loading prepare work asynchronously. Compatible primitives and Graphics submissions share GPU geometry/material resources for automatic instancing while preserving individual entity tools. See the C++ guide and Lua guide.

CPU profiling and shared jobs

The new CPU Profiler records engine and editor work and exports trace timelines. C++ gains Jobs for independent CPU work and Profiler scopes. Lua can control captures and inspect samples through Bazzalt.Profiler; worker callbacks remain native to preserve Lua and scene thread ownership. Existing systems keep their execution order.

0.8.0 focuses on engine and editor performance and adds composable level-of-detail groups. Existing scene and project data remains readable. Most changes remove duplicate CPU work or GPU state uploads without lowering visual quality, changing fixed-step timing or slowing property refresh.

Shared runtime optimizations

Transforms use direct affine composition, physics reuses body poses within each synchronization, and stable render/light state avoids repeated uploads. Primitive shapes share CPU geometry and BVHs for accurate picking; ray traversal avoids temporary heap allocations. These paths serve editor previews and standalone game players.

Editor fixes and interaction

The Play inspector avoids rewriting unchanged values, while moving objects and edited properties continue updating. Rejected field edits restore valid values. Vehicle, wheel and anti-roll guides are included in editor selection. Corrupt cyclic transform ancestry reports an error instead of hanging a world-transform query.

Entity LOD groups

Add LOD to a parent and assign detailed/simplified child subtrees. Screen-height thresholds, bias, hysteresis, culling, forced levels, orthographic views and independent per-camera selection are supported. Geometry and shadows switch without toggling scripts or physics. Viewport picking and outlines respect the selected representation. Copy/paste and serialization preserve group settings and reconnect copied child references.

Read the editor guide, C++ guide, Lua guide and performance guide. API reference pages document LOD and LODLevel for both languages. LOD uses authored meshes and hard switching; automatic mesh simplification and cross-fading are not included.

Typed global events

Create YAML .event assets in the Asset Browser, edit named typed arguments in the inspector, and assign them to C++/Lua behavior properties. GlobalEvent supports validated firing, ordered subscriptions, unsubscription, scoped cleanup and bounded FIFO delivery for nested same-frame messages. Global Subsystems can opt into direct UUID asset access, including packaged games. Read the editor guide and the C++/Lua API references.

Native macOS targets and platform profiles

Editor, Hub, Core, Compiler and game-player targets now include Intel x64 and Apple silicon arm64 on macOS 12+. The editor uses the native system menu bar and Metal viewports. Build Settings retains independent collapsible profiles for each platform; production, windowing and packaging stay shared. Native game bundles support signing, optional notarization and player-side login Keychain provisioning. Game data, licenses and ownership metadata stay in Resources; MacOS contains executable code. Publication preserves sealed metadata so signing remains valid. Read the macOS guide for requirements and deployment details.

Game input restores focus after maximizing or restoring the output viewport, including Cocoa window reparenting on macOS.

Cross builds and SSH workers

Build profiles now detect user-installed Zig/MinGW tools and support WSL and content/Lua-only foreign packaging. C++ ABI mismatches are rejected, foreign packages receive offline signature verification, and Windows metadata can be stamped on non-Windows hosts. Build > Remote Build adds verified SSH workers, optional OS-vault credentials, sync controls, cancellation and checksummed downloads. Worker builds serialize project synchronization and accept long Windows workspace paths. Native Wayland presentation and ARM64 Core/runtime build workflows are included. Game output stays black when no camera is active, including native Wayland. See the cross-build table and worker guide.

Shader Graph authoring

Create .shadg shader assets and edit them in the dockable Shader Graph panel. The searchable node catalog covers math, vectors, UVs, textures, procedural patterns, color, logic, lighting and vertex transforms. Typed connections, undo/redo, autosave and isolated Filament sphere/project-mesh previews are included. Graphs work directly in shader pickers and C++/Lua material workflows. Unlocking generates .shad source while preserving the asset UUID, with conversion undo available in the panel history. Read the panel guide and node reference.

Shader Graph now has dedicated toolbar icons and a loading overlay that keeps the previous preview visible during updates.

Every dock panel can now maximize and restore with Shift+Space or its tab menu. Empty tab headers provide group commands and a tab list.

Runtime GUI CSS can now be edited through C++ and Lua GuiCSS handles. Validated inline properties, selector rules and keyframe definitions feed the same cascade, with transitions and timed animations.

Editor tools and macros

The Scene toolbar Controls menu hosts built-in overlays and extension tools registered through Extends.Scene. Lua macros have their own dock panel, personal source snapshots, shortcuts, undoable scene/asset edits and themed programmatic dialogs. Their Editor API is separate from gameplay Lua. The Game viewport now has device-size and camera preview selectors, including default composition and None. See macros, scene tools and Game preview.

Extended visual effects

VFX graphs now support GPU analytic sprite/mesh motion, camera-facing trail ribbons, Jolt and plane collisions, scene gravity and impulse transfer, primitive or glTF mesh particles, lit output and real particle point lights. The editor exposes the modules and backend selector; C++/Lua expose collision events and resource/fallback statistics. Existing scenes retain CPU behavior. See the VFX guide for supported combinations and budgets.

Skeletal animation and controllers

Imported glTF/GLB skeletons and clips now support native skinning, state machines, 1D/2D blend trees, masked/additive layers, generic retargeting, root motion, and Two-Bone, CCD and FABRIK IK. Animator and IK Constraint components integrate fixed-step kinematic movement, dynamic bones and physics ground placement. Window > Animation adds imported clip timelines, safe pose preview and editable .banim controller graphs. C++ and Lua expose the same pipeline. Read the animation guide.

Animation authoring and deformed selection

Animation now includes morph-weight tracks, sparse and meshopt-compressed accessors, editable controller-owned clips with cubic keys and markers, validated humanoid profiles, conservative animated culling bounds and pose-aware editor picking. Imported source clips stay intact; authored overrides support automatic save, preview and undo.

Chunk-based world streaming

World Cell and Streaming Source components author large worlds directly in scenes. C++/Lua support regular grids, multiple sources, region bounds, priority, hysteresis, retry and diagnostics. Entity activation and unload share frame budgets; cancelled workers cannot resurrect unloaded cells. Scene references participate in asset packaging.

Visual CPU and GPU diagnostics

The profiler adds selectable CPU frame graphs, nested thread timelines, asynchronous GPU and backend timings, renderer counters and bounded memory histories. Its minimize control is disabled to prevent an inaccessible child window. Read the profiler guide.
