Animation in C++

Include Bazzalt/Animation.h, Bazzalt/Components/Animator.h and, for helper constraints, Bazzalt/Components/IKConstraint.h. Scenes own AnimationSystem automatically. User scripts control playback and data; they never manage the engine loop or renderer.

Playback

auto& animator = character.AddComponent<Bazzalt::Animator>();
animator.Controller = controllerAsset;
Bazzalt::Animation::Play(character, "Walk", 0.2f);
Bazzalt::Animation::SetParameter(character, "Speed", speed);
Bazzalt::Animation::SetTrigger(character, "Jump");
auto status = Bazzalt::Animation::GetStatus(character);
for (const auto& event : Bazzalt::Animation::GetEvents(character)) {
    // event.Name, State and zero-based Clip identify the latest evaluation's events.
}

AnimationRig::Load(modelUUID) returns an immutable shared rig and named clips. Skeleton::FindBone and AnimationRig::FindClip return -1 when absent; ambiguous exact bone names throw. Imported glTF/GLB clips are also usable independently with AnimationClip::Sample.

Runtime contracts

OperationMeaning
Play(entity, state="", fadeSeconds=0)Select and restart a state; empty selects Entry. Enable playback and unpause. Fade continues the outgoing state's motion.
Stop / Pause / ResumeStop resets to bind pose/time zero. Pause freezes clock advancement. Resume unpauses.
RebindDiscard runtime overrides, parameters, layers, constraints and playback state; reload the component's rig/controller.
SetRig / GetRigInstall a validated procedural rig or obtain the current immutable target rig. SetRig copies data and creates default clip states. GetRig can return null when no model/rig is assigned.
SetControllerInstall validated controller data, resolve optional retarget source and select Entry. This does not modify the serialized component's Controller UUID.
SetParameter / GetParameter / SetTriggerFinite numeric parameters; unset values read as zero. Up to 128 names. Triggers are consumed by transitions that use them.
SetTime / EvaluateSeek to 0–86,400 seconds without root movement, or explicitly evaluate a 0–1 second delta. Engine stepping is automatic; explicit Evaluate adds evaluation and should be used for tools/manual stepping.
SetLayer / RemoveLayerNamed clip layer with weight, additive flag and optional per-bone mask. Layers use independent looping clocks and stable lexical order.
SetIK / RemoveIKPersistent named model-space IK constraints, applied after clip layers. Scene IKConstraint helpers are another authoring option.
GetPose / SetPoseCopied local bone transforms; setting validates the skeleton and updates bound scene nodes. Automatic animation can replace an externally set pose on the next evaluation.
GetStatus / GetEventsCopied playback/root-motion state and bounded latest-evaluation events. Reading does not consume events; snapshots are not callbacks.

Pose operations and IK

auto rig = Bazzalt::Animation::GetRig(character);
auto pose = Bazzalt::Animation::GetPose(character);
Bazzalt::IKSettings hand;
hand.Solver = Bazzalt::IKSolver::TwoBone;
hand.Root = 3; hand.Tip = 5;
hand.Target = {0.5f, 1.4f, 0.2f}; // model space
hand.Pole = {0, 1, 1};
bool reached = Bazzalt::Animation::SolveIK(rig->Rig, pose, hand);
Bazzalt::Animation::SetPose(character, pose);

Skeleton::ForwardKinematics returns model-space matrices. Blend interpolates local transforms and optional masks; Additive applies a sample relative to a reference pose. SolveIK modifies the provided pose and returns whether the weighted result reaches tolerance. Retarget maps a source pose into a target bind skeleton using RetargetSettings; MapByName creates unambiguous generic mappings. All bone indices are zero-based.

Controllers, events and physics

AnimationController holds Entry, States and Transitions. States contain clip/blend-tree settings; transitions contain numeric comparisons, fade duration and exit phase. SourceModel, TranslationScale and RetargetMap configure cross-model playback. FromSource accepts version-1 controller data; Load resolves an imported .banim UUID. Invalid assets, names, poses and settings throw standard exceptions. Automatic engine evaluation reports errors once to Console under Animation and stops the affected player.

AnimationKey values use xyz for vectors and xyzw for quaternions; cubic keys carry input/output tangents scaled by the sample interval. AnimationMarker supplies named clip events. The runtime additionally emits StateEntered and Completed snapshots. Root-motion, kinematic bones, dynamic-body ownership and format limits are detailed in the animation manual. The Animation API reference and linked data-type references list the exact declarations.

Authored clips, morphs and humanoids

BoneTransform.Weights holds local morph weights in target order. AnimationChannel.Weights uses AnimationTrack.Target and the X component of each key/tangent. Blend, Additive, Sample, Retarget, SetPose and GetPose preserve these values. Quaternion channels still use XYZW. SkeletonBone.MorphTargets holds optional names, with the same count as its bind weights.

AnimationClip.FromSource parses bounded version-one JSON; ToSource writes a portable round trip including cubic tangents and named markers. AnimationController.Clips is an authored clip catalog: names override imported clips or add new ones, without changing the shared source rig. The selected source skeleton must validate every clip. Controller files can be up to 16 MiB; each authored clip accepts at most one million keys.

HumanoidAvatar.Joints contains HumanoidJoint entries (Name semantic, Bone index). Detect recognizes standard humanoid aliases; IsValid checks unique bindings and known parent ancestry. FindBone returns -1 for an unmapped semantic. Animation.MapHumanoid(source, sourceAvatar, target, targetAvatar, translationScale) returns a RetargetSettings mapping. Profiles can be partial, but must share at least one semantic. Review detected profiles; arbitrary names need explicit joints. Supported semantics include Hips, Spine, Chest, UpperChest, Neck, Head, left/right Shoulder, UpperArm, LowerArm, Hand, UpperLeg, LowerLeg, Foot, Toes, and Thumb/Index/Middle/Ring/Little Proximal/Intermediate/Distal.

Markers at time zero fire once when playback enters a state. Blend-tree markers come from the strongest weighted sample, with ties resolved by sample order, so blended footsteps do not duplicate. Times follow normalized blend phase. Non-looping states stop and report Completed, including blend states.
