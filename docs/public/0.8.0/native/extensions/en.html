Using extension SDKs in C++

Install and enable the required .bpack, then pin it to the project through Window > Extensions > Use Enabled SDKs in Project. Reopen the project to refresh SDK components. Native gameplay compilation includes the package's public IncludeDirs and link libraries. The engine never exposes extension implementation or renderer headers automatically.

Call an SDK module

#include <Bazzalt/Extension.h>
if (Bazzalt::Extensions::HasModule("StudioMath")) {
    auto value = Bazzalt::Extensions::Call("StudioMath", "Double", {4.0});
    double doubled = std::get<double>(value);
}

Extensions.GetModules returns available public module names. Call resolves native or Lua SDK functions and returns an ExtensionValue. Arguments and results use the supported scalar, math and UUID types documented in the native SDK boundary. Missing modules/functions, argument errors and Lua failures throw exceptions. Call from the engine thread after project SDK initialization; do not call these methods from static constructors.

Extensions::GetAsset(extensionId, assetId) returns a registered runtime asset UUID, or zero if unavailable. Registered runtime data assets are materialized with stable UUIDs and cooked through the normal asset database.

Scene extension settings

Scene.GetExtensionProperty(extensionId, fieldName, fallback) reads an extension's serialized string value; SetExtensionProperty changes it and returns success. GetExtensionProperties returns all stored namespaced entries. Inspector values are JSON strings, so a numeric setting may be stored as 1.0 and a text setting as a quoted JSON string. Values are not silently removed if the plugin is absent.

Distribution

Use the matching target SDK and compatible native dependencies when building. Runtime modules are cooked and protected with the game. Editor tools remain editor-only. See the extension user manual for installation and extension authoring to create your own package.
