Asset dependencies and references

Use Asset References in the inspector to investigate which saved files an asset uses and where it is used. Select a file in the Asset Browser and expand this section. Direct references show the target name; Referenced by lists transitive project assets. Double-click an available item to inspect it. A field tooltip identifies the serialized property that created the edge. Lists display up to 200 rows to keep large projects responsive; the API exposes the full results.

What the graph means

A dependency is a saved reference from one asset to another. A scene can reference a material, which references a shader and textures. Direct queries follow one edge; recursive queries follow every reachable edge. Reverse queries answer which assets reference a target. Results are sorted by UUID, deduplicated, cycle-safe and exclude the starting asset, even in a cycle. Missing UUID targets are retained, so deletion does not erase the evidence needed to repair a reference. UUID query arrays include known UUID targets, including missing UUIDs and built-in shaders. A file-only reference with no indexed UUID remains in the direct report with its path and Missing state; it cannot appear in a UUID array.

Resolution and analysis states

AssetReferenceState is Unknown, Missing, Found or Builtin. Found means the UUID resolves to an indexed asset; inspect AssetInfo.State separately for import failure, pending import or readiness. Builtin identifies engine shader presets that need no project file. Null UUIDs are not dependencies.

AssetDependencyScanState is Unknown, Complete, Partial or Failed. Complete describes the source format analyzed by its extractor, not the completeness of every reachable asset. Partial means known static references were extracted but arbitrary component data or dynamic behavior may contain more. Unknown means there is no extractor for that format. Failed includes LastError; outgoing references are discarded on failure to avoid publishing unvalidated paths. Never interpret an empty Unknown, Partial or Failed report as proof that deletion or packaging is safe.

Sources and update rules

Saved scenes and prefabs track environment, mesh/model/material slots, camera post-processing and render textures, GUI images/stylesheets/fonts, audio clips/mixers, prefab links and typed script asset properties. Entity IDs, parents, GUI camera links, physics bodies and mixer bus IDs are not asset dependencies. These documents report Partial because custom component properties can have their own meanings. Material instances track their shader and texture UUID properties. Shader Graph documents also expose stored texture defaults and report Partial coverage. Stylesheets use the UUID dependencies produced by the CSS importer. glTF JSON tracks its external local resource URIs; embedded data URIs do not create file dependencies.

Images, audio clips, fonts, render-texture descriptors, environments and other recognized leaf resources have no outgoing authored references. Scripts, opaque model binaries and unrecognized formats remain Unknown. Asset names constructed at runtime cannot be inferred. Engine importers may implement CollectDependencies to supply an authoritative report; custom serialized fields may use the AssetReference. prefix for explicitly declared UUID references.

Analysis runs during project import/refresh and after a saved indexed scene changes. Refreshing one source replaces its outgoing edges and updates the reverse index. A full refresh detects renames and deletions; UUID references survive a rename when the .meta file moves with the source. Path references such as glTF URIs must still be updated when their target path changes. Queries read the in-memory graph and do not scan the filesystem. Unsaved inspector edits are not part of the saved-asset graph.

Standalone output

The build writes a versioned .bazzalt/AssetDependencies.yaml graph next to CookedAssets.yaml. It rebuilds scene and prefab references after native script remapping. Older cooked projects without a graph still load and return Unknown reports. Game queries require no editor or source-code scanner. This graph does not automatically prune packages, trigger transitive reimports, record live object usage, or make unknown script behavior safe to strip.
