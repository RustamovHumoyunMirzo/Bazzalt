Particles and visual effects

A particle effect draws many short-lived sprites. Each particle has its own position, velocity, lifetime, size and color. Use particles for sparks, smoke, dust, magic or other transient details. A .vfx asset defines a reusable effect; a Particle Emitter component places and runs it in a scene.

Create your first effect

  1. In the Asset Browser, choose Create > Visual Effects. Double-click the new .vfx file to open its dockable graph.
  2. The default flow connects Spawn, Initialize, Gravity, Color Over Life and Output. Connections carry particle processing order, rather than shader values.
  3. Create an entity and add Particle Emitter. Drag the .vfx asset into its Graph field. Press Play in the editor. Play On Awake starts the effect automatically.
  4. Use Spawn to change emission rate (particles per second), duration, looping, delay, initial/loop burst and capacity. Initialize sets random lifetime, launch speed, cone angle and size ranges.
  5. Move the Scene camera to inspect the result. Scene, Game, split-screen and render-target cameras receive their own facing geometry. Output does not create a camera or light.

Work with the graph

Palette groups start collapsed. Search temporarily expands matching groups. Double-click a block or drag it onto the canvas, then drag its right-hand output socket to the next block's left-hand input. Drag blocks to arrange the graph; middle-drag pans and the wheel zooms. The right sidebar edits the selected block. Copy, paste, duplicate, delete, undo and redo use the shared graph editor. Output cannot be deleted. Disconnected blocks are saved for later work but do not execute.

Edits save automatically. An external file change is reloaded only when there are no local pending edits. Conflicting external changes are reported instead of being overwritten. The graph preview shows a native simulation snapshot at the selected time, projected into a small 2D view. The scene/game viewports show the actual material and texture output. The preview does not execute gameplay scripts or modify your scene.

Block reference

BlockBehavior and units
SpawnRate in particles/second, duration (0.01–3,600 seconds) and delay in seconds, burst at the start of each loop, and maximum live capacity. A connected pipeline supports one Spawn, including imported blocks.
InitializeUniform lifetime/size/speed ranges, a cone around local +Y in degrees, and angular speed in radians/second. Particle sizes are full world diameters before emitter/parent scaling.
Box / SphereUniform volume positions. Box uses half-extents; Sphere uses radius. The last connected position block wins.
VelocityAdd a constant initial velocity in simulation coordinates.
GravityConstant acceleration in simulation coordinates, default (0, -9.81, 0).
DragExponential velocity damping: exp(-coefficient * delta).
TurbulenceBounded procedural sinusoidal acceleration; strength and temporal frequency. This is not a fluid solver.
Color Over LifeLinear interpolation between start and end RGBA over normalized age.
Size Over LifeLinear interpolation from initial size to initial size multiplied by End Multiplier.
FlipbookColumns/rows of the output texture atlas, left-to-right then top-to-bottom, over one particle lifetime.
ImportInline another .vfx graph's connected flow at this point, using its asset UUID.
OutputOptional material and image texture. The default renderer uses soft circular alpha sprites; assigning an image uses its alpha. Imported output values only replace a parent setting when nonempty.

Blocks configure named simulation stages rather than arbitrary code: initialization runs on birth, forces run each fixed step, and lifetime curves evaluate from normalized age. Repeated blocks for the same setting use the last connected value. Graph layout position has no effect on execution.

Reusable graphs and imports

Add Import and pick another project .vfx asset, or drag it from the Asset Browser onto the canvas. Connect the Import block into the flow. For reusable modules, keep only the blocks you want to share connected to that file's Output; remove its default Spawn if the parent already supplies one. Importing a graph does not spawn a separate emitter. Keep the reference as a UUID: renaming or moving the file then preserves the link. The asset dependency graph tracks imported VFX, textures, materials and scene emitter references; game packaging retains them transitively.

Missing imports, unknown nodes, bad ranges, duplicate Spawn blocks, node cycles and recursive import cycles reject the effect. Imports are limited to 16 nested levels, 1,024 expanded connected blocks and 256 nodes per file. A file is versioned JSON, like Shader Graph, with a 1 MiB source limit. No source expression, Python or Lua code is executed from the graph.

Particle Emitter settings

Graph selects the asset; Material Override takes precedence over graph output. Max Particles caps live particles (1–32,768). Seed selects a repeatable random sequence, with zero treated as one. Rate Multiplier, Size Multiplier and Tint adjust the graph without modifying the asset. Simulation Speed is 0–100. Local particles follow the entity hierarchy; World particles keep the world positions/velocities computed at birth. Changing Space should be followed by Restart to avoid reinterpreting live coordinates. Play On Awake controls automatic start. Use Unscaled Time bypasses the global time scale. Disabling the component freezes simulation and hides its particles; re-enabling resumes it.

Runtime controls and bounds

Use the C++ or Lua guide for Play, Restart, Stop, Pause, Resume, Clear, manual Emit/Simulate, graph replacement, statistics and particle-event snapshots. Controls operate on one entity. Multiple entities share the asset definition and have independent state. Scene destruction and stopping editor Play release their simulation state.

Particles support CPU simulation and GPU analytic motion. It uses a 120 Hz fixed step, deterministic per-emitter random generators and camera-specific batches. Random sequences repeat for the same seed and fixed steps on a given platform; this does not promise cross-platform bitwise lockstep. A frame caps catch-up at 0.5 simulation seconds to avoid a hitch spiral. Manual Simulate accepts 0–30 seconds before emitter speed, and preserves fractional time between calls. Per-scene live simulation is capped at 131,072 particles; each camera renders up to 65,536, with emitter UUID order providing stable overload priority. Emit rejects counts above 65,535, while capacity overflow increments Dropped. Event snapshots retain at most 1,024 events per update/manual simulation. VFX geometry across all cameras is additionally limited to 262,144 vertices and 1,048,576 indices per frame; complex mesh particles consume that budget faster than sprites. These are safeguards, not promises of a particular frame rate.

Default sprites alpha-blend, depth-test against world geometry and do not write depth. CPU particles sort back-to-front inside each emitter, not globally across every transparent scene object. GPU analytic particles retain birth order. Custom materials must consume vertex color/UVs and provide suitable transparency/depth state. Volumetric effects and general GPU compute solvers are not provided.

Trails, collisions, meshes and lights

Connect these blocks into the flow before Output. Disconnected blocks do not execute. Each emitter owns independent state even when several entities use the same graph.

BlockFields and behavior
Trailslifetime (0.01–30 seconds), width (world units), minDistance (sampling distance), ratio (0–1), segments (2–128), dieWithParticle. Ribbons face the current camera. When dieWithParticle is false, history fades after its particle dies; Completed waits for the remaining ribbons. Local-space trails follow the emitter hierarchy. Point budgets are 8,192 per emitter and 65,536 per scene.
Collisionmode: Physics World (0) or Plane (1); radius (world units, greater than zero and at most 100), bounce, friction (0–1), kill, layerMask. Physics mode sweeps a sphere against the active Jolt world; it needs Play/physics running. It excludes the emitter and ancestor rigidbody. Plane mode works without physics; normal and distance define dot(worldPosition, normal) = distance. Collision events expose Collider, WorldPoint and world Normal. World queries are limited to 4,096 per update or manual Simulate call. Particles hold their previous position when that budget is exhausted; CollisionBudgetMisses reports this.
PhysicssceneGravity selects the scene gravity instead of the Gravity block; gravityScale scales it, mass specifies particle kilograms, transferImpulse applies the collision response impulse to dynamic rigidbodies. Combine with Collision in Physics World mode to push objects. Particles are swept probes, not individually allocated rigidbodies, and do not collide with one another.
MeshOutputmesh selects an imported glTF/GLB asset. With no asset, primitive chooses Cube, Sphere, Cylinder, Capsule, Plane, Cone or Torus (0–6). node (-1 for all) selects a glTF source node. Static node transforms and UVs are retained; skinning is not applied. Use low-poly meshes: at most 2,048 triangles and a 64 MiB source. All particles use the Output material or emitter override, rather than the source model's material slots. shadows enables shadow casting. Output's lit switch chooses built-in lit/unlit shading.
Lightsintensity (lumens), range (world units), ratio (0–1), maxLights (1–32), shadows. A stable subset of particles emits real point lights; color/alpha follow the particle tint and lifetime. There are at most 64 particle lights and four shadow-casting particle lights per scene. These lights are renderer resources and never create hidden hierarchy entities.

Choosing the simulation backend

Particle Emitter's Backend is CPU (default), Automatic or GPU Analytic. GPU Analytic evaluates position, constant acceleration, exponential drag, size, rotation and color in the vertex shader. CPU scheduling still owns births, lifetimes and events; this is not a general compute/storage-buffer simulation. Mesh and sprite outputs share this path. GetParticles calculates the same analytic state on demand without a GPU readback.

Trails, collisions, scene gravity, turbulence and custom materials require CPU state or geometry. Automatic and GPU Analytic requests fall back to CPU for those graphs or when no GPU renderer exists. GetStatistics reports the resolved Backend and BackendMessage. Backend changes do not discard particles. Older scenes without the field load as CPU. CPU and GPU analytic motion share the closed-form integrator, but floating-point results are not guaranteed bit-for-bit across devices. Use CPU when transparent particle depth sorting is required.
