Editor macros

A macro is a personal editor command written in Lua. It edits authoring data and can create helper dialogs. It is different from a game behavior: it has an Editor API, no entity-owned lifecycle, no gameplay Bazzalt table and no application loop access.

Create a macro

  1. Create Lua source assets in your project. Use identifier filenames such as Arrange.lua and Helpers.lua.
  2. Open Window > Macros and choose New.
  3. Enter a name, optionally assign a free keyboard shortcut, and choose the entry script with the project asset picker. Check any additional Lua scripts it requires.
  4. Confirm, then select the macro and choose Run or double-click it.

The editor stores a source snapshot in the cross-platform user data directory, under BAZZALT/data/Macros. The original project files can be deleted without breaking the macro. Editing the project source does not silently change an existing snapshot: use Edit and select an entry again to replace its stored scripts. Editing just the name or shortcut retains the existing snapshot. Delete asks before removing the stored bundle.

Entry and modules

local helpers = require("Helpers")
return {
  OnRun = function(self)
    Editor.BeginUndo("Arrange selected objects")
    for index, id in ipairs(Editor.GetSelection()) do
      Editor.Translate(id, {index * 2, 0, 0})
    end
    Editor.EndUndo()
    Editor.Log("Arrangement complete")
  end
}

The single entry returns a callback table or an OnRun function. Additional modules use Lua require with their stored filename stem: Helpers.lua becomes require("Helpers"). Only explicitly included modules are available. There is no package search path or access to files outside the bundle.

Build a helper dialog

return {
  OnRun = function(self)
    if self.dialog then Editor.ShowDialog(self.dialog); return end
    local dialog = Editor.CreateDialog("arrange", "Arrange objects")
    self.dialog = dialog
    self.amount = Editor.AddWidget(dialog, {
      id="distance", type="number", min=0, max=100, value=2
    })
    Editor.AddWidget(dialog, {
      id="apply", type="button", text="Apply", callback="Apply"
    })
    Editor.ShowDialog(dialog)
  end,
  Apply = function(self, event)
    local distance = Editor.GetValue(self.amount)
    for _, id in ipairs(Editor.GetSelection()) do
      Editor.Translate(id, {distance, 0, 0})
    end
  end
}

Dialogs belong to the editor and use its theme. Supported widgets are label, button, text, number, checkbox and choice. UI callbacks receive a table with widget and value. Reuse an existing dialog rather than recreating its identifier on every Run; CloseDialog hides it, while project changes, macro replacement/deletion and editor shutdown release it. No engine rendering or window-loop API is exposed.

Undo and game builds

Scene edits in each callback become one normal editor undo command. BeginUndo/EndUndo group a longer gesture; CancelUndo restores its original state. Errors roll back the tool's pending edits and stop its scene input. Tool edits honor locked entities. Generated text assets and their metadata participate in the same history; undo refuses to overwrite externally changed files.

Macro bundles stay outside the project and are never shipped. Binding project scripts records their UUIDs in .bazzalt/Editor/MacroSources.json. These source assets are excluded even with Keep All Assets. A game scene or subsystem that references an excluded macro source fails the build instead of shipping editor code. This editor-only designation remains if a macro is deleted; remove an obsolete UUID from that registry only when intentionally repurposing the source as gameplay code.

Macros do not run automatically when the editor opens. Run them explicitly or use their shortcut. Project changes close their dialogs and release their VM state. Stop Play before running authoring commands. See the Editor Lua API for every capability and its limits.
