Using extensions

Extensions add optional editor tools and reusable gameplay SDKs. Install a .bpack through Window > Extensions. Imported packages are disabled initially. Read its description and compatibility, enable its dependencies, then enable it and restart the editor. Disable a package before replacing it. The extension store is shared across projects for this editor installation's application-data location.

Choose SDKs for a project

Open a project, then use Enabled SDKs in Project in the Extensions window. Reopen the project afterward. Extensions.lock.json pins exact packages so another machine or an editor update cannot silently change the game's SDK. Install those exact .bpack files on a build machine. Missing packages, incompatible targets and duplicate public module or component names are reported rather than merged.

Editor tools and components

Plugins can add Window panels and menu commands. Their widgets use the editor's shared theme. Stop Play before running editor plugin commands. Registered behaviors appear in Add Component through their normal COMPONENT declarations; fields and gameplay lifecycle work like project scripts. Scene extension settings appear when selecting a scene in Hierarchy. Their values are saved with that scene and remain when the extension is disabled.

Build a game

Gameplay SDK modules and registered component behaviors are included in the game's protected runtime content. Editor panels and controller scripts are excluded. Generated project assets, such as a terrain produced by a tool, are cooked like other assets. Games do not require access to the editor's extension store. See C++ SDK usage and Lua SDK usage.

Create an extension

Use Build > Build Package with an authoring YAML file and a supplied runtime SDK. Extension creation, manifest fields and editor controller APIs have their own Extensions documentation.
