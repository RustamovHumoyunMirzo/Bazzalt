Physics recording and replay

Physics replay records fixed-step checkpoints of an already running scene. It supports rewinding to a checkpoint, branching simulation, inspecting recorded frames and playing them back without re-running the solver. Use it from C++ or Lua gameplay/tools; there is no separate editor timeline panel in this version.

Workflow

  1. Finish creating your physics bodies and configuring shapes, joints and vehicles.
  2. Enable deterministic stepping with PhysicsReplay. Match the engine fixed timestep to the configured value.
  3. Call BeginRecording. Continue ordinary fixed-step physics. Each completed step records a checkpoint, including forces queued by after-step callbacks.
  4. Call EndRecording, or allow the frame/memory budget to stop recording. GetStatus exposes the result.
  5. Disable PhysicsSettings.AutoSimulation. Call BeginPlayback, then AdvancePlayback at your desired playback rate. SeekFrame uses zero-based indexes. StopPlayback leaves the selected state in place for resuming simulation.

Budgets and errors

The default budget is 3600 frames and 64 MiB, including the initial frame. Recording stops when the next full checkpoint would exceed a limit and retains existing frames. A frame itself is bounded to 512 MiB. Invalid state, wrong session, invalid index or incompatible physics configuration throws a normal scripting exception. End-of-playback AdvancePlayback returns false unless looping. Clear releases recorder-owned frames; separately retained PhysicsState handles still own their checkpoints.

See C++ examples or Lua examples.

Scope and compatibility

A checkpoint belongs to one running physics world session. Stopping/restarting simulation invalidates it for restoration. Adding/removing/recreating physics bodies, changing collider geometry, relevant hierarchy or solver configuration rejects old checkpoints. Unrelated non-physics objects may be created or moved normally. Checkpoints include the solver, soft vertices and pinning, joints, vehicle state/inputs, queued forces, contacts, physics-related transforms and their ancestors. Restore does not replay collision callbacks.

This is physics rollback and state playback, not an input-driven whole-game replay. Script variables, application time, random generators, audio and non-physics gameplay are not rewound. Pause or gate gameplay that modifies the recorded physics world while playing back. Serialized replay files, topology-changing recordings and cross-session checkpoints are not supported in this version. States remain trusted opaque handles; the API never parses arbitrary native solver bytes.

Determinism requirements

Enable PhysicsDeterminismSettings.Enabled and use its exact FixedDeltaTime for every simulation step. Call the APIs on the main thread at a completed step boundary. SingleThreaded defaults to true. Repeat the same commands in the same order, with the same assets and settings. Match the application fixed step to the physics fixed step. The Jolt source build enables BAZZALT_CROSS_PLATFORM_DETERMINISTIC_PHYSICS by default; imported SDKs may differ. IsSolverCrossPlatformDeterministic reports the loaded solver flag. It does not certify script math, procedural geometry, vehicle wrapper calculations or whole-game cross-platform lockstep. Test your shipping builds and gameplay across target machines. See Jolt determinism requirements.
