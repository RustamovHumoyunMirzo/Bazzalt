Shader graphs

A .shadg is an editable, versioned JSON shader graph. It generates Bshader source, then follows the standard shader reflection and Filament compilation pipeline. It is a shader asset, not a material instance. Read the panel guide for the editor workflow.

Document structure

Version 1 stores version, name, shading (lit/unlit), blending (opaque/transparent/masked/add), doubleSided and nodes. Each node has a stable id, type, position, values and inputs. An inputs entry maps a destination socket name to the source node id. Nodes have one typed value output, except the Material and Vertex sinks. File layout positions have no effect on generated shader behavior.

{
  "version": 1, "name": "GraphShader", "shading": "lit",
  "nodes": [{"id":"output","type":"Material","position":[460,80],"values":{},"inputs":{}}]
}

Validation and determinism

Exactly one Material sink and at most one Vertex sink are allowed. Graphs are limited to 512 nodes, 128 nodes per dependency chain and 4 MiB. Identities, node types, socket names, finite numeric values, vector dimensions, missing references and cycles are checked. Every node participates in cycle checking, including disconnected nodes; only nodes reachable from an output generate code. Shared expressions are emitted once per stage. Reconnecting a socket replaces its previous connection.

Properties and textures

Property uses name, kind and value fields. Numeric kinds are float, float2, float3, float4, signed 32-bit int, plus bool. Names must be shader identifiers, cannot start with the generator-reserved bzg_ prefix, cannot be reserved surface/builtin names, and must fit the configured length limit. Reusing an identical declaration shares a parameter; conflicting declarations fail compilation. Texture declares a texture2d parameter with a project asset UUID default. Feed it to Sample Texture or Texture Lod. Unconnected UV inputs use the mesh's first UV set. Vector dimensions are explicit; a scalar can be broadcast.

Generated .shad source retains texture defaults in strict // BazzaltTextureDefault Name UUID metadata comments. The material compiler puts these defaults in runtime reflection. This preserves material behavior when a graph is unlocked. Image pixels are separate assets, never embedded into the graph.

Shader stages and previews

Material inputs generate a surface fragment stage. Vertex > Offset adds to the Bshader vertex position. Object matrix transforms are vertex-only and cannot feed Material directly. Unlit graphs cannot use lit-only normal inputs. Node generation and the native shader compiler both validate these restrictions.

The preview uses the compiled material and reflected defaults, with a fixed studio camera and light in its own renderer. OBJ/glTF/GLB preview geometry is bounded, with existing UVs/normals retained where present and generated fallbacks otherwise. Scene-fed render textures require the scene/game viewport. See the complete shipped node catalog.
