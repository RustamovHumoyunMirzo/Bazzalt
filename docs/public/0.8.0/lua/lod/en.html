LOD in Lua

LOD and LODLevel are available through Bazzalt. Component reads return copies; write a modified value back with SetComponent.

Assign and control levels

local B = Bazzalt
-- group, high and low are existing entities; high/low are children of group.
local lod = group:AddComponent("LOD")
local detailed = B.LODLevel.new()
detailed.ScreenHeight = 0.5
detailed.Roots = {high:GetUUID()}
local simple = B.LODLevel.new()
simple.ScreenHeight = 0.08
simple.Roots = {low:GetUUID()}
lod.Size = 1
lod.Levels = {detailed, simple}
group:SetComponent("LOD", lod)

lod = group:GetComponent("LOD")
lod:ForceLevel(0)
group:SetComponent("LOD", lod)
-- Restore automatic selection:
lod:ForceLevel(-1)
group:SetComponent("LOD", lod)
-- Pure selection helper; result is zero-based, unlike Lua array indices:
local level = lod:SelectLevel(0.2)

Invalid values passed to SetComponent become a script error. IsValid, SelectLevel, GetScreenHeight and ForceLevel have the same semantics as C++. Read Levels and Roots as Lua arrays; assign changed arrays back to the value before committing it to the entity.

Group settings

SettingMeaning
CenterLocal center of the group bounds.
SizeLocal diameter of a sphere enclosing the complete model. World scale is applied automatically using the largest axis.
BiasMultiplies apparent screen height. Values above 1 retain more detail; values below 1 select simpler models sooner.
HysteresisBoundary margin from 0 to 0.5. It prevents rapid switching when the camera sits near a threshold.
CullHide all level geometry below the final threshold. Turn off to keep the last level at any distance.
Forced Level−1 is Automatic, −2 is Culled, and 0 or higher forces a specific level. Disabling the LOD component displays level 0.
Levels1–8 levels ordered from highest to lowest detail. Each level has a ScreenHeight threshold and a list of child subtree roots.

How a level is chosen

ScreenHeight is a fraction of the viewport height: 0.5 means half its height. Thresholds must descend strictly and remain between 0 and 1. The first threshold met by the projected group size is selected. Perspective selection uses camera distance and vertical projection scale; orthographic selection uses orthographic size and does not change when the camera moves closer. Different cameras, split-screen views and render targets choose independently.

For a 0.5 threshold and Hysteresis 0.1, a camera coming from lower detail needs about 0.55 screen height to enter the higher level. Coming from higher detail, it stays there until below about 0.45. Culling uses the same margin. Forced levels bypass hysteresis.

What belongs to the group

Roots are entity UUID references, not assets or file paths. Assign a child subtree root for each representation, such as an imported model parent or a primitive child. Its mesh/primitive descendants participate automatically. Do not assign the group itself. A root cannot appear twice, and roots in different levels cannot contain each other. Nested LOD groups are supported: their visibility also depends on the outer group.

LOD changes rendered geometry and shadows. Entity enabled states, scripts, colliders, rigidbodies, cameras, lights and audio continue operating. This avoids changing gameplay as the viewer moves. Hierarchy selection can still inspect inactive levels; viewport picking and outlines exclude their hidden geometry. Logical scene/physics queries keep their existing behavior and are not a camera visibility query.

Resources and transitions

Level changes retain GPU resources and materials, so switching does not reload a model or compile a shader. They reduce submitted geometry rather than unloading all inactive assets from memory. Models need authored simpler representations: this component does not generate simplified meshes. Transitions are hard switches with hysteresis; cross-fading and automatic decimation are not provided. Invalid group assignments produce a rendering warning and leave geometry visible so the scene can be repaired.
