Lua deterministic physics and replay

Use Bazzalt.PhysicsReplay.ForScene(scene) inside a gameplay callback after physics initialization. Keep the handle on self if needed; it and PhysicsState participate in gameplay hot reload.

Record

local B = Bazzalt
local scene = self.Entity:GetScene()
self.Replay = B.PhysicsReplay.ForScene(scene)
local policy = B.PhysicsDeterminismSettings.new()
policy.Enabled = true
self.Replay:SetDeterminismSettings(policy)
local limits = B.PhysicsReplaySettings.new()
limits.MaxFrames = 600
self.Replay:BeginRecording(limits)
-- The engine records completed fixed steps automatically.
-- Later: self.Replay:EndRecording()

Playback and checkpoints

local physics = scene:GetPhysics()
local settings = physics:GetSettings()
settings.AutoSimulation = false
assert(physics:SetSettings(settings))
local checkpoint = self.Replay:CaptureState()
physics:ApplyImpulse(ball, B.Vec3.new(1, 2, 0))
physics:Simulate(1 / 60)
self.Replay:RestoreState(checkpoint)

self.Replay:BeginPlayback(false)
-- Call once for each desired playback tick, not in a blocking render loop:
local advanced = self.Replay:AdvancePlayback()
local status = self.Replay:GetStatus()
if status.FrameCount > 10 then self.Replay:SeekFrame(10) end
self.Replay:StopPlayback()

Handle exceptions with pcall where recovery is appropriate. GetFrame returns a trusted opaque PhysicsState. Its GetHash is for same-build equality diagnostics, not security. See the full Lua API reference.

Scope and compatibility

A checkpoint belongs to one running physics world session. Stopping/restarting simulation invalidates it for restoration. Adding/removing/recreating physics bodies, changing collider geometry, relevant hierarchy or solver configuration rejects old checkpoints. Unrelated non-physics objects may be created or moved normally. Checkpoints include the solver, soft vertices and pinning, joints, vehicle state/inputs, queued forces, contacts, physics-related transforms and their ancestors. Restore does not replay collision callbacks.

This is physics rollback and state playback, not an input-driven whole-game replay. Script variables, application time, random generators, audio and non-physics gameplay are not rewound. Pause or gate gameplay that modifies the recorded physics world while playing back. Serialized replay files, topology-changing recordings and cross-session checkpoints are not supported in this version. States remain trusted opaque handles; the API never parses arbitrary native solver bytes.

Determinism requirements

Enable PhysicsDeterminismSettings.Enabled and use its exact FixedDeltaTime for every simulation step. SingleThreaded defaults to true. Repeat the same commands in the same order, with the same assets and settings. Match the application fixed step to the physics fixed step. The Jolt source build enables BAZZALT_CROSS_PLATFORM_DETERMINISTIC_PHYSICS by default; imported SDKs may differ. IsSolverCrossPlatformDeterministic reports the loaded solver flag. It does not certify script math, procedural geometry, vehicle wrapper calculations or whole-game cross-platform lockstep. Test your shipping builds and gameplay across target machines. Jolt’s Architecture documentation, “Deterministic Simulation”, describes the upstream solver requirements.
