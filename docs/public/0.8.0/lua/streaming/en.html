Streaming from Lua

The global Bazzalt.SceneManager exposes asynchronous loading without exposing engine initialization or authoring saves. A UUID such as sceneAsset below is an imported .bscene asset reference provided by your game.

Replace a scene

self.SceneRequest = Bazzalt.SceneManager.LoadSceneAsync(sceneAsset, false)
-- In a later update:
if self.SceneRequest:GetStatus() == Bazzalt.AsyncLoadStatus.Ready then
    self.SceneRequest:SetActivationAllowed(true)
end

Poll GetStatus, GetProgress and GetError. IsDone is true for Complete, Failed, Cancelled and Unloaded; it does not mean success. Cancel requests cancellation and rollback before completion. Ready means file data is prepared; Activate may span several frames. Keep a handle as a member to inspect it later. Dropping it does not cancel the operation.

World cells

local cell = Bazzalt.StreamingCell.new()
cell.SceneAsset = cellAsset
cell.Offset.Position = Bazzalt.Vec3.new(500, 0, 0)
cell.LoadDistance = 150
cell.UnloadDistance = 220
Bazzalt.SceneManager.RegisterStreamingCell(cell)
-- Update from your player/controller:
Bazzalt.SceneManager.SetStreamingPosition(player:GetWorldTransform().Position)

LoadWorldCellAsync(sceneAsset, optionalTransform) manually loads a cell. UnloadWorldCell(sceneAsset) queues removal. RegisterStreamingCell(cell), UnregisterStreamingCell(sceneAsset) and SetStreamingPosition(position) manage distance-driven loading. GetRootUUID identifies a loaded cell's parent in the active scene; GetSceneUUID identifies its source scene. Each cell preserves entity UUIDs and must not conflict with the active scene. Repeated loads of a resident asset do not duplicate entities. Cell scripts start after assembly and stop before removal; referenced scripts must already be imported/compiled.

Resources and settings

Bazzalt.AssetManager.LoadAsync(assetUUID) returns ResourceLoadHandle. GetData returns nil until successful completion, then a binary Lua string containing cache bytes; it copies data into Lua, so avoid copying large textures/models into gameplay tables. Native rendering consumes its own prepared resources. Bazzalt.SceneManager.GetStreamingSettings returns a settings value: change fields and pass it to SetStreamingSettings. Defaults are 2 ms, 128 entity operations per tick, 64 pending requests, 4 concurrent preparations and 256 MiB for raw/staged source reservations. Settings do not make Lua, ECS, Qt or GPU APIs thread-safe.

Instancing

Bazzalt.Graphics.SetInstancingEnabled(enabled) and IsInstancingEnabled control automatic GPU batching. Compatible geometry/materials are required; different resources or render state split batches. These methods belong to Graphics, not to a Filament backend API. See the C++ streaming guide for activation, failure, budget and renderer-path details.

Cells, grids and multiple sources

StreamingCell.HalfExtents describes a world-axis-aligned box centered at Offset.Position. Distances are measured to its nearest edge, not its center. Zero extents preserve point-cell behavior. Priority orders new requests before distance (larger values first), with UUIDs breaking ties. AlwaysLoaded ignores distance. Existing residents are retained through the hysteresis band: load at LoadDistance, unload beyond UnloadDistance.

SetStreamingSource(sourceUUID, position, distanceScale) adds or updates a named source. RemoveStreamingSource removes it. Every enabled source contributes; a cell stays resident while any source retains it. A scale of 2 doubles that source's distance thresholds. SetStreamingPosition remains a convenience source; ClearStreamingPosition removes only that source. Sources are explicit: the engine does not invent a camera or assume the world origin is a player.

StreamingGrid has Origin, CellSize, LoadDistance, UnloadDistance and Cells. Each StreamingGridCell supplies SceneAsset and integer X/Y/Z. Cell centers are Origin + coordinates * CellSize; bounds are half CellSize. RegisterStreamingGrid validates the whole batch before registering anything. Use a distinct scene asset with distinct entity UUIDs for every cell. A cell is a unique world region, not an instanced copy of a scene.

Authoring in scenes

Add WorldCell to a persistent-scene entity and choose SceneAsset. Its world transform places the chunk; HalfExtents is local to this definition and transforms to conservative world bounds. Set load/unload distances, priority and optional AlwaysLoaded. Attach StreamingSource to a player or camera and enable it. The engine discovers these components during Play and standalone gameplay. Editing a scene does not automatically load cells. Components serialize, support enable/disable, appear in Add Component and expose the same C++/Lua controls. Scene references enter asset dependency tracking and packaging.

Duplicate enabled authored definitions for one asset are rejected together. Manual registrations take precedence and report conflicting authored definitions. Definitions inside a streamed cell become active only after their owner finishes activation; removing an owner retires its nested definitions. Disable/remove a definition or unregister a manual cell to keep it unloaded while a source is still nearby. A direct UnloadWorldCell request alone does not disable automatic residency.

Budgets and unload lifecycle

UnloadWorldCell is deferred and changes the handle to Unloading. Poll until Unloaded; IsDone is false while unloading. Behavior runtimes stop once before entity teardown. Entity removal is spread across EntitiesPerTick and MainThreadBudgetMilliseconds, preserving unrelated children that were parented beneath a cell. Activation rollback follows the same bounded removal path. Teardown on engine/scene replacement remains synchronous. Component factories and lifecycle callbacks are indivisible, so the time budget is soft rather than a hard real-time guarantee.

MaxResidentCells (default 128, range 1–4096) caps additive cell slots, including requests and cells still unloading. MaxConcurrentLoads also counts cancelled workers until they exit. Registered definitions are limited to 4096; manual named sources to 256. StreamingSettings.RetryDelaySeconds defaults to 2 (0.1–3600). Automatic failures retain diagnostics and retry after that delay; RetryStreamingCell permits an immediate explicit retry. Repeated requests during unloading return the draining operation instead of creating conflicting copies.

local B = Bazzalt
local source = B.StreamingSource.new()
source.DistanceScale = 1.5
self.Entity:AddOrReplaceComponent("StreamingSource", source)
-- The engine follows this entity while the component is enabled.
local cells = B.SceneManager.GetStreamingCells()
for _, cell in ipairs(cells) do
    if cell.Status == B.AsyncLoadStatus.Failed then
        B.Console.Warning(cell.Error, "World Streaming")
    end
end

Monitoring and persistence

GetStreamingCells returns copied snapshots with SceneAsset, SceneUUID, RootUUID, Status, Progress, Distance, Automatic and Error. GetStreamingStatistics reports registered/resident/pending/unloading counts, source count and reserved CPU source bytes. GetStreamingEvents returns up to 4096 observed status changes for the most recent pump; reading does not consume them. Poll once per frame and retain any history you need. Events are diagnostics, not a pre-unload save callback. Loaded data becomes usable after Complete, not merely Ready.

Cells contribute entities to the active scene; they do not replace its environment, gravity or active-scene identity. Changes to streamed entities are transient when unloaded. Use the save-game API for persistent gameplay state. Streaming does not automatically serialize modified cells, relocate physics to worker threads, or promise GPU residency when parsing completes.
