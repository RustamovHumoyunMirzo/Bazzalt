GUI stylesheets in Lua

Stylesheets are imported .css assets. Assign their UUID to GuiElement.Stylesheet for a whole GUI Frame, or GuiElement.Stylesheet for a subtree. A nested Frame starts a new scope. Existing explicit component fields remain authored fallbacks.

Assign metadata and styles

This example runs in a behavior callback. stylesheetUUID is an existing imported asset UUID selected by your game/editor code; it is not a path or source-code string.

local B = Bazzalt
local element = self.Entity:HasComponent("GuiElement")
    and self.Entity:GetComponent("GuiElement")
    or self.Entity:AddComponent("GuiElement")
element.Stylesheet = stylesheetUUID
element.ID = "play"
element.Classes = "primary wide"
element.Tags = "action navigation"
element.Attributes = '[state="active"]'
self.Entity:SetComponent("GuiElement", element)

-- After the next automatic layout, inspect computed values:
local text = B.GUI.ResolveText(self.Entity)
local bounds = B.GUI.GetBounds(self.Entity)
local diagnostics = B.GUI.GetStyleDiagnostics(self.Entity)

Rules and scope

Classes/tags are space-separated tokens, without leading dots. Attributes use presence/exact forms such as [disabled] or [state="active"]. Node types are Frame, Button, TextInput, Image, Text, Rectangle and Container. An empty ID uses the entity name. Tags are queried with [tags~="action"]. Actual input supplies hover, active, focus and disabled states.

See the complete stylesheet language/application contract for supported properties, asset references, inheritance and diagnostics. C++ and Lua receive the same computed results; there is no Lua-only CSS renderer.

Typed stylesheet inputs

Declare @require(name, default, type, ...); at a stylesheet root, then use require(name) in its rules. Assign that stylesheet to GuiElement to generate inspector fields, including typed project asset pickers. Scene saves retain per-element overrides. See the stylesheet input syntax and types for all declarations, bounds, vectors and enum options.

local B = Bazzalt
local fields = B.GUI.GetStylesheetProperties(stylesheetUUID)
assert(B.GUI.SetStyleProperty(entity, "accent", "#ff8844"))
assert(B.GUI.SetStyleProperty(entity, "caption", '\"Start\"'))
local value = B.GUI.GetStyleProperty(entity, "caption")
B.GUI.ResetStyleProperty(entity, "accent")

Values are CSS literals. String literals include their quotes; textures/fonts use asset("uuid") or none. Invalid values return false. These service methods update the actual entity directly; no component copy/write-back is needed. Field descriptors contain Name, Type, DefaultValue, Label, Tooltip, HasMinimum, HasMaximum, Minimum, Maximum and Options.

Editing CSS during play

Each GuiElement can have a private runtime stylesheet and inline declarations. These are instance data: editing one entity does not modify the shared .css asset or another entity. Runtime edits are temporary and are not written to scene files. They affect the next GUI layout/render in the same ordinary frame pipeline, including Spatial and Camera-Bound Frames.

GetStylesheetCSS (or GuiCSS.GetBaseText) reads the directly assigned asset source. GetCSS returns the additional runtime stylesheet text; SetCSS replaces that layer and AppendCSS adds rules after it. The assigned asset remains the base layer. An empty replacement removes the additional layer. Inline values override normal stylesheet rules; author !important rules still win over normal inline values. GetCSSProperty reads an inline declaration, not a computed pixel value. Use GetBounds and ResolveStyle for effective layout and appearance.

OperationPurpose
GetCSSStyle(entity)Returns a lightweight GuiCSS handle for object-style editing.
GetCSS / SetCSS / AppendCSSRead, replace or append the private runtime stylesheet.
GetCSSProperty / SetCSSProperty / RemoveCSSPropertyRead, set or remove one inline declaration. Removing it restores the cascade.
SetCSSRule / RemoveCSSRuleReplace or remove matching top-level selector rules. Pass declarations without outer braces. Replace the enclosing stylesheet to edit rules inside a media/viewport block.
SetCSSKeyframes / RemoveCSSKeyframesReplace or remove a named top-level keyframe definition. Pass the frame blocks as text.

GuiCSS exposes Get, Set, Remove, GetText, GetBaseText, Replace, Append, SetRule, RemoveRule, SetKeyframes and RemoveKeyframes. Its owner must have an enabled GuiElement to render the styles. It does not own the entity. Invalid/stale owners and malformed edits return false; rejected edits leave the previous valid source intact. Set and rule-edit operations cannot inject additional rules through a property value.

Transitions and keyframes

Button {
  opacity: 1;
  width: 120px;
  transition: width 250ms ease-out, opacity 150ms linear;
}
Button:hover { width: 170px; }
@keyframes pulse {
  from { opacity: 0.4; }
  50% { opacity: 1; }
  to { opacity: 0.4; }
}
.busy { animation: pulse 1.2s ease-in-out infinite alternate; }

Transitions respond to changed cascade values, including inline runtime edits, hover and requirement overrides. A replacement transition starts at the last displayed value rather than snapping back. No entrance transition runs on the initial layout. Define the base value explicitly so removal has a target to transition back to.

Supported transition longhands are transition-property, transition-duration, transition-delay and transition-timing-function. Comma lists repeat when shorter than the property list; all selects interpolable changed properties and none disables transitions. Timings include s/ms, negative delay, linear, ease, ease-in, ease-out, ease-in-out, cubic-bezier(x1,y1,x2,y2), steps(count,start/end), step-start and step-end. Colors and matching numeric value structures interpolate; incompatible units, textures and discrete keywords change directly.

Animation supports animation-name, animation-duration, animation-delay, animation-timing-function, animation-iteration-count (fractional or infinite), animation-direction (normal, reverse, alternate, alternate-reverse), animation-fill-mode (none, forwards, backwards, both) and animation-play-state (running, paused), plus the shorthand above and comma-separated animations. Declare keyframes outside conditional viewport/media blocks. Keyframes accept from, to, percentages and grouped offsets. Missing endpoints use the authored base value when available. Later animations override earlier animations on the same property, !important values override animations, and active transitions override both. Changing the definition restarts its timeline; pause/resume retains elapsed time. Time follows the engine game clock, including time scale and pause.

The GUI implements its own CSS dialect, not a browser DOM. Animate supported GUI layout/paint properties; parsing a web-only property does not add renderer support. Interpolation requires compatible units/structure, so use consistent units across endpoints. CSS transforms, additive animation composition and per-keyframe timing overrides are not provided. Motion shorthands and longhands follow normal declaration order and cascade priority. Motion remains bounded: 64 simultaneous animations per element, 1024 keyframe offsets per definition, 256 KiB runtime stylesheet text, 128 inline properties and 64 KiB total inline data. Existing parser, hierarchy, filter and renderer limits continue to apply.

local css = Bazzalt.GUI.GetCSSStyle(button)
css:Set("width", "170px")
css:SetKeyframes("pulse", "from{opacity:0.4}to{opacity:1}")
css:Set("animation", "pulse 1s linear infinite alternate")
css:Set("animation-play-state", "paused")
