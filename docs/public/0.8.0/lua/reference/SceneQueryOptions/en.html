SceneQueryOptions

Filters and distance limit shared by picking, ray and overlap queries. Queries operate on scene geometry, not a simulated physics world.

Underlying public header: Bazzalt/SceneQuery.h.

Read signatures together with the behavior notes below. The reference introduction explains arguments, return values, value copies, and errors.

In call notation, argument = default describes an optional argument and its default; Lua does not use named arguments here. Supply the value positionally or omit it. The C++ declaration below is comparison data, not Lua syntax.

Construction

Bazzalt.SceneQueryOptions.new()

Each line is an accepted construction form. The argument names stand for values you supply; an empty call uses default values. Plain data types construct with their declared default fields.

Example

Gameplay snippets run inside a behavior callback or helper. Variables such as scene, camera, savedText and assetUUID are existing values, not automatically declared global variables.

local options = Bazzalt.SceneQueryOptions.new()
options.MaxDistance = 100

Filter

value.Filter

Lua members and signatures

Use Bazzalt.SceneQueryOptions. Each member below is actually registered in Lua. The adapter declarations are C++ binding notation, not Lua example code. sol::property exposes a field, sol::overload lists alternatives, sol::optional accepts an omitted/nil argument, and std::make_tuple returns multiple Lua values. sol::as_table returns a Lua table. Instance methods use value:Method(...); service/static calls use Bazzalt.SceneQueryOptions.Method(...) unless a colon overload is explicitly registered. An engine exception becomes a Lua script error. See the examples and behavior notes above for usage.
