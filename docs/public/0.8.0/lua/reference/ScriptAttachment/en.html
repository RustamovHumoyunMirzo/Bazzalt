ScriptAttachment

One authored behavior attachment. Source identifies its asset; the runtime privately loads executable code or Lua bytecode.

Underlying public header: Bazzalt/Components/ScriptComponent.h.

Read signatures together with the behavior notes below. The reference introduction explains arguments, return values, value copies, and errors.

In call notation, argument = default describes an optional argument and its default; Lua does not use named arguments here. Supply the value positionally or omit it. The C++ declaration below is comparison data, not Lua syntax.

Construction

Bazzalt.ScriptAttachment.new()

Each line is an accepted construction form. The argument names stand for values you supply; an empty call uses default values. Plain data types construct with their declared default fields.

Component values returned by Entity are copies. After changing fields or methods, call entity:SetComponent(typeName, value). Derived components inherit Component.Enabled, IsEnabled and SetEnabled; core Identity, Hierarchy, Name and Transform have entity-level restrictions.

Lua members and signatures

Use Bazzalt.ScriptAttachment. Each member below is actually registered in Lua. The adapter declarations are C++ binding notation, not Lua example code. sol::property exposes a field, sol::overload lists alternatives, sol::optional accepts an omitted/nil argument, and std::make_tuple returns multiple Lua values. sol::as_table returns a Lua table. Instance methods use value:Method(...); service/static calls use Bazzalt.ScriptAttachment.Method(...) unless a colon overload is explicitly registered. An engine exception becomes a Lua script error. See the examples and behavior notes above for usage.
