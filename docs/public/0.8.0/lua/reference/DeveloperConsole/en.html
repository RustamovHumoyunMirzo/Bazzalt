DeveloperConsole

Runtime command interpreter, history/completion, bounded output and optional native-rendered overlay. Disabled by default in standalone games; editor integration enables it. Commands retain module/VM owners and disconnect on stop/reload. Execute never invokes an OS shell. See the developer-console guide for syntax, threading and limits.

Lua members and signatures

Use Bazzalt.DeveloperConsole. Each member below is actually registered in Lua. The adapter declarations are C++ binding notation, not Lua example code. sol::property exposes a field, sol::overload lists alternatives, sol::optional accepts an omitted/nil argument, and std::make_tuple returns multiple Lua values. sol::as_table returns a Lua table. Instance methods use value:Method(...); service/static calls use Bazzalt.DeveloperConsole.Method(...) unless a colon overload is explicitly registered. An engine exception becomes a Lua script error. See the examples and behavior notes above for usage.
