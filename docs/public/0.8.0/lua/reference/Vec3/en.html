Vec3

Three floating-point coordinates. Used for positions, directions, sizes and RGB colors. Directions are not automatically unit length.

Underlying public header: Bazzalt/Math.h.

Read signatures together with the behavior notes below. The reference introduction explains arguments, return values, value copies, and errors.

In call notation, argument = default describes an optional argument and its default; Lua does not use named arguments here. Supply the value positionally or omit it. The C++ declaration below is comparison data, not Lua syntax.

Construction

Bazzalt.Vec3.new()
Bazzalt.Vec3.new(value)
Bazzalt.Vec3.new(x, y, z)

Each line is an accepted construction form. The argument names stand for values you supply; an empty call uses default values. Plain data types construct with their declared default fields.

Example

Gameplay snippets run inside a behavior callback or helper. Variables such as scene, camera, savedText and assetUUID are existing values, not automatically declared global variables.

local direction = Bazzalt.Vec3.new(1, 0, 1):Normalized()

Lerp

Bazzalt.Vec3.Lerp(from, to, amount)

Linear interpolation from the first value to the second by amount. Amount is not clamped: 0 selects from, 1 selects to, other values can extrapolate.

Returns: Vec3.

ArgumentMeaning
Vec3 fromInterpolation starting value.
Vec3 toInterpolation target value.
float amountInterpolation factor; 0 starts and 1 ends, not automatically clamped.

Invalid arguments and C++ exceptions are reported as Lua errors at the protected script boundary. Check the specific absence/false result rules above; not every missing value is an error.

Lua members and signatures

Use Bazzalt.Vec3. Each member below is actually registered in Lua. The adapter declarations are C++ binding notation, not Lua example code. sol::property exposes a field, sol::overload lists alternatives, sol::optional accepts an omitted/nil argument, and std::make_tuple returns multiple Lua values. sol::as_table returns a Lua table. Instance methods use value:Method(...); service/static calls use Bazzalt.Vec3.Method(...) unless a colon overload is explicitly registered. An engine exception becomes a Lua script error. See the examples and behavior notes above for usage.
