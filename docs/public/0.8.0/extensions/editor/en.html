Editor plugin API

Use Qt Designer .ui files for widget layout and Lua controller tables for behavior. The host loads built-in widgets through a restricted loader. It exposes named widget commands rather than raw PySide objects, editor internals or engine-loop callbacks. C++ logic can be exported as a module and called from a thin Lua controller.

Panel registration

AssetRegistry:
  - Id: panel
    Path: panels/tool.ui
  - Id: controller
    Path: scripts/controller.lua
EditorRegistry:
  panel:
    Title: My Tool
    Script: controller
Scripts:
  controller:
    Id: controller
    Scope: Editor
    Entry: true
Extends:
  Menubar:
    - Menu: Tools
      Title: Open My Tool
      Script: controller
      Function: Open

Use unique objectName values in a panel. Standard labels, buttons, text/number inputs, lists, trees, tables, group boxes, scroll areas, tabs, stacks, sliders and splitters are supported. The shared editor theme supplies styling. Custom widget plugins, embedded scripts, XML entities, external .qrc resources, pixmap imports and per-panel stylesheets are rejected. Register the panel icon as an AssetRegistry file instead.

Controller callbacks

A controller returns a table. OnEnable is called for the entry controller during activation; OnDisable is called for loaded controllers on editor close. OnClicked receives a button objectName. OnChanged receives the widget objectName for supported text, combo and number inputs; use Editor:GetValue(name) to read the current value. Menu actions call their configured function. Controllers are isolated Lua VMs with memory and instruction limits. A failing controller is disabled and logs to Console. Stop Play before running editor extension commands.

local Tool = {}
function Tool:OnEnable() Editor:Log("Tool loaded") end
function Tool:Open() Editor:OpenPanel("panel") end
function Tool:OnClicked(name)
    if name == "runButton" then Editor:SetText("resultLabel", "Done") end
end
return Tool

Editor commands

CallBehavior
Editor:Log(message)Adds a Console item attributed to this extension.
Editor:OpenPanel(assetId)Opens a panel belonging to this extension.
Editor:SetText(objectName, text)Sets text on a supported text widget belonging to this extension.
Editor:GetText(objectName)Returns the widget text.
Editor:SetEnabled(objectName, boolean)Changes whether the widget accepts input.
Editor:SetVisible(objectName, boolean)Shows or hides the widget.
Editor:GetValue(objectName)Returns a boolean for checkable buttons, a number for numeric inputs, or text for text/combo inputs.
Editor:SetValue(objectName, value)Sets a supported scalar input without triggering OnChanged recursively. Numeric controls enforce their configured bounds.
Editor:GetProject()Returns the active project descriptor path, or an empty string.
Editor:BeginUndo(label), Editor:EndUndo()Groups scene authoring changes into one undo operation and marks the scene dirty. An open group commits when the callback returns; a failing callback rolls its open group back.
Editor:RefreshScene()Refreshes hierarchy, inspector and gizmos after an ungrouped scene edit and marks the scene dirty. Prefer an undo group for user-visible edits.
Editor:RefreshAssets()Rescans generated project assets and refreshes the browser.
Editor:SelectEntity(uuidText)Selects a scene entity by UUID.
Editor:BeginUndo("Create object")
local scene = Bazzalt.SceneManager.GetActiveScene()
local entity = scene:CreateEntity("Tool object")
Editor:EndUndo()

Widget lookup stays within the extension's panels. Use panelId/objectName when names occur in multiple panels; ambiguous unqualified names are rejected. Editor commands are not gameplay APIs and are never included in standalone runtime bindings. Use project assets for a tool's generated content so that its results are cooked normally without shipping the editor plugin.
