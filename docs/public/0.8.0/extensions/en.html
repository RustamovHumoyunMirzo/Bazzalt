Creating extensions

An extension is an optional package that adds editor tools, a gameplay SDK, or both. A gameplay SDK is reusable code and public headers that projects can call. An editor plugin is a tool that runs only inside the editor. Distribute extensions as .bpack files.

Start with a manifest

Create a folder containing an extension.yaml manifest and its registered files. Paths are relative to the manifest. Choose a stable lowercase extension ID, for example studio.terrain. The ID identifies a package independently of its display name. Public module names identify callable SDKs; they must not collide with modules in other enabled packages.

The package builder reads files listed in AssetRegistry and native include/library/binary directories. It does not recursively include arbitrary neighboring project files. Absolute paths, path traversal, symlinks, junctions and unsafe ZIP members are rejected. This keeps a package self-contained and portable.

A minimal Lua SDK

FormatVersion: 1
General:
  Id: studio.math
  Name: Studio Math
  ShortDescription: Shared gameplay calculations.
  Version: 1.0.0
Compatibility:
  MinEngineVersion: 0.7.0
AssetRegistry:
  - Id: math
    Path: scripts/math.lua
Scripts:
  math:
    Id: math
    Public: true
    ModuleName: StudioMath
    Scope: Runtime

local M = {}
function M.Double(value) return value * 2 end
return M

Save the Lua file as scripts/math.lua. Choose Build > Build Package, select the manifest and a supplied runtime SDK, then build a .bpack. Lua is compiled to bytecode during packaging. A user imports the package through Window > Extensions and enables it after satisfying its dependencies. Activation changes apply after an editor restart.

A complete portable SDK and editor-panel example is included in the repository at examples/extensions/math.
